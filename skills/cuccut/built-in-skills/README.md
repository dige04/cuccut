# Built-in skills

The built-in agent skills that ship with CucCut, also called crafts: how to judge a job and which steps to follow. The Runtime loads them from this directory (the "Agent skill" part of [architecture design §3.8](../../../docs/architecture/architecture-design.md)); one skill per directory, and the directory name is the skill's `id`. Built-in skills are on by default; the user can turn them off but cannot remove them.

This directory sits under the manual [`skills/cuccut/`](../../README.md). The manual covers the general "how to use CucCut" (getting started, the capability catalog, hard rules, delivery), and the renderer hands it per surface to the in-session agent and to external agents: the routing that lists which skill to read before starting each type of task is in §1 of [`SKILL.md`](../SKILL.md), and the one-line catalog of all crafts is "Built-in skills" at the end of §3 (CLI surface only; the in-session agent sees the skill index at the start of the session). External agents read the copies generated by the sync script (`../references/craft/<id>.md`); the single source is still here. Ids starting with `cuccut-` are reserved for manual pages (`cuccut-catalog-*`, `cuccut-workflows`, `cuccut-conventions`) and are not used here.

## Adding or changing a skill

1. Create `skills/cuccut/built-in-skills/<id>/`; the `id` is kebab-case and must not clash with an existing directory.
2. Write `SKILL.md`: front matter with `name` (the short name shown directly in the UI), `description` (what it does, when to use it, when not to; the index at the start of a session takes only the first 300 characters) and `version`; the body is the method, kept concise. Put long detailed rules in `references/`, which the agent fetches on demand with `skills_read`.
3. Skills do not reference each other's files; each skill is self-contained. Shared model material and reference tables live in the manual's `references/catalog/`, read with `skills_read` as `cuccut-catalog-<page>`; the sync script rewrites these into catalog page links for external agents, without copying the data. The body references only cuccut tools and document types the agent actually has, and does not repeat general rules the manual (the entry guidance) already states.
4. The method must work for videos and target languages in any language; do not assume Chinese or English.
5. No symbolic links, and no files starting with a dot (they do not count as skill content); limits are in `SKILL_LIMITS` in `@cuccut/protocol`.
6. Run `npm test -- packages/runtime-core/src/skills`: `builtin-skills.test.ts` loads every skill here and checks the list, the limits, the index above and the manual's "Built-in skills" table. When adding or renaming, update the list in the test, the index above, the routing in §1 of the manual's SKILL.md and the "Built-in skills" table in §3 (then run `npm run build:agent-skill` to regenerate the craft copies), and the "Sources" entry in [product design §6.9](../../../docs/product/product-design.md#69-skillag-07).
