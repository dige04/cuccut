# 6. Export

> From [CucCut edit-domain protocol design (Cut / Clip / element / watermark / project export)](../ccut-edit-domain-design.md)

## 6.1 Export target registry (implemented)

The registry trait promised in [cli-design §9.1](../ccut-cli-design.md) has landed in `core/crates/ccut-kernel/src/services/export_registry.rs`:

```rust
trait ExportTargetImpl {
    fn token(&self) -> &'static str;              // "srt" … "capcut" "premiere" …
    fn arg_schema(&self) -> Value;                // target-specific arguments, fed into `ccut spec export`
    fn run(&self, ctx: &ExportCtx) -> ExportReport;  // receives the timeline after OUTPUT projection
}
```

`ExportReport` unifies `{format, path(s), laneCount, segmentCount, blockers[], warnings[], omitted[], lossy}`. Editable projects also carry `deliveries[]` / `summary`, and BCF projects carry `film{path, rendered, stale}` (specVersion 1.228.0). `lossy` is a **computed value**: it is true only when this export actually loses something (`summary.dropped > 0` or an `attr-*` downgrade warning exists). It does not echo the `--allow-lossy` flag. Hidden tracks, hidden elements and elements outside the output window are `skipped` and do not count as loss. `spec` is generated from the registry; tests cross-check the clap value set against target parameters, eliminating enum/spec drift. Target tokens: `capcut · premiere · resolve · final-cut-pro · shotcut · kdenlive` (consistent with the stable tokens of the older version).

## 6.2 OUTPUT IR (the Rust counterpart of the older EditableTimeline)

`ccut-editable` crate. The single entry point is `build(timeline, transcripts, studio_style, options) -> (EditableTimeline, PreflightReport)`:

```rust
struct EditableTimeline {
    canvas: Canvas,                  // outputSize(natural, --ratio, --size)
    fps: f64, duration: f64,         // timeline time (= output time)
    main_transform: Transform, main_muted: bool,
    subtitle_layout: SubtitleLayout, // x/y/width/order/gap/backgroundMode ← studio style
    lanes: Vec<Lane>,                // kind: video|audio|text; array order is the target track order
    assets: Vec<Asset>,
}
```

Build rules (aligned with the older builder semantics, restated for the two-layer model):

1. **Main-picture lane**: each clip is expanded by its source cuts into a sequence of kept sub-segments (`srcStart` advances segment by segment, `rate` converted), entering the `main-track` lane. Adjacent seams ≤1µs are forcibly aligned.
2. **Elements**: an element's window is timeline time and goes directly into a lane. When an element referencing media has its source clock cross a cut segment of the referenced source, it **splits the segment and advances `srcStart`** (video/audio advance; text does not apply). Items dropped by `hidden` tracks / elements or `clampEvent` go into `skippedElementIds`.
3. **Lane fan-out**: elements on the same track that overlap in time are split onto adjacent lanes (`<trackId>+<n>`, the latter on top).
4. **Subtitles**: the retiming result, identical to the sidecar (§4.2), generates a text lane. Bilingual splits into `tr-subs` + `tr-subs-trans`, sharing geometry into `subtitle_layout`. `backgroundMode:"shared"` reports a `bilingual-shared-background` warning.
5. **Animation**: under the native mapping it is dropped as a whole, with an `attr-animation` warning per element (no NLE has an equivalent vocabulary; final-MP4 burn-in is not subject to this). With `--bake lossy`, it is baked together with other lossy attributes into an alpha video; see v2 design draft §3.
6. **Bake outputs**: each `BakedAsset` baked by the host per `plan_bakes` is registered as the asset `baked-<elementId>` (no `sourceId`, resolved by `path`, `hasAlpha` / `sequence` copied as-is). The clip stays on its original track and time range, with an identity transform filling the canvas. The template layer is the `template` lane, below all element lanes and above the main picture.

The preflight code table is frozen as part of the protocol (source of truth: `ccut_editable::preflight_code`; consumers must not hard-code their own copies of the strings):

- **blocker**: `missing-media` (never downgradable) · `empty-output` · `lossy-drop` (`summary.dropped > 0` and `--allow-lossy` not given; judged by the host) · `film-missing` (a BCF animation project has no rendered film and `--render-film` was not given; judged by the host);
- **warning**: `attr-mask/attr-effects/attr-animation/attr-tile/attr-corner-radius/attr-text-style/attr-transform/attr-transition/attr-audio-fade/canvas-background/bilingual-shared-background/caption-sequence/reference-media/media-copied/capcut-restart-required/untested-editor-version`; bake-related `element-baked/template-baked/bake-unavailable/bake-failed/film-rendered/film-stale`; `unsupported-element` (dropped by policy);
- **Request reason codes** (appear only in `BakeRequest.reason` and `deliveries[].reason`, not as standalone issues): `no-native-form` (the target has no native mapping) · `lossy-attr` (baked under `--bake lossy` to preserve lossy attributes).

`caption-sequence`: when the source track carries daoyazi (倒鸭子) cross-sentence dynamic typesetting, the subtitles still enter `tr-subs` as ordinary lines; the typesetting and camera moves do not enter the NLE. See [`ccut-daoyazi-caption-design.md`](../../subtitle/ccut-daoyazi-caption-design.md) §12. `attr-transition` / `attr-audio-fade` are the video transitions and audio fade-in/fade-out that were previously dropped silently; they are now reported per element. `PreflightReport` also carries `deliveries[]` (each element and template-layer item that enters the output window resolves to one of `native | baked | dropped`, with `reason` / `asset`) and `summary{native, baked, dropped, skipped}`.

**Reachability of codes** (rewritten on 2026-09-24 with editable project export v2 A1, replacing the v0.5 clarification about “reserved codes”): the element set has long been extended to 12 kinds, so `unsupported-element` is now reachable. It means “dropped per the `--bake` policy” (elements with no native mapping under `--bake none`, Lottie-source stickers, the template layer), as well as the defensive path for a missing source on the host. `attr-blend` is still unreachable (the model has no blend field) and stays in the table. `--allow-lossy` is no longer a reserved slot: when `summary.dropped > 0`, without this flag the export fails with `lossy-drop`; with it, the file is written as usual. Warnings and baking never block. See v2 design draft §6 for the semantics.

For the mapping decision table (native / bake / drop), the bake interface and the report format, see [editable project export v2](../../editor/ccut-editable-export-v2-design.md).

## 6.3 Porting notes for the CapCut / 剪映 writer

`CapCutDraftWriter` (42.7KB) is ported behaviour-for-behaviour into `ccut-editable`. Every empirically calibrated constant is **kept as is** (this batch is hard-won output from real-device reverse engineering):

- Draft files: `draft_info.json` + a byte-identical `template-2.tmp` written twice, `draft_meta_info.json`, `draft_cover.jpg`. Portable mode additionally adds `cuccut-manifest.json` (sha256 manifest);
- The skeleton comes from a sanitized empty template collected via clean-room methods (bundle resources ship with the CLI). The writer changes only its own fields;
- Version-prefix allowlist `8.7.* / 9.0.*`. A version mismatch does not block (it is recorded diagnostically);
- Units and conversions: integer microseconds; `transformX = (pct-50)/50`, `transformY = (50-pct)/50`; `fontSizeDivisor = 50/9`; `lineWidthScale = 0.82/0.80`; `backgroundInsetFactor = 1.5`; `shadowFeatherDivisor = 6`;
- Known pitfalls, locked in as tests: for `background_*` to take effect, `check_flag` must go from 47 to 63 (bit 16); overlay/watermark has no automatic line wrapping, so it needs pre-folded, materialized `\n`; for the MP4 audio tail, only `source_timerange` is trimmed, never `target_timerange`; `render_index = laneIndex*10000 + segmentIndex`;
- Media mode `reference | auto | copy` (auto decides based on CapCut sandbox readability). Install mode: staging validation (draft lint) → atomic publish, with `capcut-restart-required` when necessary.

## 6.4 The other five writers

`FCP7ProjectWriter` (Premiere / Resolve legacy `.xml`), `FCPXMLProjectWriter` (FCP / Resolve `.fcpxml`, `--fcpxml-version 1.9|1.10`, `--event-name`) and `MLTProjectWriter` (Shotcut `.mlt` / Kdenlive `.kdenlive`, `--profile source|canvas`, `--bin-layout flat`) are ported with behaviour parity. They consume only `EditableTimeline` and are unaware of the CapCut writer. IR neutrality is verified by “adding a new writer requires zero changes to the builder.”

## 6.5 Final MP4: skip cuts + full overlay burn-in

`export --to mp4` is upgraded to full compositing (decision 6). The pipeline:

```
timeline.json ──§4.3 compile──▶ equivalent BCF expansion (elements/animations → keyframes, word anchors already evaluated)
                                  │
timeline_media flattens the clip×kept main track with an ffmpeg filter graph
  (trim/atrim + setpts/atempo + concat, producing a temporary canonical MP4)
                                  │
OverlayRenderPlan::render_rgba(tlT)   ← generalization of SubtitleRenderPlan
  = subtitle layer (existing kernel, unchanged) + element layer (BCF sample-semantics sampling of place/animate → rasterization)
                                  │
native_video single-input per-frame compositing → platform encoder (AVAssetWriter / Media Foundation)
```

- **Zero drift**: the serve-side `__ccut/subtitle/overlay` endpoint is upgraded in step to full overlay (keeping the existing cache key and the `next_change` invalidation-boundary mechanism). Preview and export use the same `OverlayRenderPlan`;
- Audio: concatenation of the main-picture kept sub-segments + mixing of audio elements (static volume, with fades expanded by the preset). (Changed 2026-09-16: “main-picture kept sub-segments” only describes the older document format. In split / element-based documents, the original sound comes from each `kind: video` element's own audio, without distinguishing `srcId` or track, and muting is written per element as `muted`. See [product-design §12.0](../../product/product-design/12.md#120-三种文档形态与统一口径2026-09-16).)
- Normalizing cuts, speed changes, and multi-segment / multi-source main tracks explicitly depends on `ffmpeg` on PATH. The platform-native backend only receives the flattened single input and continues to handle zero-drift overlay and H.264/AAC encoding. The performance fallback follows the “pre-rendered overlay sequence per interval” in [§4.4](../../../archive/mac/ccut-mac-app-port-design.md). There is no option to degrade to approximate drawing.
