# 5. Shared semantics: `ccut-editor-core::cut_mode`

> From [CucCut talking-head cut design (prototype rounds 192–197 → kernel / serve / App v2 / Web)](../ccut-talking-head-cut-design.md)

New module `core/crates/ccut-editor-core/src/cut_mode/`: pure functions, no I/O, `#![forbid(unsafe_code)]`, scanned by the existing purity gate.

## 5.1 Mark projection `CutMarks` and in-segment tokens

```rust
pub enum CutMark { Cut { cut_id: String, category: String, removed_sec: f64 },
                   Suggested { item_id: String, category: String, removed_sec: f64 },
                   Pause { item_id: Option<String>, cut_id: Option<String>, gap_sec: f64, keep_sec: f64 } }
/// Markers only; the word list is not copied. A kernel cannot afford a second copy of hundreds of thousands of words in a seven-hour project (same discipline as the header comment in paras.rs).
pub struct CutMarks { pub words: BTreeMap<String /*word_id*/, CutMark>, pub pauses_after: BTreeMap<String, CutMark> }
pub fn marks(cuts: &CutSet, provenance: &CutProvenance, review: Option<&CleanupReview>, words: &[WordTiming]) -> CutMarks
/// Token split for a single segment, called lazily per visible line. Byte ranges come from the existing subtitle_list::word_ranges.
pub struct CutToken { pub word_id: String, pub byte_range: Range<usize>, pub utf16_range: Range<u32>, pub t0: f64, pub t1: f64, pub cue: usize }
pub fn para_tokens(text: &str, words: &[CueWord]) -> Vec<CutToken>
pub fn token_at(text: &str, words: &[CueWord], byte_offset: usize) -> Option<usize>   // = transcript_list::word_index_at_byte_offset
```

- **The token is `words[]`**: ASR Chinese words are already per character or short words, English is per word, and punctuation attaches to the preceding word. This is the same convention as the prototype `tokens(text)`, but time is no longer prorated by character ratio. Multi-character Chinese words are never split (`words[]` is the only source of truth; splitting them would leave no timing). `para_tokens` returns both byte ranges (used by GPUI `StyledText`) and UTF-16 ranges (used by the Web DOM); the conversion itself goes into the fixture.
- **Cut markers**: `CutSet::word_is_cut(t0, t1)` (the only entry point; `edits::cut_word_ids` already calls it) → `Cut`. `cut_id` is taken from `cut_end_containing`; `category` is taken from `ai/cuts.json`, and defaults to `manual` if absent.
- **Suggestion markers**: entries with `effective_state == pending` are marked `Suggested` over their `wordIds` (the closed range `firstWordId..lastWordId` in `words[]`). Entries with `category == pause` do not mark any word; they are written into `pauses_after[afterWord]`.
- **Removed pauses**: cuts with `entries[].kind == silence` also go into `pauses_after` (shown as a small struck-through label, `◷ 1.4s`).

## 5.2 Selection `CutSelection` and timeline sync

```rust
pub struct CutSelection { pub src_id: String, pub first: String, pub last: String, pub live: bool }
pub struct CutSelectionSpan { pub source_start: f64, pub source_end: f64, pub fragments: Vec<MappedEvent>,
                              pub duration: f64, pub label: String /* "1.9s · 00:07.1 – 00:09.1" */ }
pub fn selection_span(sel: &CutSelection, words: &[WordTiming], duration: f64, fps: f64, map: &TimelineMap) -> Result<CutSelectionSpan, CutModeError>
```

- `first/last` are given by the view's drag-selection hit (normalized in `words[]` order; spanning paragraphs and spanning speakers is allowed).
- Source span = `resolve_word_span(words, first, last, duration, fps, DEFAULT_WORD_PAD, DEFAULT_WORD_PAD)`. This is the **same function** the `cutWords` op uses, so the duration shown on the toolbar is exactly the duration that will be cut.
- Timeline fragments = `map.clamp_source_event(src, start, end)`. When the range crosses a removed segment, `fragments.len() > 1`, the highlight draws multiple blocks, and the label uses `duration = Σ fragments`, with the timecodes from the start of the first block and the end of the last block.
- Timecode format is `mm:ss.d` (consistent with transport). The duration format reuses the prototype `label(secs)` (`0.8s` / `1 分 12 秒`, i.e. “1 min 12 s”).
- The selection and `SelectionSet` (element selection) are mutually exclusive: `cut_mode::on_pick_element` clears the selection, and entering cut mode while `SelectionSet` is non-empty clears element selection first. The mutual-exclusion rule is written in the core; both ends only forward events.

## 5.3 Actions, key bindings and toolbar state machine

```rust
pub enum CutAction { CutSelection, AuditionSelection, ClearSelection,
                     AcceptItem(String), DismissItem(String), AuditionItem(String), RestoreCut(String), AuditionCut(String),
                     AcceptAll, DismissAll, RestoreAll, Rescan }
pub enum CutOp { TimelineOps(Vec<Value>), Review { action: ReviewAction, items: Vec<String> }, Audition { source_start: f64, source_end: f64 }, None }
pub fn resolve(action: CutAction, marks: &CutMarks, sel: Option<&CutSelection>, review: Option<&CleanupReview>) -> CutOp
pub fn toolbar(sel: Option<&CutSelection>, span: Option<&CutSelectionSpan>, scrolled_out: bool) -> Option<Toolbar>
pub fn key_predicate(key: &Chord, ctx: &CutKeyContext) -> Option<CutAction>
```

- `CutSelection` → `TimelineOps([cutWords {srcId, first, last}])`. `AcceptAll` → `Review { accept, items: all effective pending }`. `RestoreAll` → `TimelineOps([restoreCut …])` as one batch (one request = one journal entry = one ⌘Z).
- Key bindings merge into the abstract action table in [`ccut-editor-interaction-port-design.md`](../ccut-editor-interaction-port-design.md) §2.8: `⌫ / Delete` with a `CutSelection` = `CutSelection` (capture phase, ahead of element deletion; passes through when there is no selection), `Esc` = `ClearSelection`, `⌘↵` = `AcceptAll`, and `Space` with a selection = `AuditionSelection`.
- Toolbar: hidden while `live` (drag-selection in progress); collapses when `scrolled_out` (the first line of the selection has left the visible area). Content = `span.label` + cut / audition / cancel.
- The three-state summary bar copy (§13.1) is produced by `summary_text(marks, review, view_duration) -> SummaryBar`:
  - With suggestions → “N 处建议 · 共 X ／ 口癖 a 处、停顿 b 处、重复起句 c 处 [· 另有 M 处已剪]” (Chinese UI copy; gloss: “N suggestions · X in total ／ filler words a, pauses b, repeated sentence openings c [· M more already cut]”).
  - No suggestions but something cut → “已剪掉 N 处 · 成片 m:ss ／ 省下 X” (Chinese UI copy; gloss: “N cut · finished film m:ss ／ X saved”).
  - Neither → “拖选一段文字，按 ⌫ 剪掉” (Chinese UI copy; gloss: “Drag-select a passage of text, then press ⌫ to cut it”).
  - `view_duration` comes from `CutSet::view_duration()`.

## 5.4 Timeline projection: seam markers and suggested segments

```rust
pub struct SeamMarker { pub cut_id: String, pub timeline_time: f64, pub removed_sec: f64, pub category: String }
pub struct SuggestedSeg { pub item_id: String, pub timeline_start: f64, pub timeline_end: f64, pub category: String }
pub fn timeline_overlay(cuts: &CutSet, provenance: &CutProvenance, review: Option<&CleanupReview>, map: &TimelineMap) -> (Vec<SeamMarker>, Vec<SuggestedSeg>)
```

- Seam marker time = `map.source_to_timeline(cut.t0, SeamBias::Preceding)`. Adjacent seams within `CUT_MERGE_GAP` are already merged by the kernel, so they never overlap.
- Suggested segment = the fragments from `clamp_source_event(item.t0, item.t1)`. The suggestion has not taken effect, but its time is kept; there is generally only one fragment.
- App v2 `cutseg.rs` takes its input from `CutReview` to these two tables instead. This also fixes an existing defect where it drew source-clock `t0/t1` directly using the timeline `Scale` (§2.5). Web `ClipsRow` is drawn new. Both ends now receive only timeline seconds and no longer convert separately.
- **Naming settled (2026-09-07)**: the two tables are combined into `CutOverlay { seams, suggested }`. Projection after trim / speed / duplicate clip goes through `mapped_timeline_overlay` (projected clip by clip against the actual clips; shared by App and Web). The “across all tracks + fold + expand” from round 197 adds one more layer on top: `fold_view(overlay, expanded) -> FoldView { seams: Vec<SeamGroup>, slots: Vec<CutSlot>, removed_total }`. Seams adjacent at the same timeline position merge into one `SeamGroup` (ruler badge `−N.Ns`, title summarizing the categories, click = restore the whole group). When `expanded`, it yields `CutSlot` empty bands (stretched by the source duration, spanning all tracks). The App consumer is `timeline/cutbands.rs` (replacing `cutseg.rs`). Web does not yet wire `fold_view` (§15).
- **Dragging a slot band edge changes the range (2026-10-01, `1.303.0`)**: `SeamMarker` / `CutSlot` carry the multi-band cut's `src_id / t0 / t1` (source clock) and the `rate` of the clip they belong to. Pure function `drag_cut_edge(cuts, words, cut_id, CutEdge::{Start,End}, source_time, snap, fps, duration) -> Option<(t0, t1)>`: by default it snaps to word boundaries, with candidates the same as `cutWords` (left edge `word_span_start`, right edge `word_span_end`, with `DEFAULT_WORD_PAD` and frame alignment; hidden words are not candidates; if there are no words or no candidate within bounds, it falls back to free). Alt gives free drag, frame-aligned. The result is clamped to `[0, duration]`, does not cross adjacent cuts (touching is allowed), and is at least one frame wide; dragging past a bound sticks to that bound. Surface entry `drag_slot_edge(slot, cuts, words, edge, press_x, x, pxps, free, fps, duration) -> Option<CutEdgeDrag>`: source time = original edge + `(x − press_x) / pxps × slot.rate`. The preview moves only the dragged edge (`start' = start + (t0' − t0) / rate`; the right edge is symmetric). When `changed`, it carries `action = CutAction::RetimeCut {id, t0, t1}`, which `resolve` turns into `TimelineOps([retimeCut])` (cut missing or range unchanged → `None`). A press without movement returns unchanged. `FoldView::slot(cut_id)` returns the first band with that id (a seam that falls exactly on the junction of two main-track clips projects two bands). wasm `cutModeDragEdge(input, {cutId, edge, pressX, x, pxps, alt})`.
- **Compose fragments return to their own track (round 196 ruling)**: the kernel's compose splits a detached main-video clip into `video-<clip>-<n>` fragment elements per `clips[].segments`. `timeline_doc::compose_groups()` (`ComposeGroup { track_id, clip_id, source_id, element_ids, start, end, src_start }`) regroups all fragments of the same clip onto **that clip's own track**, so both ends show one block, seams are still drawn by `cut_mode`, and no new “main video” row is added (`COMPOSE_EPS = 1e-3`).

## 5.5 Audition window

`audition_window(source_start, source_end, duration) -> (f64, f64)` = `[max(0, start − 0.6), min(duration, end + 0.4)]`, returned on the **source clock** (§9.2).

## 5.6 wasm exposure and fixtures

- `core/crates/ccut-wasm-editor/src/api/cut_mode.rs`: `cutModeProject / cutModeSelectionSpan / cutModeResolve / cutModeToolbar / cutModeSummary / cutModeTimelineOverlay / cutModeAudition`. Signatures correspond one-to-one with the Rust, with JSON in and out.
- `core/fixtures/editor/cuts.json`: follows the `{cases: [{name, input, expect}]}` shape of `tests/fixtures.rs` (`input` has exactly one key naming the function to call; replayed by the `fixture!` macro and `cases()`, loaded with `include_str!` so it passes the purity gate). The Web twin test goes in `apps/web/tests/unit/editor-core/cuts.fixture.test.ts`, and the wasm export shape is registered in `ccut-wasm-editor/tests/api_shape.rs`. Cases cover: Chinese per character and English per word; suggestions overlapping manual cuts (`superseded`); accepted then withdrawn by ⌘Z (`accepted` but cut missing → `pending`); a selection crossing a removed segment (two fragments, label takes the total duration); a selection containing `hidden` words (the breathing pad does not cross adjacent visible words); the `keep` head and tail for pause suggestions; byte ↔ UTF-16 range conversion (including emoji and full-width punctuation); and the three states of the summary bar. Cases for source range → timeline fragments are added to the existing `core/fixtures/timeline-map-contract.json` rather than to a separate file.
