# 17. Open Questions and Known Gaps

> From [CucCut File-Contract Subtitle AI Pipeline Design (File-Contract Pipeline, v0.3)](../ccut-file-contract-subtitle-ai-design.md)

## 17.1 Items Pending Calibration (carried over from v0.2, still open)

- Re-calibration of the 8000-word translation/alignment budget and the page-level match threshold of 0.7 for polish on large pages (stress test).
- Choice of the page-budget scaling factor for CJK pages.
- Final field-compatibility checklist between `report.json` and the current consumers of `ai/polish.json`.
- Verbatim fidelity rate of small-model segment-only output (this determines the shortcut hit rate and the cost model).
- Whether v2 needs B's `TextPatchSet` overlap merging (only if stress testing falsifies the seam quality of the read-only context approach).

## 17.2 Known Unimplemented Items (M1–M4 Reconciliation Results)

The items below are **described in the body of this document but not implemented in code**. Each gives "why not now" and "the entry point for later". None of them constitutes M5 workload.

| Gap | Why not now | Entry point for later |
|---|---|---|
| **`LlmDocument` / `DocumentRequest` transport channel** (§9.1): the struct is defined but has no construction site; the engine still uses `LlmJson`; `sha256` is always empty | Switching the trait would require changing the engines of all four stages and both execution paths at once; the risk and benefit do not match. Carrying documents in `LlmRequest.user` already works for the file contract | `core/crates/ccut-flow-core/src/llm.rs`, `filepipe/common.rs::DocumentRequest`; first run one stage (minimal align) in dual mode and cross-check the results |
| **`references[]` channel** (§5.3/§9.2/§9.3): the claim envelope has no such field, and the provider envelope has no `<BEGIN REFERENCE>` section | Depends on the previous item. The current approach of "inlining only the glossary lines that hit this page" has not been shown to lack quality | Same as above; on the provider side, change `llm_exec.rs::request_user_content` |
| **Content-addressed reuse cache** (§9.5): still a linear scan with full string equality, no digest | Depends on `DocumentArtifact.sha256`; and the real reuse hit rate is currently very low, so the benefit is unverified | `llm_exec.rs::reuse_prior_response` / `reuse_logged_response` |
| **Per-kind model routing `llm.stages.*` / `--llm-for`** (§9.4) | Until someone asks for it, an extra configuration surface is just another source of misconfiguration. The benefit of the cheap `segment-only` tier must first be proven by the fidelity stress test in 17.1 | CLI argument layer + provider selection point in `llm_exec` |
| **Splitting the agent task directory into data plane and control plane, and `responses` not embedding body text** (§9.2) | A destructive directory change that affects the CLI, the worker skill docs and in-flight tasks; it cannot be done in the same batch as the contract track switch | Directory constants table in `llm_exec.rs` (first lift the scattered `format!` literals into constants) + `cmd/task.rs` |
| **Worker-side local validator subcommand** (§9.2) | First requires settling the form of a "read-only validation" command and its exit code contract. This is a CLI contract change and must sync `ccut-cli-server-reference.md` | Add `ccut task lint --file` (or equivalent) + `serve/contract.rs` |
| **Lint budget changed to a per-call constant** (§9.2) | The actual turnover rate of the file contract has not been observed yet. Changing the lease system's semantics carries more risk than the current exposure | `cmd/task.rs::read_lint_tries_for_lease` / `bump_lint_tries` |
| **Re-calibration of `default_lease_sec`** (§9.2) | No worker tail-latency measurement under the file contract exists. HTML payloads are larger and fall into a higher tier, so the direction is safe | `llm_exec.rs::default_lease_sec`; add a pinning test that "the HTML tier is not lower than the equivalent JSON tier" |
| **`ArtifactWriter` reuses the currently effective version** (§4.1): `open` always creates a new `vNNN` | Reuse needs a "resumable" predicate (same stage+lang+input fingerprint **and** no truth write in between), and nowhere currently computes it. A wrong judgment would silently merge two unrelated runs into the same audit directory. The outputs are audit artifacts; always creating new ones costs disk, not correctness | `core/crates/ccut-kernel/src/services/ai_artifacts.rs::ArtifactWriter::open` |
| **align: 1 sentence of read-only context before and after each** (§8.2/§12): the carrier supports it, the engine passes empty | The wiring itself is easy, but it would change packing size and the comparability with existing benchmarks. It should be done in the same batch as the 17.1 stress test | `context_before`/`context_after` at the request construction in `engines/align.rs` |
| **timeline routing lacks a translation provenance ledger** (§7.7 × §11.3) | The timeline variant has already moved to file-v1 along with the deprecated execution (2026-08). But a ledger keyed on `(srcId, sentenceId)` for multi-source routing without sentence-level target truth still requires first resolving whether "the same sentence under multiple sources counts as the same provenance record" | Key type in `provenance.rs` + timeline branch in `ai.rs` |
| **JSON contract deprecation** (§7.8, §13.1 (1), §9.6) | **Executed** (2026-08): the `--contract` argument, `ContractMode`, `TRANSLATE_FUSED_WORDS`/`TRANSLATE_WORDS`, the json `run_polish`, and `MAX_CARRY_CHARS` have all been removed, and the five migrated kinds are fixed at file-v1. Remaining sub-items: removal of the brief double-write and migration of the Mac read points are not done (`brief.json`/`polish.json` are still double-written) | Remaining order: Mac switches to reading `context.md` → remove the brief double-write |
| **`refine-align` integration with the file contract** (§14) | refine has its own set of targeted retries and acceptance bookkeeping, which overlaps with the wave bookkeeping of §7.5/§8.4. Direct integration would double-count attempts | `TranslateArgs` construction site in `core/crates/ccut-kernel/src/cmd/refine.rs` |
| **`ccut glossary lock/set` subcommands** (§5.2) | Optional from the start. Hand-editing `context*.md` is already a complete entry point | New CLI subcommand + `ccut-cli-server-reference.md` |
| **Merge the two align validators into one call site** (§2/§13.1 (4)) | The arithmetic is already shared. What remains is two call sites and two copies of the same text. Merging would change the provider acceptance and the common preparation data for the agent lint | `engines/align.rs:4721` and `:5410` |
