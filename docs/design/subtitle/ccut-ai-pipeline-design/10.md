# 10. LLM call layer

> From [ccut transcript post-processing AI pipeline design (polishing / segmentation / chaptering / translation / subtitle alignment)](../ccut-ai-pipeline-design.md)

## 10.1 Structured output: json_object + engine-side semantic validation

**Do not use json_schema strict mode**, because it is not portable across the OpenAI / Volcano Ark / Gemini-OpenAI compatibility layers. Constraints come from three stacked layers:

1. `response_format: {"type":"json_object"}` (guarantees only valid JSON; the prompt describes the shape verbatim, which also satisfies OpenAI's json_object requirement that the prompt "must mention JSON");
2. **Fence-strip parsing**: take the outermost `{…}` in the response, tolerating markdown fences and surrounding chatter; numeric fields use lenient decoding (accepting `12`, `12.0` and `"12"` alike);
3. **Engine-side deterministic semantic validation** (coverage, id reconciliation, normalized equality, similarity). This is the real constraint layer; failures go through the unified retry.

Compatibility branch: HTTP 400 with an error mentioning `response_format` ⇒ drop that field and resend once (some lightweight models do not support it; fence-strip can still recover JSON from prose).

## 10.2 Error classification and retry

```rust
pub enum LlmError {
    Http { status: u16, message: String },   // 0/408/429/5xx retryable; 401/403/404 terminal
    Malformed(String),                        // retryable
    Terminal(String),                         // provider terminal error; leaves the pipeline immediately
}
```

- Layered retry: the transport/JSON layers follow the table above; **semantic errors (thrown by the engine) are retryable by default**. This is how "mapping failure = attempt failure" is implemented. Retry ×3 with 2s backoff; cancellation aborts immediately. Where `status=0` means a transport failure before any HTTP status was received, such as DNS, connection, TLS, connection reset or timeout, it also enters the same bounded retry;

**Three-level classification of semantic rejections (redesigned 2026-08).** Each kind defines a "unit" (analysis = table row, polish = in-page sentence, translate = sentence id, chapters = chapter row; other waves are unit-level from the start). Problems are graded by scope into three levels:

| Level | Meaning | Handling |
| --- | --- | --- |
| **page-fatal** (structural) | The whole document cannot be parsed: no fences and no core region can be inferred, no recoverable units at all, size exceeds the hard cap, or atom-LCS coverage of the core region < 0.7 | The only level that allows a whole-page retry |
| **unit** (unit-level) | A unit is missing, duplicated, drifted, or fails validation | That unit is judged failed; other units are accepted and persisted as usual; failed units enter the make-up queue |
| **advisory** (advisory-level) | Drift in read-only regions, frozen sentences edited or moved, extra nodes, lines over the limit, surface-level rewrites | Only logs a Warning; code corrects or ignores deterministically; does not affect acceptance |

Three landing principles:

- **Code fixes first**: any problem that code can resolve must not trigger an LLM retry. Examples: dedupe/merge, column-count repair, missing fences inferred from adjacent fences, conflicting punctuation normalized, categories downgraded to `other`, Lock/Origin downgrades, out-of-range rows truncated. For that reason the size guard becomes a **hard cap**: `max_output_chars` = 8× input (floor 4096). Only exceeding the hard cap is page-fatal; otherwise the output is parsed as usual and handed to the unit rules;
- **Shrink on retry**: unit-level failures do not resend the whole page. The page is re-paginated by the kind's existing make-up carrier (only the failed units plus necessary read-only context), and each round carries `[code] detail` feedback. Make-up rounds are capped at 2 (`RetryPolicy::UNIT_ROUNDS`). Page-fatal whole-page attempts are 2 (`RetryPolicy::MAX_PAGE_ATTEMPTS`; the 2nd carries feedback). After that the page is **split in half** (each half is cut in two by its own paginator over the page's word range / sentence set), with 1 attempt per half. Halves that still fail go to the existing fallback. The total call cap is on the same order as the old "whole page ×3", and the fallback granularity is halved;
- **Exhaustion only affects failed units / halves**: keep original words, leave them as-is or split them deterministically, and report counts. Do not fall back for the whole page and do not abort the command. `Terminal` / `Cancelled` still propagate immediately.

Batch primitives correspondingly add the report-style variant `complete_batch_retry_report`: when rounds are exhausted, **every** failed page and its reason is returned to the caller (the old `complete_batch_retry_with` reported only the first one and is now a thin wrapper over it).

- **429 is absorbed in place by the provider executor and does not consume the retry budget above**: hosted quota windows are minute-scale, so a 2s backoff will inevitably hit the limit again. When rate-limited, first retry immediately with `CCUT_API_KEY_<PROVIDER>_FALLBACK` (if configured), then wait per the server's `Retry-After` header or the `retryDelay` suggestion in the body and retry, at most two rounds. If the suggested wait exceeds 75s (common with daily quota exhaustion), propagate immediately rather than pinning the lane;
- Retries may carry a structured `retryReason`, which is injected into the next call's prompt;
- **In-batch tail-latency hedging**: the provider batch defaults to 8 lanes (config key `llm.maxConcurrent`; the env var `CCUT_PROVIDER_MAX_LANES` overrides it wholesale, and `0` means unlimited). Hosted model call durations have huge variance. Measured: when aligning the same round of same-size requests, most return in 50–82s while some take 246s. Since later fix rounds have barriers, all lanes just sit idle. Idle lanes that have finished dispatch therefore duplicate the still-in-flight long-tail calls and take whichever returns first, discarding the loser. It is not fault tolerance (the hedged call itself succeeds); it is variance governance, using lanes that were idling anyway. Three self-limits: judgment starts only with ≥3 completed samples; the threshold is the batch median ×2 and not below 45s; each request is hedged at most once. The agent executor also hedges, but both the samples and the in-flight durations count only **worker time** (claim → submit; queueing is not counted; calls with no claim record fall back to creation time), and the coefficient for the last remaining in-flight call is reduced to 1. Otherwise 12 sonnet sessions over 4 rounds of queueing would push the threshold to 26 minutes, effectively disabling it;
- **Gemini's `effort=auto` must still cap the thinking budget**: not sending `thinkingConfig` does not mean "no thinking". It is an uncapped dynamic budget, which is exactly the root cause of the 33s-vs-246s long tail above (the long-tail call's load was also the smallest in its round). So auto falls to 8192, while explicit `--llm-effort low/medium/high` still map to 512 / 8192 / 24576 respectively. The budget is a ceiling, not a quota; the model thinks as needed; measured thinking-token demand is 2.5k–9.3k. It is only sent for 2.5 and later models. 2.0/1.5 receive `thinkingConfig` and return 400 outright, so when the version number cannot be recognized it is never sent;
- **DeepSeek V4's file tasks disable thinking under `effort=auto`**: V4's OpenAI ChatCompletions enables thinking by default, and `max_tokens` counts both reasoning and the final body. If reasoning exhausts the limit first in whole-page write-backs such as polishing, translation or alignment, the result is HTTP 200 with an empty `content`. So auto sends `thinking:{type:"disabled"}`; explicit `--llm-effort` still enables native thinking. The empty-body error logs only `finish_reason`, the reasoning character count and the reasoning token count, never CoT text;
- Every call (success and failure) writes a file log: kind / project / model / system / user / response / error / duration / `hedge`, for after-the-fact auditing, replay and A/B, regardless of executor. Records with `hedge=true` are hedge copies with the same prompt and attempt as the original call. **They do not represent any failure** and must be excluded when computing retry rates.

## 10.3 Dual execution modes (aligned with CLI design §8)

The `ccut-flow-core` engine depends only on the `LlmJson` trait; the CLI provides two executors:

- **provider executor** (`--llm provider:<id>`): ureq connects directly to OpenAI-compatible / Anthropic / Gemini (note for the Anthropic branch: thinking mode requires `temperature=1` and `max_tokens > thinking budget`); keys come from `CCUT_API_KEY_<PROVIDER>`;
- **agent executor** (default): a stage issues a "call" = contract file + payload file written to `tasks/`. The Agent claims and answers via `task claim / submit --next`. Answers are written to the database only after passing lint (= the same engine-side semantic validation); `rejected` answers are retried under the same lease with per-item problems (≤3 times).
  **Prompts and answers always travel by file path and never enter the conversation context.**

Both modes produce artifacts with an identical schema and identical call records.

## 10.4 Parameters per stage

| Stage | temperature | Retry | Response format | Page budget (source word count) | Concurrency |
| --- | --- | --- | --- | --- | --- |
| brief/analysis | 0.2 | 3 × 2s (page-level exhaustion drops only that page; succeeds if ≥1 page succeeds and merges; Err only if all pages fail) | file-v1 Markdown (`ParseMode::Model` lenient parsing: dedupe / column-count repair / junk-line filtering / per page 150 lines · whole document 400-line truncation) | 8000 | extract batch (agent multi-worker); glossary is a deterministic engine-side union, and the summary merge is a single short call |
| speaker-repair (before pagination; sent only for multi-speaker documents) | 0.1 | ≤2 rounds (each round is a retry; accepted window by window; rejection keeps the original as is) | file-v1 text index contract (multi-window fences, one word per line with line numbers, block header states existing speakers and current ranges, answer returns only `start-end label`) | ≤8 windows/call (window ≤240 words) | batch |
| polish | 0.2 | whole page ×2 → halves ×1 each → half-page fallback; sentence-level `polish-retry` ≤2 rounds | file-v1 text (fences recoverable; read-only region drift and surface flaws only logged as warnings) | 2200 core + 200 context on each side | batch |
| punct-repair (after the polish wave, before segment-repair) | 0.2 | ≤3 rounds (each round is a retry; accepted sentence by sentence; after exhaustion the engine splits sentences deterministically) | file-v1 text (one pair of id fences per sentence, ⏸ pause hints, only adds sentence-final punctuation) | 2200 (overlong sentences re-paginated once more, supplementing pages per worker slot count) | batch |
| seam-repair (after punct-repair, before segment-repair) | 0.2 | ≤2 rounds (each round is a retry; accepted block by block; rejection keeps the original segment pinned) | file-v1 text index contract (multi-block fences, one sentence per line with line numbers, block = tail window of page k's last paragraph + head window of page k+1's first paragraph, answer returns only line-number ranges) | 2200 (page-seam blocks re-paginated once more) | batch |
| segment-repair (after polish wave) | 0.2 | ≤3 rounds (each round is a retry; accepted block by block; after exhaustion the engine closes out deterministically by pause level) | file-v1 text index contract (multi-block fences, one sentence per line with line numbers, block header states the minimum number of segments, answer returns only line-number ranges) | 2200 (over-limit paragraphs re-paginated once more) | batch |
| speaker-names (polish wrap-up; sent only when placeholder speakers exist) | 0.0 | ≤2 rounds (whole-answer acceptance; on exhaustion keep placeholder names) | file-v1 text evidence contract (opening-remarks window + each person's first-appearance window + table of pending labels; answer returns only `label = name`) | single call (opening remarks 400 words + ≤180 words per person) | single |
| segment | 0.2 | 3 × 2s + tier4 + tier5 | json_object | 8000 | batch |
| chapters / chapters-outline | 0 | 3 × 2s (structured problems; empty titles and unrepairable anchors are row-level discards, and only page-fatal when 0 rows remain) | file-v1 HTML | 8000 (paragraphs atomic; single page output directly, multi-page Map in parallel + single Reduce) | Map batch / Reduce single |
| translate | 0.3 | wave 1 whole page ×2 → halves ×1 each (exhaustion no longer a hard error) → wave 2 per-page make-up → wave 3 cross-page residuals | file-v1 HTML (duplicate ids take the first, truncation keeps the parsed prefix, edited or moved frozen sentences only logged as warnings) | with default `rows` mode: 800 (shared by both executors); `--align-fusion on\|off` falls back to 2000 (declared per tier by agent / provider, currently the same value) | batch (agent multi-worker; provider multi-lane) |
| display split / align | 0.2 | 1 global repair round + deterministic fallback | file-v1 HTML | 2000 + ≤40 items per page + 16000 complexity budget (targeted repair is identical) | agent multi-worker; provider multi-lane |
| summary / blog / titles (three writing tools, §11.4) | summary 0.2; blog / titles 0.4 | 3 × 2s (page-level exhaustion in Map fails the whole thing; writing has no partial output to deliver) | file-v1 Markdown | 8000 (sentences atomic; single page output directly, multi-page Map in parallel + single Reduce) | Map batch / Reduce single |

**Unified word-count pagination**: analysis, segment, chapters, translate and align all reuse `atomize::word_count`. Latin text counts 1 per word, CJK counts 1 per character, and punctuation is atomic with its content and not counted separately. The translate page count is `ceil(source word count / (budget + 10% slack))`. In the **default `rows` mode**, both executors share the smaller 800-word tier (`/880`; rationale and tier details in §8.6.1). Only with `--align-fusion on|off` does it fall back to the regular tier (agent / provider currently both 2000, i.e. `/2200`). Page boundaries are then balanced across consecutive order (§5.3).
align takes, on top of the same word-count page count, the maximum of `ceil(items to align/40)` and `ceil(total complexity cost/16000)`, and balances consecutive pages by complexity. Concurrency slot tiers still do not change page shape. The page-splitting tier for the align stage does not change with the `--align-fusion` value.
`CCUT_LLM_PAGE_WORDS` only overrides the word-count constraint (including rows' 800-word tier), and does not turn off safety guards.
Targeted repair and first-pass alignment share the same three-constraint pagination; the worker count only affects how already-formed pages are consumed concurrently.

**Fusion draft channel** (`--align-fusion rows|on|off`, default `rows`): see §8.6 / §8.6.1. `rows` takes effect only under `--align-mode many-to-one`, and does not change the retry policy or response format in this section (`file-v1` HTML is unchanged). It only changes the fusion contract section of the translation prompt, the carrier attributes, and (only for `rows`) the translate page budget above. `on` is the old minimal semantic-block contract, kept as an optional fallback after promotion.

**Brief reuse for align-only (refinement) rounds**: `--align-only` does not change the translation truth. On this path the brief is only consumed (protected terms + bilingual anchors). Refinement rounds cannot obtain the translation round's analysis / instructions / tone; judging by generation inputs necessarily mismatches, so it would waste a translate-brief run and overwrite `ai/brief-<lang>.json` wholesale (terms `locked` by the user would be wiped out too). Therefore the reuse condition on this path is relaxed to "document word fingerprint + matching target language". The judgment semantics for translation rounds are unchanged.

**Slash rule for the brief glossary**: a slash counts as alternative candidates and is rejected only when the target **invented** it out of thin air. Glossary entries whose source term itself contains a slash (CLI flags like `/compact`, path-style identifiers) must be preserved verbatim. Validation lets them through, and so do the per-line rules in the translate stage and glossary injection. The old rule rejected all slashes across the board, which directly contradicted the "identifiers preserved verbatim" prompt. The model had no legal output, and the whole brief round was discarded and rerun. This validation is also the implementation of the agent submission-time lint (§10.3; the same code is reused by both executors), so a bad glossary is now repaired within the same lease instead of falling out into a brand-new call.
