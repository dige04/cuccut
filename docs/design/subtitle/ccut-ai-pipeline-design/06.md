# 6. Stage 2: Segment (segment)

> From [ccut transcript post-processing AI pipeline technical plan (polish / segment / chapter / translate / subtitle alignment)](../ccut-ai-pipeline-design.md)

## 6.1 Contract: punctuation only, proven by normalized equality

The LLM contract for the segment stage is narrower than for polish: **keep the source text verbatim, only add or correct punctuation, then split into paragraphs of 1–4 sentences**. "Punctuation only" is not a request but a decidable proposition: after `normalize_chars` (which strips punctuation, whitespace and case), the text must be **strictly equal** to the source word span. If it is not equal, that paragraph's text is downgraded to the original words and its boundaries are kept as they are:
**boundaries tolerate drift, text never lies**.

Key points of the prompt (inherited from voice-ink `SegmentPrompts`):

- State explicitly that the downstream consumer is a subtitle splitter, "your punctuation is the cut point", so clause boundaries always get a comma;
- Dots in abbreviations, decimals, version numbers and file names are not sentence ends (`agents.md`, `2.14`, `e.g.`);
- `⏹` (speaker change) must always break. But this is only a hint: **after the result is received, the deterministic `split_at_speaker_changes` hard guarantee still applies**;
- Response: `{"paragraphs": ["…", "…"]}`.

## 6.2 Five-tier mapping ladder

```
tier 1  exact — page-level normalized character equality → O(n) character offset mapping (most common)
tier 2  diff  — atom-LCS (the model quietly fixed a typo), match ratio ≥ 0.75
tier 3  align — per-paragraph cursor scan recovers word spans (text is always discarded, only boundaries kept)
tier 4  json  — after 3 failed attempts, one index-contract call (returns only span indices;
                clamping + continuity self-healing, gaps of ≤10 words snap automatically)
tier 5  split — deterministic fallback: speaker change / ≥1.2s pause / sentence end after 200 characters /
                hard break at 400 characters. Never fails.
```

Tiers 1–3 are tried in order within each attempt; 4–5 are escalations. 401/403/404 abort the whole run.

## 6.3 Artifacts and write-back

- Runtime `SegmentedParagraph` (word indices, volatile) → persisted `SegmentRecord`
  (`firstWordId/lastWordId/t0/t1/text/source`) written to `ai/<media>/segment.json`;
- Restoration (artifact → paragraph plan) is **extremely conservative**: fingerprint must match, ids must not repeat, spans must be contiguous, and coverage must be complete. If any condition fails, it returns a failure. Partial or stale artifacts never silently become a source of structure;
- **Write-back to transcript**: punctuation fixes go through rebind onto the word text; paragraph structure is exported as `paraBreaks` pins on the first word of each following paragraph (the trailing paragraph and speaker boundaries are skipped where they are forced). Cue derivation itself still uses the canonical algorithm of §18.5. The segment stage feeds it better punctuation and paragraph pins rather than establishing a separate splitting system. If the model drops spaces between multiple Latin source words and produces new atoms that exceed the single-line hard budget, the text gate discards that paragraph's punctuation answer and keeps the original words and paragraph boundaries, so that rebind does not create an over-wide Cue without internal word seams;
- Commit: after rebind, first migrate and clear the stale `breaks` / `paraBreaks` / `hidden` keys by time proximity. If an old `nobreak` welds the revised Cue beyond the single-line hard budget, remove only the `nobreak` inside that over-wide Cue and keep other manual pins. Then write `stages.segment = id_fingerprint(words)`. If segment follows a completed polish, the punctuation revision is a legitimate post-processing step, so the polish content fingerprint is refreshed in sync rather than reporting stale. Once the paragraph pins are settled, the balanced break layout is laid out with the same strategy as the polish stage (only where no `breaks` already cover it, see §5.6), and `stages.asrLayout` is refreshed with the final pin set.

Parameters: page budget 8000 (§5.3 balanced pagination), `temperature 0.2`, retries 3 × 2s, serial.
There is also an optional **line-width review** (an optional second call, kind `repunct`): it re-punctuates paragraphs whose widest clause exceeds one line. With zero overflow it makes zero calls. If the answer is rejected, the original text is kept.
