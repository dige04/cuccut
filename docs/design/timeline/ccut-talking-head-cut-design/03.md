# 3. Key Decisions

> From [CucCut talking-head cut design (prototype rounds 192–197 → kernel / serve / App v2 / Web)](../ccut-talking-head-cut-design.md)

| # | Decision | Basis / cost |
|---|---|---|
| C1 | **Cut truth = `sources[].cuts[]`; attributes go into `ai/cuts.json`; no new top-level table.** | `timeline.json` top level is closed. `cuts[]` is already folded by playback, subtitle projection, chapters, export and six writers. `ai/cuts.json` is open and already carries `kind / reason / wordIds / origin`. The prototype's `by / batch / text` each have a home (§4.1). |
| C2 | **Suggestion truth = `ai/reviews/cleanup.json`, reviewVersion 3 → 5 (4 is already taken by the chapters overlay), entries carry `state`.** Suggestions are not written into `timeline.json`. | The rule "no effect on playback or export before acceptance" is exactly "not in timeline". App v2 and `ccut-editor-core::review` already read this file. `TIMELINE_CURRENT` is left unchanged. |
| C3 | **The accept gate changes from the whole `baseTimelineSha` to a per-item overlap check against the current `CutSet`. The transcript gate changes to a content fingerprint, `fingerprint(words)`.** | Cutting one spot by hand must not invalidate all nine suggestions. A suggestion references word ids and source times, so it stays valid as long as the words still exist and their times are unchanged. Overlapping items go into `skipped[]` (reason `already-cut`) with HTTP 200, consistent with the `skipped` convention of `timeline/apply`. |
| C4 | **Suggestion state after undo is derived, not stored: `state: accepted` whose `cutId` is no longer in `cuts[]` is treated as `pending` on read.** | ⌘Z undoing an accept, `restoreCut` restoring a cut, and an external process running `cut restore` all make the cut disappear. Deriving on read is more reliable than changing the review file on each of these paths, and it keeps the journal tracking only `timeline.json`. |
| C5 | **Manual cut = `cutWords`; accepting a suggestion = `apply_cleanup_suggestions` (`cutRange` semantics).** No new `timeline/apply` op. | The `t0/t1` of pause suggestions already include the head and tail kept after compression (`detect_silences`), so they must be cut as a range. Word suggestions are already anchored by WordSpan at generation time. |
| C6 | **The review write path enters the protocol: `Command::Review {project, kind, action, items, batch}`, specVersion 1.58.0 → 1.59.0.** App v2 switches from a subprocess to `Kernel::dispatch`, and Web goes through serve. | ADR-4 prefers a resident kernel. contract_tests require new handlers to go through the envelope. One accept = one journal group. |
| C7 | **Timeline: cut segments fold into seam markers; suggested segments stay in place as dashed lines.** | The three time domains are a kernel contract (view time = source time folded by cuts). Playback, subtitles and export all follow it, so the UI must not invent a separate clock with "in-place hatching". Seam markers carry a `−0.8s` badge, and clicking one restores the cut, which still satisfies "visible, and can be recovered by a click". Prototype divergence is logged in §8.4. |
| C8 | **Categories have two layers.** Provenance `kind` stays closed as `silence|filler|badTake|manual|match` (since `1.291.0` it also has `offScript`: off-script talk removed by `cut script`, see [talking-film design draft §5.1](../../video/ccut-talking-film-design/05.md#51-按稿预剪)). The fine-grained `category: filler|pause|retake|falseStart|repeat` is written in `ai/cuts.json` and on review entries, and UI copy follows the fine category. | Do not change `ops.rs:926` or the lint rules. An LLM-added `repeat` category maps to `badTake`. |
| C9 | **Incremental semantics for cleanup**: a new scan replaces all `pending` entries, keeps the records of `accepted / dismissed` entries, and `skip_already_cut` skips proposals that overlap already-cut ranges. | Consistent with prototype §12.6: "a new scan replaces unprocessed suggestions; cut ones stay untouched". `dismissed` is kept so that a spot the user already rejected is not suggested again (deduplicated by `firstWordId..lastWordId`). |
| C10 | **All criteria for cut mode go into `ccut-editor-core::cut_mode`, exposed via wasm and checked against fixtures.** | Same layering as the interaction porting plan. Neither end may compute timecodes on its own. |
| C11 | **Receipt undo (review kind) = all `pending` entries in the batch → `dismissed`; redo = back to `pending`. Accepted cuts are unaffected.** | Stated explicitly in prototype §15.3. The journal does not track the review file, so this undo goes through `Command::Review` rather than `history undo`. |
| C12 | **No "experimental project" concept in the kernel.** | Any project with no elements is one. The difference lies only in empty-state copy and wizard presets (§8.4). |
