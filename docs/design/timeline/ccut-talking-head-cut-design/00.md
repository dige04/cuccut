# 0. Summary on One Page

> From [CucCut talking-head cut technical plan (prototype rounds 192–197 → kernel / serve / App v2 / Web)](../ccut-talking-head-cut-design.md)

1. **No new data structures; the `timeline.json` schema is unchanged.** Items in the prototype's `cuts[]` with `state: 'cut'` are the existing `sources[].cuts[]` (lossless soft deletion; playback, subtitles, export and all six NLE writers already fold them). `kind / text / why / by / batch` live in the already-open sidecar `ai/cuts.json`. Items with `state: 'suggested'` are the existing `ai/reviews/cleanup.json`; this plan upgrades it from a whole-file pending / accepted state to **per-item state**, and relaxes the gate that invalidates the whole file whenever the timeline changes.
2. **Manual cut = existing `cutWords` op; accepting an AI suggestion = existing `apply_cleanup_suggestions`.** Breathing padding, frame alignment, not crossing adjacent visible words, 0.02s merging and the `clip-empty-after-cuts` lint are all already in place.
3. **Suggestions and manual cuts coexist** via two rules: on accept, each item is checked for overlap against the current `CutSet` rather than comparing the whole `baseTimelineSha`; an accepted suggestion whose `cutId` has disappeared from `cuts[]` (⌘Z or restore) returns to the pending state on read.
4. **The write path is unified in the protocol.** Add `Command::Review` (`specVersion` 1.58.0 → 1.59.0, minor). serve exposes `GET /__ccut/reviews` and `POST /__ccut/review/apply`. App v2's `resolve_review`, which used to spawn a `ccut review accept` subprocess, switches to `Kernel::dispatch`, and Web gets the review write path for the first time.
5. **Both ends only draw, they don't compute.** Word tokenization, mark derivation, selection → WordSpan → timeline segments and timecode labels, the three-state summary bar copy, the floating toolbar state machine and key-binding predicates all go into `ccut-editor-core::cut_mode` and are exposed via wasm, with three-layer cross-checking against `core/fixtures/editor/cuts.json`.
6. **On the timeline, cut segments collapse into seam markers rather than being hatched in place as in the prototype.** This is the kernel's existing semantics (§2.3 three time domains), and it is also how Descript does it. Suggested segments are still drawn in place with dashed lines, because they are not in effect yet (the time is still there). The divergence is recorded in the prototype ledger.
