# 7. Write path and protocol

> From [CucCut talking-head cut technical plan (prototype rounds 192–197 → kernel / serve / App v2 / Web)](../ccut-talking-head-cut-design.md)

## 7.1 Manual cut and restore: reuse `timeline/apply`

- Cut a selection: `POST /<id>/__ccut/timeline/apply {baseRev, label: "剪掉 1.9s", ops: [{kind: "cutWords", srcId, first, last}]}`. The response's `applied[]` carries `cutId` and `snapped: true`; `staleTranslations` works as before.
- Restore: `[{kind: "restoreCut", cutId}]`; restoring all = one batch of ops.
- Change the cut range (from `1.303.0` on; in the expanded state, drag the left or right edge of the empty-slot band): `[{kind: "retimeCut", cutId, srcId?, t0, t1}]` (source-clock seconds). The cut boundary is changed in place; `id` / `ref` and the source category in `ai/cuts.json` are kept (provenance entries only change `t0` / `t1`). Elements follow per `ClockEdit::Retime`, using the current composed output as the baseline. The main video picture matches running `restoreCut` and then `cutRange`. Numeric time overlay elements whose start or end falls inside the new cut range snap to the current composition; they do not first expand back to the restored state, so the result may differ from restoring first and then cutting. One step undoes it. Overlapping another cut from the same source returns `invalid_arg` (touching edges is fine). If the range is unchanged, the batch returns `unchanged`. Undo only reverts `timeline.json`; the provenance sidecar does not enter the journal (same limitation as `cutRange` writing provenance; provenance reads associate by id, so display is not affected).
- Provenance: when `cutWords / cutRange` write `ai/cuts.json`, they add `via` (inferred server-side from the request header or caller: serve request → `app`, CLI → `cli` / `agent`).
- `DocDelta`: `doc.changed` already pushes `timeline` `put/remove`. The `timeline` projection of `GET /__ccut/doc` already includes `views[srcId].cuts` and `keptSpans` (the projection field is named `views`, while the file uses `sources`). Both ends recompute `CutMarks` from these, so no new field is needed.

## 7.2 Review: `Command::Review`

```rust
// ccut-protocol/src/command.rs
Command::Review { project: PathBuf, kind: String /* cleanup | broll | … */,
                  #[serde(flatten)] action: ReviewAction }
#[serde(tag = "action", rename_all = "kebab-case")]
pub enum ReviewAction { Accept { items: Vec<String> }, Dismiss { items: Vec<String> },
                        Restore { items: Vec<String> } /* dismissed → pending */,
                        AcceptAll, DismissAll { batch: Option<String> }, RestoreAll { batch: Option<String> } }
pub struct ReviewApplied { rev, doc_rev, seq: Option<u64>, applied: Vec<ReviewItemResult>, skipped: Vec<ReviewItemResult /* reason: already-cut | orphan-word | not-pending */>, review: Value /* file as written back */, can_undo, can_redo }
```

- `items` use v4's stable `id` (`sug-<n>`) instead of zero-based indexes. The CLI `ccut review accept --items` accepts both forms (a number = index, for compatibility with the skill docs).
- Kernel `dispatch_inner` new arm → `ccut_workspace::review::apply_review(project, history, kind, action)`: `ProjectLock` → read v4 (or upgrade v3) → `effective_state` for each item → items with `accept` go through `apply_cleanup_suggestions` (one journal entry, label `AI: cleanup`, `set_edit_group` in the same group) → write back the review file → return.
- argv projection: `review accept|reject|restore <project> <kind> [--items …] [--all] [--batch …]`. `ccut review reject` changes to per-item `dismiss` semantics (without `--items` = `DismissAll`).
- serve endpoints (register in `serve_contract.rs` + `router.rs` dispatch + `contract_tests.rs::KERNEL_API_CALL_SITES`):
  - `project.reviews`: `GET /<id>/__ccut/reviews` → `Query::Reviews {project}` → input to `AiReview::parse_list` (the files for all kinds).
  - `project.review-apply`: `POST /<id>/__ccut/review/apply` → `Command::Review`.
- `SPEC_VERSION` 1.58.0 → 1.59.0 (new Command/Query variants, minor). Add one line to the `version.rs` changelog, regenerate `docs/generated/*`, hand-sync `docs/design/cli/ccut-cli-server-reference.md`, and add `review` usage to `skills/cuccut/references/editing.md`. The `requireSpec` range `>=1.31,<2.0` does not need to change.

## 7.3 Write-path switch for App v2

`apps/cuccut/src/app/editor/review_bars.rs::resolve_review` and `app/mod.rs::refresh_reviews` change from `engine::review::list` plus a subprocess to `Kernel::query(Query::Reviews)` / `Kernel::dispatch(Command::Review)`. Receipts go through the existing `AppStore` receipt channel (`app/mod.rs:393`). The subprocess path is deleted, with no dual write left behind.

## 7.4 Undo

| Action | Write | Undo mechanism |
|---|---|---|
| Cut selection / restore a range / restore all | one journal entry in `timeline.json` | Editor ⌘Z = `history undo`; the toast undo covers the same source |
| Accept one / accept all | `timeline.json` + `ai/cuts.json` (sidecar in the same transaction as the timeline) + review file | ⌘Z reverts the timeline; review items are derived back to `pending` per C4, so no second undo is needed |
| Dismiss one / dismiss all | review file only | Summary-bar toast “已忽略这一条建议 · 撤销” (“Ignored this suggestion · Undo”) = `Review::Restore {items}`; not in the journal, and does not take a ⌘Z slot (prototype divergence D-C2) |
| Task receipt (review-type cleanup) | — | Undo = `DismissAll {batch}`; redo = `RestoreAll {batch}`. `task_undo` for `review.cleanup` tasks reads the review file instead of the journal. State = whether any `pending` items remain under that batch (`Undoable` ↔ yes; `Undone` ↔ all dismissed; all accepted → `Hidden`) |
| Task receipt (directly applied cleanup) | `timeline.json` (`AI: cleanup`) | Unchanged |

## 7.5 Cross-client sync

- Web and App under the same serve: `timeline` changes go through `doc.changed`. Review file changes are pushed by the kernel as one **`Event::ReviewChanged {project, kind}`** frame when `Command::Review` or a cleanup task finishes. The `Event` enum carries `#[serde(other)] Unknown`, so old clients ignore it; this is still a minor change. The WS `doc` channel is reused; no new channel is opened.
- External process (`ccut cleanup --review` does not go through the kernel): handled the same way as today's external edits to `timeline.json`. App v2's file-layer watcher (`reload_banner`) already covers `ai/reviews/`, and Web re-fetches `GET /__ccut/reviews` when the task-completion frame arrives.
