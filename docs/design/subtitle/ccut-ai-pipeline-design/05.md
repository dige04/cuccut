# 5. Stage 1: Polish (polish)

> From [ccut AI pipeline technical design for transcript post-processing (polish / paragraphing / chaptering / translation / subtitle alignment)](../ccut-ai-pipeline-design.md)

## 5.0 Before pagination: speaker attribution repair (speaker-repair)

polish treats ⏹ (speaker change) as a **hard guarantee**: a sentence may not cross it, and a paragraph break must always occur there. So as long as `words[].sp` is still wrong (diarization assigns the “的” in “打 DOTA 什么 | 的 | 就是宿舍…” (roughly “what did you play, DOTA or something, | the | that's the dorm…”) to the other speaker, or moves the switch point a few words earlier or later), the main polish is forced to treat “的” as a standalone sentence and add punctuation. In the UI this shows up as two speakers alternating word by word. The repair must happen before pagination, and it must give polish a legal channel that can change `sp`. `sp` is not part of any fingerprint, so changing it does not trigger a stage re-run. There are two steps. Both change only `sp` and never the text, and their accounting goes into the envelope `speakerRepair`:

1. **`rowRealign`** (deterministic, no LLM; applies only to the row-level authoritative engine, i.e. the MOSS project): see §4.3.
2. **`wave`** (LLM, `kind = "speaker-repair"`, `engines/speaker_repair.rs`):
   - Gate: runs only when `speaker_turns(words).len() > 1`. A single speaker makes zero calls (`skipped: single-speaker`). Targeted re-polish with `--paragraphs` skips it (`scoped-run`). `--no-speaker-repair` turns it off (`disabled`).
   - Candidates are selected deterministically by the engine from timing and shape, **regardless of whether punctuation is present**. Punctuation chunking in raw ASR is unstable, so “no sentence-final punctuation before the word” is only a negative signal. Two kinds are selected: sandwiched short islands (a turn of ≤4 words and ≤1.2 s with the same speaker on both sides) and unnatural switch points (a gap under 0.25 s with no sentence-final punctuation on the preceding word). An island whose text, with punctuation stripped, falls entirely within the acknowledgment whitelist (嗯/哦/对/OK/是的/对吧… meaning “mm / oh / yeah / OK / yes / right?”; “啊/呃” (“ah / uh”) is deliberately excluded) is kept as-is and not sent to the model. In a measured 7-hour multi-speaker interview, there were 577 sandwiched islands among 1911 turns, and the whitelist blocks about 530 of them. There were 153 unnatural switch points. Each candidate gets a synthetic window with 40 words of context on each side (merged, ≤240 words). Each call handles ≤8 windows.
   - **Index contract** (same idea as segment-repair / seam-repair; without it, there is no anchor point for changing text): the payload for each window is `<<<WINDOW k | n lines | speakers S1,S2 | current: 1-13 S1, 14-14 S2, 15-31 S1>>>`, then **one word (one CJK character) per line** as `N| word` (a word is followed by the ⏸ pause marker), then `<<<WINDOW-END>>>`. The answer for each window returns only `start-end label` ranges. Validation is pure arithmetic: ranges start at 1, are contiguous, and run to the last line; each label ∈ the `speakers` in the block header; and after merging adjacent same-label ranges, **the segment count must be ≤ the current segment count**. So the model can only fold fragments back into a neighbour or move existing switch points, and cannot invent new speaker changes out of nothing. One contract covers both shapes, “folding a fragment back” and “moving a boundary a few words”. A violation is marked `range-invalid`, which rejects only that window. A second round is sent with `retry_reason`, up to 2 rounds in total. If the retries run out, or the transport fails, the window is left unchanged, which is exactly the same as not doing repair.
   - Application: windows do not overlap. Each window's ranges are written to `doc.words[].sp` one window at a time. Before landing, a further deterministic change cap applies: if a single window changes more than 12 words in total, or any contiguous changed run exceeds 8 words or 2.5 s, the whole window is ignored (`windowsCapped`). “Segment count does not increase” does not stop wholesale re-attribution. In practice, flash assigned a 38-word guest quote at the start of the episode to the narrator. Afterwards `speaker_turns` is re-derived, so the paginator and the main polish see clean turns. For envelope fields, see the CLI reference `ccut polish`.
   - **Measured** (Xie Saining 7-hour interview, rebuilt from raw MOSS rows, deepseek-v4-flash, typo/term/punct/filler/wordy): `rowRealign` had 0 mismatches (the row-level authoritative build). Candidates were 738 islands (the whitelist caught 616) plus 423 unnatural switch points, giving 267 windows over 34 calls, with 0 rejections. The first run, with 266 windows, confirmed the status quo, but 1 window assigned the 38-word guest quote at the start to the narrator. That is why the cap was added. After adding the cap, a re-run confirmed 266, 1 window changed 2 words (the “跟的” false start was returned to its speaker), and 0 were blocked by the cap. At the screenshot spot, 「当时打什么游戏？ | 呃，很多啊，打 DOTA 啊什么的，…一个经历。 对。 | 哦，所以…」 (“what game were you playing back then? | uh, lots, DOTA and stuff, …an experience. right. | oh, so…”) is attributed correctly. Across the whole piece there is not a single word-by-word speaker swap on 「啊，/的，/吗？」 (filler words “ah,” “de,” and “ma?”). The remaining short sandwiched turns are all real acknowledgments or overlaps that MOSS's row-level judgment identified (美金, 优雅, STORYTELLING).

## 5.1 LLM contract: plain text in, sentence strings out

This is the key decision voice-ink settled on only at M28, and it is inherited directly. **Abandon** the “sparse mapping with word indices” contract, because the model's failure rate when maintaining indices was too high. Instead:

- **Input**: one page of plain text. Between words, soft markers are injected for pauses: `⏸` (≥0.6 s) / `⏸⏸` (≥1.0 s) / `⏸⏸⏸` (≥1.8 s). A speaker change injects `⏹`, and a sentence **never** crosses it. In multi-speaker documents, `⏹` carries a **stable speaker label**: `⏹S2` means everything to the right, up to the next `⏹`, is spoken by S2. The label is the digits from the `sN`-form id; a non-canonical id falls back to the sequence number of its first appearance. The same speaker has the same label on every page of the whole document, and labels contain no timing. Markers and labels go only into the payload copy as metadata and are forbidden in the output. On the return side, `markers::strip_markers` strips the labels along with the markers, and a bare `⏹` is also recognized for compatibility.
- **Output**: `{"paragraphs": [{"sentences": ["…", "…"]}]}`, the corrected sentence strings grouped by paragraph. **There are no index or time fields at all.**
- **Task** (four items in the prompt): ① fix explicit recognition errors (spelling, homophones and near-homophones, with special emphasis on Chinese and Japanese). **Forbidden**: rewriting, summarising, adding or removing content, or translating. ② Add punctuation. ③ Split sentences by meaning. ④ Group adjacent sentences by topic into paragraphs of 1–4 sentences.
- **Coverage constraint**: the sentences, concatenated, must **cover the input exactly once, in order**. This is the premise that the later deterministic mapping relies on, and it is the first gate of validation.

## 5.2 Document brief (brief / analysis)

Before polish, run one full-text analysis. Long documents run it per page. For a single page, it is **merged into one call with polish** to save a round trip. For multiple pages, each page's extraction runs in parallel. **The glossary is a deterministic union computed by the engine**: `Source` is grouped by lowercase with whitespace and ASCII punctuation removed; the spelling is the majority form; Category is the mode; Note is the longest; Variants are the union. Losing spellings are folded into Variants, and likewise kept only if they literally appear in the full text. The model only serially writes one overall summary. Its input is each page's `# Summary`, and its answer is an empty-table context document. If retries are exhausted and the output still cannot be parsed, it falls back to the longest per-page summary, so a failed summary does not sink the whole analysis round:

```jsonc
// ai/<media>/brief.json
{ "fingerprint": "…",
  "referenceFingerprint": "…",              // fingerprint of the project/source metadata reference block
  "summary": "…",                          // content overview; injected into the system prompt of every later stage
  "terms": [ { "term": "CucCut", "note": "product name",
               "observedVariants": ["宝卡特", "包卡"] } ],   // term lock
  "namedEntities": ["…"] }
```

**Table parsing has two levels (`ParseMode`)**. The hand-written user file `ai/context.md` uses `Strict`: any structural or value defect fails the parse, and the caller keeps the previous validated context. A half-table never overwrites it. Model answers always go through `Model` (the “code fixes first” rule of §10.2). Problems that code can resolve do not trigger a retry:

- Multiple rows for the same `Source` (after normalisation by the merge key) ⇒ merge them (Variants union, Note the longest, Category the first seen), and record a `duplicate-id` warning.
- Column count ≠ 6 ⇒ extra middle columns are folded back into `Note`, and missing columns get defaults. Only a row with 1 column or an empty `Source` is dropped. Unknown `Category` ⇒ `other`. Invalid `Lock`/`Origin` ⇒ downgraded (model rows are downgraded anyway).
- The header is matched loosely on the first cell `Source` (trimmed, case-insensitive). A file without frontmatter but with a glossary is accepted as usual, and the engine stamps the fingerprint.
- Junk rows are filtered deterministically. A `Source` that is a single CJK character, pure punctuation, pure digits, or an acknowledgment or filler word is dropped (reusing the speaker-repair whitelist).
- Row limits: each page keeps its first 150 rows. After the full text is merged, 400 rows are kept, sorted by the number of cross-page occurrences in descending order, with ties broken by first appearance. Output still follows first-appearance order. The excess is only logged as a warning and counted as dropped (`termsDropped`).
- **Page-fatal errors are now only two kinds**: the input exceeds the hard size cap (§10.2), or there is neither a `# Canonical Terms` section nor any table row to be found. When per-page retries are exhausted, the error **is no longer raised**. As long as at least one page succeeds, the glossary is merged from the successful pages, and failed pages are counted in `pagesFailed`. Only if every page fails is `Err` returned, and the host keeps the old context.

The prompt is tightened accordingly. `Source` is limited to “proper nouns, person names, products, technical terms, and foreign words mixed in that ASR is likely to misrecognise”. Common vocabulary and filler words are explicitly forbidden. There are at most 80 lines per page, and each `Source` gets only one line.

The glossary lock enters the polish prompt as a “known correct spellings” list. Similar-sounding or misspelled forms are always corrected to the canonical form. Also, before the similarity check (§5.5), term variants are replaced with opaque tokens, so that “correcting a wrong spelling to the correct term” is not misjudged as tampering. The brief also serves as the glossary for the translation stage (§8.2).

When running analysis and polish, the project title and description in `project.json`, and `media.sourceMetadata` (source title, description, channel, publish date, platform, video ID, URL), are also read. The description is injected after being truncated by character count, so it does not crowd out the body text. This block is a strong reference for spelling, personal names, and proper nouns. It is not dictated content or an absolute source of facts, and it must not be used to add words or sentences to the transcript. The reference block has its own fingerprint, so a metadata change invalidates the old brief cache.

## 5.3 Pagination and carry-over

- Pagination uniformly uses `atomize::word_count`: Latin text is counted by words, CJK by characters, and attached punctuation is not counted separately.
- **Page count is fixed first, and page boundaries are balanced** (shared by all stages that paginate by words). Page count = `ceil(total words / (budget + slack))`, where slack is 10% of the budget. When the total only slightly exceeds N pages' worth of budget, no extra page is cut just for the tail. Then the target for each page is “remaining words / remaining pages”, so earlier pages come out slightly short and later pages make up the difference automatically. This avoids a greedy fill that leaves a tiny last page. For example, with a budget of 6000 and a full text of 24200, the result is 4 pages of about 6050 each, not the 6000×4+200 layout of the 3-pages-of-8000 era. The remaining page count is also guarded by `ceil(remaining words / (budget + slack))`. When earlier breakpoints fall early and the shortfall accumulates, it is better to add a page than to let the last page exceed the “budget + one slack” limit.
- The nominal page budget for analysis and standalone segment is 8000 words each. file-v1 polish uses a separate 2200-word editable core (the page target is recomputed page by page after the balancing above), with at most 200 words / 3 sentences of read-only context on each side. It allows a 15% overflow that snaps to the next natural breakpoint.
- Breakpoint selection: within the last 20% of the page-target window, take the highest score from a joint score of “word position + rank×(page target/20)”. Rank is **speaker change (3) > long pause (2) > sentence-final punctuation (1) > none (0)**. Each step up in rank is worth only about 5% of the page target in advance. So a higher-rank breakpoint cannot veto a more balanced lower-rank breakpoint near the tail of the window. Measured on a real word stream, pure rank priority let one early pause block all the later sentence-final breakpoints, leaving the first page underloaded and the last page 15%+ overloaded. Ties go to the later one.
- **Turn-aware pagination (the polish pagination unit when speaker information is present)**: when the word stream contains two or more distinct `sp` values, the polish pagination unit is raised from “word stream plus breakpoint scoring” to the **turn sequence**, where a turn is a maximal contiguous run of words with the same `sp`. A page is a union of whole consecutive turns. The page boundary is the turn start, within the +15% overflow limit, whose word cost is **closest to the page target** (ties go to the later one). Short turns (dialogue, Q&A) naturally group together. Only a turn that by itself **exceeds the page budget** is split internally. In that case **sentence boundaries take priority** (sentence-final punctuation). Only if the window has no sentence boundary does it fall back to the rank scoring above, and if that also finds nothing, it cuts hard. When the turn boundary closest to the page target cannot reach the window's lower bound (0.8× page target), the next turn alone exceeds the budget. A single “嗯” (filler, “mm”) is not given its own page. Instead, the page boundary falls at a sentence boundary inside that long turn, so this page = the short turns plus the head of the long turn. Page seams therefore fall only at turn boundaries or at sentence boundaries inside a long turn. They no longer split a person's speech mid-way, and there are fewer boundary oscillations of the kind where an early pause blocks a sentence-final breakpoint. The word budget and page count are entirely unchanged. **Documents without speaker information (a single `sp` for the whole piece) do not enter the turn path**, but since 2026-08 they likewise **prefer sentence boundaries**: if the window contains sentence-final punctuation, take the highest-scoring sentence boundary, and only if there is none does it fall back to pauses. Measured on a single-speaker long talk (a 7-hour interview with speakers flattened), 30 of 47 page seams fell mid-sentence, because a 0.6 s hesitation pause at rank 2 always beat the rank-1 sentence-final punctuation in the window. After sentence-first ordering, 8 remain, all in stretches with no punctuation at all. The overflow zone likewise reaches for sentence boundaries first and then for pauses. file-v1 polish runs all pages in parallel with no carry-over, and right context is supplied by the read-only zone. **Page seams are not paragraph evidence.** A hard page cut's two sides are merged unconditionally by the engine, while a blank line at the start of the next page is an explicit “start a new paragraph” signal. Other page seams are judged by `seam-repair` after the polish wave: the tail window of page k's last paragraph and the head window of page k+1's first paragraph are sent together, with line numbers and one sentence per line. The answer returns only a line-number range, only the two ends of a range spanning the seam are accepted, and a rejection keeps the paragraph pin (see file contract design §6.2/§6.8). A carrier with carry-over (segment) still uses the last segment as its unit. Since a paragraph never crosses a speaker change, that is equivalent to the last turn. Inside a long turn, it falls back to the last segment.
- **Carry-over** (segment carrier; the file contract for polish does not use it, because it would drag the page waves from 2 min in parallel to 13 min in series. Seam judgment is instead done by the parallel seam-repair): the last paragraph of each page is not committed. It is re-sent together with the next page's payload, so the model sees right context and re-decides the boundary. **A paragraph is never split at a page seam.** An overlong tail has a snowball guard: beyond 600 characters, it is forcibly committed and split. **The guard also applies to a tail consisting of only one sentence.** The model occasionally returns a whole page as a single sentence. If such a tail kept being carried, the next payload would restart from the top of the previous page, doubling each time. This was measured on p1215: 30k → 106k characters, finally landing as a single 2615s, 40k-character sentence record.

## 5.4 Mapping back to word spans: atom-LCS

After the sentence strings are received, rebuild the word ranges deterministically:

```
1. Source side: atomize each word on the page (CJK one character per atom, Latin per word) → source key sequence srcKeys
2. Output side: flatten the sentence list, atomize it the same way → outKeys
3. LCS(srcKeys, outKeys); match rate < 0.7 ⇒ this attempt fails and the whole page is retried
   (the threshold is lower than the 0.75 used in the segmentation stage, because polishing necessarily changes the text)
4. Anchor each sentence to the last source word it matches → cut the word spans in order; unmatched trailing source words are merged into the last sentence
5. Boundary refinement: each adjacent boundary is probed by moving within a ±10-word window; a move is accepted only if "neither side gets worse and at least one side gets better",
   and it must not break speaker consistency
```

## 5.5 Applying: rebind keeps ids and times

Write the revised sentence text back into the word spans via `rebind` (`ccut-flow-core/src/rebind.rs`,
ported from voice-ink `TranscriptRebinding` + `SubAlign.rebindCorrected`):

- Strip the common prefix and suffix, then run a word-level LCS only on the changed middle section;
- **Words matched by the LCS are kept as they are**: id, t0 and t1 are not touched at all;
- Unmatched new tokens create new words (`w…` ids), and their times are interpolated by character weight within the gap (punctuation gets no time share, and every token is guaranteed one share; `Camelot → came a lot` deterministically occupies the original word window in a 4:1:3 ratio);
  the **`sp` of a new token is inherited from its LCS neighbours** (previous kept word > next kept word > fallback `span[0]`;
  on the degenerate path where the LCS table exceeds its limit, take the speaker with the most words in the range). Sentence ranges sometimes cross speakers (when a ⏹ forced boundary cannot be moved, the degenerate case snaps to the sentence start, or the range starts with a filler word such as 「呃」 (“uh”) that the model deleted from the other speaker's utterance). Before 2026-08, `span[0].sp` was always used, so every character that had punctuation added to it across the whole S2 sentence (the new tokens 「啊，」 (“ah,”), 「的，」 (“-de,”), 「吗？」 (“ma?”)) was tagged S1, and the UI alternated the two speakers character by character;
- CJK text is re-segmented on source word boundaries before rebind, so unchanged characters keep their original ids and times;
- Before the final rebind, CJK-dominant source text passes through an idempotent AutoCorrect: normalise CJK/Latin spacing, safe full-width punctuation, full-width letters and digits, and the casing of technical terms;
- At the end, everything goes through `normalized_word_timings`.
- After all rebinds for the whole-page polish are done, `word_timing_repair` runs once more. When the local original word window is narrower than the centisecond minimum for the new tokens, the repairer expands into the neighbouring healthy windows, so that `t0` is non-decreasing and nothing overlaps. It then cleans up orphaned keys in `breaks` / `paraBreaks` / `hidden` by the new word ids and refreshes the layout fingerprint. The sentence record's `t0/t1` take the repaired word times, so the audit artifact does not diverge from the body text.

**This is the foundation of the incremental system:** a small-scope polish changes only the ids of the words it touched,
so the segmentation (keyed by id) does not go stale, and translation (keyed by group text fingerprint) only invalidates the groups that were touched.

## 5.6 Validation, degradation and artifacts

- **Per-sentence span cap (after mapping, does not reject the page):** if any mapped sentence's **source word span** exceeds 1200 characters
  (`MAX_SENTENCE_SOURCE_CHARS`, i.e. `span_chars` = Σ word surface + 1, counted the same way as `MAX_CARRY_CHARS`) or 300 seconds, or if a corrected single sentence exceeds the capacity of one segment (Latin 300 words / CJK 500 characters, since `segment-repair` can only insert blank lines between sentences and a single over-capacity sentence has no safe cut seam), the sentence is marked **oversized**. LCS match rate and similarity both give high scores to a page that is returned unchanged, so this check is the only one that detects that case. The thresholds come from the real corpus distribution (the longest single-sentence source span was about 412 characters / 27 seconds) and existing constants; they block only pathological cases and leave normal long sentences alone. **An oversized sentence no longer fails the whole-page attempt.** (The old rule rejected the whole page with `document-oversize`, then retried and fell back. In one real incident, p014 at 1652 characters and p042 at 1822 characters, both long unpunctuated sentences from the same speaker, were returned unchanged on three consecutive retries, so the whole page ended up reverted to the original text. The old 900-character corrected “re-split” also only respected existing full stops and never created boundaries, and it has been removed.) The main wave **accepts the body on the first round**, and oversized sentences are cut after the wave by the `punct-repair` step, which adds punctuation in a targeted way (see below). Body text and segmentation responsibilities are thereby separated: polish segmentation only has to "add sentence punctuation along the way" and no longer relies on rejecting pages to force the model to break sentences;
- **Targeted punctuation repair `punct-repair` (after the wave, before segment repair):** the engine gathers the sentences that are still oversized in the final accepted set, packs them across pages, and wraps each sentence in a pair of fences, `<<<SENTENCE-BEGIN id=sNN min-sentences=K>>>` / `<<<SENTENCE-END id=sNN>>>`. The body projects source pauses into soft hints `⏸` / `⏸⏸` / `⏸⏸⏸` via atom-LCS, where `K` = ⌈sentence word count / (segment capacity / 2)⌉ ≥ 2. The pages are then re-split with a 2200-word budget, and when worker slots are available the page count is raised to the slot count (at least one sentence per page) so that concurrency is filled. The prompt differs from polishing: **the only permitted change is adding sentence-final punctuation** (`.?!` / `。？！`). Non-punctuation characters are reproduced verbatim, with no typo fixes and no rewording, and entries do not interfere with one another. Each sentence is checked individually (`parse_punct_repair_page`; the agent's `task submit` mirrors the same lint and engine implementation): missing or unpaired fence ids ⇒ `missing-id`; word surface rewritten, added, or removed (the atom sequence differs after removing punctuation) ⇒ `source-drift`; no sentence-final punctuation added at all ⇒ `sentence-oversize`; conflicting adjacent punctuation such as `。，` is **normalised in code first** (recording a `punctuation-normalized` warning, without rejecting the sentence); a dangling false sentence end ⇒ `surface-artifact`. Sentences that pass are sliced along the new sentence boundaries, each slice is mapped back to source words with atom-LCS and `heal_boundaries` is applied (a mapping failure also counts as `sentence-oversize`, and the sentence is kept as it was). A slice that is still oversized simply "goes to the next round". **A round is a retry:** `PUNCT_REPAIR_MAX_ROUNDS = 3`. From round 2 onward, the request carries `attempt = round` and `retry_reason = "[sentence-oversize] sNN: <previous round's feedback>; …"` (a rejected sentence's Problem is `[code] detail`; a slice still oversized after splitting carries the note "still oversized after the previous round's split (reason): please keep adding sentence-final punctuation where the meaning completes"). Page ids are `pr{round}-{serial:03}`, and a retryable transport error only means that round got no answer. **Once the rounds are exhausted, the engine splits sentences deterministically on the source timeline**, guaranteeing that no oversized sentence leaves the stage. Candidate cut points are scored: speaker change (5) > existing sentence-final punctuation (4) > pause ≥ 1.8 s (3) > pause of 0.6–1.8 s where the corrected text falls after a comma or semicolon (2) > either a pause or a comma (1). Within the word-count window [capacity/5, capacity·4/5] (also bounded by the hard limits of 1200 characters / 300 seconds), the highest score wins and ties go to the later point. The left slice has its trailing comma removed and then gets `。` / `.` appended according to language. The process loops over each slice until none is oversized. The counts are reported as `punctRepairedSentences` (split by the model), `punctSplitSentences` (split by the engine fallback) and `oversizedSentences` (still oversized after both; this should always be 0);
- **Fence recovery `recover_fences` (before locating):** in measured runs, of 7 cases of “missing fences”, 5 were only a missing `<<<EDIT-END>>>` while `<<<CONTEXT-AFTER>>>` was still there, 1 was a missing CONTEXT-AFTER, and 1 was a missing EDIT-BEGIN. **The core region was intact in every case.** So recovery first infers from neighbouring fences: if EDIT-END is missing but CONTEXT-AFTER is present, the latter is taken as the end of the core region and the read-only trailing context is treated as empty; if CONTEXT-AFTER is missing, the core region closes at EDIT-END; if EDIT-BEGIN is missing but CONTEXT-BEFORE is present, scan after the latter and strip the prefix whose normalised similarity to the payload's read-only leading context is ≥ 0.85. If that prefix cannot be stripped, the failure is page-fatal. For duplicated fences, the first valid ordered group is taken. Each recovery action records a `fence-recovered` warning. If both EDIT fences are missing and cannot be inferred ⇒ `document-truncated` (page-fatal);
- **Drift in the read-only regions is always advisory:** parsing takes only the core region, and read-only regions in the output are never written back as the source of truth. The core region is separately guarded by an independent word-stream truth gate. Surface-level incidental fixes and whole-block truncation now record only `content-ignored` warnings;
- **Prompt and mirror lint:** the file-v1 contract states explicitly that “line breaks and blank lines do not end a sentence”, and states the limits of 1200 characters / 300 seconds per sentence. It also says that an oversized sentence is sent back for one `punct-repair` round (adding sentence punctuation along the way saves that round). The submit mirror lint still rejects newly introduced illegal control characters in an answer, to prevent UTF-8 mojibake such as `ã\u{80}\u{82}` from being silently stripped to plain letters by generic cleaning, where it would only surface after engine mapping as an oversized sentence. Conflicting adjacent punctuation such as `。，` / `，。` / `，，` / `..` is now **normalised in code** (the strong sentence-end punctuation wins, recording `punctuation-normalized`). A dangling false sentence end, and suspected English run-ons of 20+ letters inside Chinese body text (such as `purereinforcementlearning`), are now recorded per paragraph as `surface-artifact` warnings. They **no longer reject the page**: after mapping to sentences they enter the sentence-level queue of `polish-retry`. The mirror lint therefore also no longer marks a whole answer `rejected` because of one surface blemish in one sentence;
- **Similarity check (does not reject the page):** a low-similarity sentence is a **unit-level** failure and goes directly into the sentence-level retry queue. The old rule, “more than 30% of sentences failed the gate ⇒ whole-page `source-drift`”, has been removed (in a two-sentence page, one sentence was enough to reject the whole page and re-roll all of its sentences). Page-level `source-drift` now covers only atom-LCS mapping failures (coverage < 0.7 / no mappable sentence / LCS table too large);
- **Sentence-level retry wave `polish-retry` (json-v0, in waves):** candidates = low-similarity sentences ∪ `surface-artifact` sentences. The payload is still
  `{"sentences":[{"startWordIndex":…,"reason":…,"originalWords":…,"previousAttempt":…,
  "contextBefore":…,"contextAfter":…}]}` (with a new `reason ∈ {low-similarity,
  surface-artifact}`). It is paginated at ≤40 sentences per page, each sentence is checked individually, and a failed sentence gets a targeted `retry_reason` opinion in round 2. **A round is a retry; there are 2 rounds in total.** When the retries are exhausted, the outcome depends on the reason: `low-similarity` sentences revert to the original words (`fallback: true`, counted as `fallbackSentences`); `surface-artifact` sentences **keep the model's text** and are counted as `surfaceArtifactSentences`. The characters and words themselves are correct, and reverting to the original would only swap one surface blemish for a whole unpolished sentence. The `polish-false-sentence-end` and `polish-surface-artifact` warnings from `ccut check` continue as the backstop;
- **Hard per-page atom capacity (before a page is sent):** the answer is mapped back to source words with atom-LCS (`lcs.rs`). Middle sections up to 25 million cells use the full-table backtrace (the historical path, whose result is bit-identical to voice-ink). Larger ones use linear-space Hirschberg, with a total cell time limit of 250 million (about 15.8k × 15.8k atoms). Anything above that returns `None`, and the engine reports `atom-LCS table too large` (retryable, since the answer is much longer than the page). Chinese has one atom per character. In 1.0.9, pages were cut at 12000 characters, producing a page of 10111 atoms, while the old limit of 25 million cells (√ ≈ 5000) rejected the table before any comparison. **Any answer fails the map-back, including a byte-identical zero-change answer.** The engine treated it as a wrong model answer, retried three times, and then fell back on the whole page (491 of 627 sentences reverted to the original text, while `check` still reported ready). Now the paginator and the validator use the same measure: `polish_page_atom_capacity()` = √cap / 2 (the answer may be twice the source length). The default budget gives a worst-case page of about 2800 atoms, well within that limit. Any planned page whose core region exceeds the capacity in atoms is terminated with `Terminal` **before the LLM is called** (`polish page pNNN too large: N source atoms exceed the validator capacity (M)`); the page is not sent and not retried. The diff fallback layer of the segment engine benefits from the same capacity;
- **Degradation ladder (rejection narrows the scope):** two whole-page attempts (the second carries the problems as feedback) → a page that still fails with page-fatal is re-planned by `plan_polish_pages` into two pages by bisecting the **core word range** (the same paginator, under the same context budget, with cut points still falling on sentence, pause and speaker boundaries). Each half is sent once (counted as `splitRetryPages`) → a **half-page** that still fails falls back to punctuation or 30-word splitting, keeping the original words (counted as `fallbackPages`) → sentence-level `polish-retry` waves (2 rounds) → sentences that still do not pass are handled by the disposition above. The total number of calls is of the same order as the old “whole page ×3”, but the fallback granularity is halved;
  an oversized sentence (source span > 1200 characters / 300 seconds, or a corrected sentence exceeding the single-segment capacity) **does not count as a page failure**. The body is accepted on the first round; after the wave, `punct-repair` adds punctuation in a targeted way (at most 3 rounds), and when that is exhausted the sentence is split deterministically on the source timeline. This step must come before segment repair, because segment repair can only insert seams between sentences;
  an over-long segment (more than 300 words / 500 CJK characters) **does not count as a page failure either**. The body is accepted on the first round. After the wave, the segments still over the limit are packed across pages and go through the `segment-repair` index contract (one block per segment, `<<<BLOCK k | n sentences | c words | at least m paragraphs>>>` / `<<<BLOCK-END>>>`, one sentence per numbered line, the answer returns only line-number ranges `a-b`, each block is checked individually, the blocks are re-paginated, at most 3 rounds). Multi-sentence paragraphs still over the limit after exhaustion are closed deterministically by the engine using inter-sentence pause levels (`fallbackParagraphs`), so no over-long multi-sentence paragraph remains in the output and the segment stamp is still applied. When the model gives a legal range but a sub-segment is still over the limit, an overflow of up to 15% is split immediately by the engine by pause level (without spending another round just for pure capacity convergence). Larger overflows carry a feedback note "still N words" into the next round so the model splits them by meaning. An illegal range (`range-invalid`) or a single returned range (`paragraph-oversize`) is retried under the usual rules;
  in multi-speaker documents, short interjections such as 「嗯。」 (“mm.”) and 「哦。」 (“oh.”) that sit between utterances of the same speaker each become their own paragraph. This follows from the Para derivation rule in spec §18.5 (a speaker change always starts a new paragraph) and is not a segmentation defect (in a measured 7-hour interview, 1284 of 1965 paragraphs). The successful polish envelope reports these with `shortInterjectionParagraphs` (≤10 characters and ≤3 s) so the UI can fold or inline them. **The derivation is not changed and nothing is merged** (decision of 2026-08);
- **Artifact** `ai/<media>/polish.json`: sentence records (`firstWordId/lastWordId/t0/t1`) plus
  per-change suggestions `{cat: "typo"|"punct", find, replace, firstWordId, lastWordId}`
  (equal after normalisation ⇒ `punct`). The suggestion list is for review in the GUI/CLI. Applying or not applying them does not affect the timeline;
- **False sentence-end warning:** after polish runs, `ccut check` emits `polish-false-sentence-end`. This flags sentence-final punctuation that falls on a dangling conjunction or preposition (`… because.` / `… of how.` / `And.`). Such false sentence ends derive pointless, predicate-less short Sentences and pass the noise on to translate/align batches. The criterion is `seam::dangling_sentence_end`: first confirm that the text ends with sentence-final punctuation, then strip the punctuation and closers and look at the last content word. It applies only to languages it can judge (en / zh) and reuses align's dangling-word list without extending it. A legal stranded preposition after a fronted English wh-object (such as `what it reaches out to`) is not reported. A complete Chinese sentence ending in 「的」 (such as “是的。” (“Yes, it is.”) or “这是很重要的。” (“This is very important.”)) is not reported. Only an isolated fragment 「的。」 is still reported. Sentence endings that already form complete words, such as `方向` (“direction”), `对比` (“compare”), `总和` (“sum”) and the A-not-A question `跟不跟` (“follow or not”), are exempt too. The display seam keeps using the original strict `ends_dangling` criterion and is not affected by these whole-sentence exemptions.
  **It emits only a warning; it does not enter `next[]`, and the engine does not reject.** The criterion is heuristic, and a targeted re-polish rewrites the surface words and leaves existing translations mismatched, so it should not sit in the automatically executable position. `fix` offers `ccut polish <project> --paragraphs <p-…>` for a human to decide;
- **Surface artifact warning:** after polish, `ccut check` also scans for conflicting adjacent punctuation, and for single Latin atoms of 20+ letters in Chinese code-switching. On a hit it emits the warning `polish-surface-artifact`, with the sentence, the paragraph, and the same targeted polish `fix`. This is the delivery-side backstop of the commit mirror lint: artifacts written by old projects or old runners can also be found, and a strict gate will not mark something ready just because word count and width statistics look normal;
- **Fallback sentence blocking:** a whole-page fallback and a single-sentence keep-original-words both record their accounting only as `fallback: true` on each sentence in the artifact. `stages.polish` is still stamped and `polish=fresh`, but a fallback does not mean "polish complete", only "these sentences were not polished". `ccut check` reads `ai/polish.json` with the same fingerprint as `stages.polish`. Any record marked `fallback` whose two end words still exist is reported as a **blocker** `polish-fallback` (regardless of `--for/--lang`; `--strict` only affects the exit code). `fix` = `ccut polish <project> --paragraphs <p-…>` (the paragraph containing the fallback sentence), and it is added to `next[]`. A fingerprint mismatch in the artifact (pending review acceptance, or a stale leftover) or a record whose sentence has been deleted expires silently. The envelope field `data.fallbackSentences` is project-wide: `fallbackPages` is now the number of **pages or half-pages** that fell back in this round, and `splitRetryPages` is the number of half-pages resent after bisection;
- **Commit:** `stages.polish = fingerprint(words)`. If the transcript was never segmented before, paragraph pins are also derived from the polish paragraph grouping, written to `paraBreaks`, and `stages.segment` is stamped (one LLM call feeds two stages);
- **Balanced break layout:** once punctuation is final, if the transcript has no `breaks` coverage yet (no manual or historical layout intervention), the deterministic layout optimiser runs (`ccut-flow-core::layout`, cross-checked against the M51b/M54 designs prototypes). It derives according to §18.5, then uses a “window with display padding + target-language CPS ceiling” to find cues that cannot be read in time (orphaned short tails from overflow, speech-rate spikes at pause breaks). It prefers moving seams and merges when necessary, then commits the result as a **minimal set of break pins** written to `breaks`, and refreshes `stages.asrLayout` (layout changes made by the pipeline itself do not count as manual edits). If a pin set already exists, the whole step is skipped and never overrides user intent.

Parameters: `temperature 0.2`, 3 retries × 2s backoff, 1s between pages, serial (carry-over dependency).

## 5.7 Final polish: speaker real-name inference (speaker-names)

Diarization only produces voice ids such as `s1`/`s2`, so the three UIs have been showing `S01`/`S02` placeholder names. The deterministic heuristic in `speaker::propose_names` only recognises **self-introductions** (`my name is …` / `我是…`, "I am…"). In interviews, podcasts and panel discussions, though, most real names are given by **the other party** ("today I'm joined by Andrew Ng", "有请张三" — "please welcome Zhang San"), or appear only in the title and description. That evidence has no sentence pattern to match, so the heuristic always comes back empty. This wave (`kind = "speaker-names"`, `engines/speaker_names.rs`) hands the job to the model. It is on by default, and `--no-speaker-names` turns it off.

- **Position: last step of polish** (after the text has been `apply`'d to disk and all the waves above have run):
  ① speaker-repair rewrites `words[].sp` and may absorb a spurious cluster entirely, so naming first would attach a name to a speaker who no longer has any words; ② only the polished text has punctuation, and third-party introductions ("欢迎 Andrew Ng。" — "Welcome, Andrew Ng.") are much easier to read than raw ASR. Putting it in analysis does not work either: when the `ai/context.md` fingerprint is fresh, the whole analysis is skipped, and the naming wave would disappear along with it.
- **The only edit surface is `speakers[<id>].name`.** Neither `sp` nor `speakers[].name` enters the stage fingerprint, so renaming does not make polish / segment / translate / align stale. This wave is therefore safe for projects that are already translated (re-running polish, however, is not).
- Gates: `--no-speaker-names` (`disabled`), empty word stream (`no-words`), scoped re-polish via `--paragraphs` (`scoped-run`), and no placeholder speakers (`no-placeholders`). A speaker is "to be named" if the name is still a placeholder **and** `doc.words` still contains words for that speaker.
- Evidence payload (file-v1 `text/plain`): an `<<<OPENING | n words | speakers S1,S2>>>` opening window (400 words, with ⏹/⏸ markers), plus, for each speaker whose first appearance falls outside the opening, a block `<<<SPEAKER S2 | first speaks around hh:mm:ss | n words>>>` (first 60 words + last 120 words; introductions usually come from **the other party**, so the preceding context matters more than what follows), plus a `<<<NAMES-ASK>>>` table of pending labels. The system prompt additionally carries the project/source metadata and the named entities from analysis, since full names often appear only in the title.
- Answer: inside `<<<NAMES>>>` … `<<<NAMES-END>>>`, one `S1 = Andrew Ng` per line; if the evidence is insufficient, answer `?`. Validation is entirely string-level: the label set must **exactly equal** the set the payload asked about, with no duplicates, names non-empty, at most 40 characters, containing no `=`, and not themselves placeholder names. If any check fails, the whole answer is unusable (this wave makes only one call, and writing half the names is worse than resending once). A second round is sent with `retry_reason`, for at most 2 rounds; when the rounds run out, the placeholder names are kept (`rejected`).
- Write-back: label → id **must** go through `SpeakerLabels::speaker_for_label`. A label equals its number only when all ids are clean `s<digits>` and the numbers are pairwise distinct; otherwise it falls back to first-appearance order, because `format!("s{n}")` would silently mix up speakers. Before writing, the placeholder check is **run again**, so a speaker the user renamed in the meantime is never overwritten.
- Accounting goes into the envelope and into `speakerNames.wave` in `report.json`: `skipped? / targets / calls / proposed / named / unknown / rejected / names[]`. `speakerNames.candidates` is still the deterministic output of `propose_names` (kept for manual review, not applied automatically).
- `--review`: the candidate full `TranscriptDoc` (including the `speakers` table) is staged, and on accept the whole document is written back, so the real names land together with the candidate. Conversely, names edited by hand before accept are overwritten by the candidate.
