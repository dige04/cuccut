# 11. Open Questions and Risks

> From [CucCut edit-domain protocol design (Cut / Clip / element / watermark / project export)](../ccut-edit-domain-design.md)

1. ~~**Closed set of element kinds**: the first release has `text/image/video/audio`; the usage of the legacy `shape / sticker(template·asset·waveform) / motion` kinds is to be confirmed with product before they join the set (sticker-asset can first migrate as image)~~ → **Settled** (EF P0, `ccutTimeline 0.2`, see [ccut-element-render-foundation-design.md](../../bcf/ccut-element-render-foundation-design.md) and format spec §19): the four kinds `shape / sticker(template·asset) / visualizer / progress` are promoted to formal kinds; the waveform subtype is retired and migrated to the top-level `visualizer`; motion remains deferred. `ccut element add --kind` has not yet been extended to the four new kinds (they go through `addElement` in `timeline apply`). Extending the set is additive evolution and does not break the schema.
2. **Polishing / segmentation / chapters for attached sources**: the translation pipeline is settled by §4.2 (timeline-projection assembly + scatter write-back + visible-word fingerprint). Whether polishing / segmentation / chapters should likewise run across sources via timeline projection, or still operate per single source, is to be scheduled separately (leaning toward the former, as it is isomorphic with translation).
3. ~~**Numeric-anchor elements and structural changes**: cut/restore, clip splitting and reordering change the timeline length; numeric-anchor elements keep their coordinates fixed (content moves beneath them). Whether to offer an optional ripple semantics for `timeline/apply` awaits the editor interaction design~~ → **Settled** (2026-09-28, CLI `specVersion` 1.283.0, [clip editing gaps plan §2.1](../ccut-agent-editing-gaps-plan.md)): any write that changes the projection makes elements follow the clock; this is not optional. A video element named under a clip receives the remaining source interval; other numeric-time elements are converted by "old output moment → source moment → new output moment", and those spanning a cut are only shortened, never leaving a hole. `clip move` carries along only the elements lying entirely within that clip; word anchors and elements without an end point do not move. The rules and receipts are in [BCF §19.1](../../bcf/cuccut-format-spec/19.md) "Elements follow the clock"; the reference implementation is `ccut_timeline::follow_clock`.
4. **Burn-in performance**: multi-stream decoding + per-frame overlay compositing is wired up; the release baseline for long 4K films still needs continuous measurement on target machines. The fallback is pre-rendered overlay sequences per interval (same-kernel output), with no render-degradation option.
5. **CapCut version drift**: draft fields in later CapCut 9.x versions may change; the mechanism of clean-room templates + draft lint + a version allowlist is retained, and new versions will be calibrated against real installs and appended.
6. **`clip.rate` speed change**: the field is reserved; before opening writes, the display of word-anchor mapping under speed change and round-trip tests against CapCut `speed` segments must be resolved first.
7. **Studio Web editing UI** (registered in the 2026-08-02 audit): the `timeline/apply` endpoint and projection are ready; the front end only has playback jump-skipping and translation routing. The clip track and cut / split / reorder interactions are entirely absent. Under the multi-surface sync obligation this is the largest surface asymmetry (the designs/ prototypes and the Mac app both have an editing surface). Since 2026-09-07, the plan for talking-head editing (word-selection cutting in the script, item-by-item AI suggestion review, cut-point markers on the timeline) and its App v2 landing are in [`ccut-talking-head-cut-design.md`](../../editor/ccut-talking-head-cut-design.md).
8. **Mac fine-grained ops and cross-source playback consolidation** (updated 2026-08-09): OUTPUT ↔ source seek, playback-clock readback, source cut jump-skipping and in-point switching for clips on the same media already consume `TimelineMapping.swift`; the remaining work is switching the AVPlayer media when a clip boundary crosses `srcId`. The write path still needs to move from `replaceTimeline` to the fine-grained ops of §5.3 (regaining per-item base validation and skipped semantics); soft-delete write-back still needs to generate `sources[].cuts` entries rather than removing the clip.
9. **§4.3 BCF compile bridge**: burn-in and transitions currently implement sampling on their own (kept consistent with preview via fixture cross-checks); the architectural constraint of "consuming the BCF expansion" has not yet landed. The timing of landing is to be scheduled together with `export --to bcf`.
10. **Golden byte-freezing of project exports**: the six targets are currently structural-assertion regressions, so formatting or attribute-order drift has no backstop; byte-freezing fixtures should be added before release-candidate acceptance.
