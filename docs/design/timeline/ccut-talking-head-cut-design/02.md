## 2.1 Media-layer lossless cut (done, v0.5)

- `core/crates/ccut-timeline/src/schema.rs`: `Source.cuts: Vec<Cut>`, `Cut {id, t0, t1, ref}`, source-clock seconds, half-open intervals; the top-level `sources / clips / tracks / main / template` are closed (`additionalProperties: false`).
- `core/crates/ccut-timeline/src/cuts.rs`: `CutSet::new` validates ordered, non-overlapping cuts; `word_is_cut(t0, t1)` is the only "word is cut" check in the whole repo (word midpoint falls in `[t0, t1)`); `view_time / source_time(bias) / kept_spans / kept_intersections`; `insert_cut` merges within `CUT_MERGE_GAP = 0.02` and keeps the earlier id; `restore_cut`.
- `core/crates/ccut-timeline/src/words.rs`: `resolve_word_span(words, first, last, duration, fps, pad_pre, pad_post)`: 0.05s breath padding, frame-grid expansion, **never crosses adjacent visible words** (skips `hidden`), errors on empty range.
- `core/crates/ccut-timeline/src/map.rs`: `TimelineProjection::clamp_source_event(src, t0, t1, MIN_EVENT_DURATION)` projects a source range onto one or more timeline segments, breaking where it crosses already-cut spans.
- `core/crates/ccut-workspace/src/timeline/ops.rs`: `cutRange` (:177), `cutWords` (:220), `restoreCut` (:285); `apply_cleanup_suggestions` (:825) runs `mutate_timeline(project, "cleanup accept", "AI: cleanup", …)` with `insert_cut` + `record_cut_provenance` per item; `detect_words` (:958, skips `hidden`), `cleanup_detect_proposals` (:1065), `make_detect_options` (:971). The closed enum for `cut list --kind` is at :926 (`silence | filler | badTake | manual | match`).
- `ai/cuts.json`: append-only provenance, `entries[] {id, kind, t0, t1, srcId, reason, detail, origin: detect|cleanup|manual|match, at, wordIds?, afterWord?}` + `params` + `fingerprint`; `restore` does not delete entries. This is an **open** sidecar; adding fields does not need a dataVersion.

## 2.2 Detectors and cleanup flow

- `core/crates/ccut-timeline/src/detect.rs`: `detect_silences` (threshold 0.8, compressed to 0.3 / 0.4 at sentence end, `max_gap` 3.0, across chapters not cut unless `trim_chapter_starts`), `detect_fillers` (`EN_HARD / EN_SOFT / ZH_HARD = [呃 (er), 额 (e)] / ZH_SOFT = [那个 (that), 这个 (this), 就是 (just), 然后呢 (and then), 对吧 (right), 你知道吧 (you know), 反正 (anyway), 其实 (actually)]`; soft words need punctuation isolation), `merge_proposals` (badTake swallows the filler it covers), `skip_already_cut`. **“嗯” (um) is not in any word list.**
- `core/crates/ccut-flow-core/src/engines/cleanup.rs`: `PAGE_BUDGET 6000`. The LLM sees only the in-page index / text / speaker / `pauseBefore` / `alreadyCut`, and returns `{"cuts":[{a, b, cat: retake|falseStart|filler, alt?, reason}]}`. `validate_page` and `lint_agent_answer` mirror five guards (in-page, category, filler ≤ 6 words, no crossing speakers, no intersection with already-cut ranges); the artifact is `CleanupArtifact {fingerprint, strength, suggestions[] {firstWordId, lastWordId, category, alternative?, reason, t0, t1}}`.
- `core/crates/ccut-engine/src/flows/cleanup.rs`: `run_cleanup_cmd` local + LLM → `merge_proposals` → writes `ai/cleanup.json`; `--review` → `stage_action_review_locked`, otherwise directly `apply_cleanup_suggestions`; `changed = ["ai.cleanup", "review.cleanup"|"timeline.cuts"]`, `next = ccut review accept <proj> cleanup`.
- The flags of the two entry points are asymmetric: `ccut cut detect --no-pauses` vs `ccut cleanup --no-silences`; `cleanup` has no `--max-gap` (it goes through the hard-coded defaults of `make_detect_options`).
- Note that the `filler` check in `polish` is **destructive** (it deletes words from `words[]` via rebind, `engines/polish.rs:785`); talking-head cutting must not reuse it.

## 2.3 Review transaction

`core/crates/ccut-workspace/src/review.rs`: `ACTION_REVIEW_VERSION = 3`; `<proj>/ai/reviews/cleanup.json` = `{reviewVersion, kind, status: pending|accepted|rejected, baseTranscriptSha, baseTimelineSha, createdAt, updatedAt, summary: {suggestions}, artifact}`; `accept_action_review` (:801) validates both shas, **if either changes, the whole review is rejected**; `--items` is zero-based indexing; on success, `status: accepted` + `applied[]`; `reject` voids the whole review. There is no protocol `Command`, only the CLI `ccut review accept|reject`.

## 2.4 Write path, undo and protocol

- `core/crates/ccut-workspace/src/apply.rs::apply_timeline`: `ProjectLock` → `preflight_versions` → `history.sync_from_disk` → `capture_external` → `timeline_revision` CAS (409 stale) → per-op → `TimelineProjection::build` lint → sidecars → `atomic_write` → `record_edit` → `refresh()` → `staleTranslations` scan. Visibility-changing ops already include `cutRange / cutWords / restoreCut`.
- `core/crates/ccut-workspace/src/history.rs`: the journal stores **groups** on two stacks (`group` id), `set_edit_group` / `new_group_id`; if any file in a group is changed externally, the whole group is rejected.
- `core/crates/ccut-editor-core/src/task_undo.rs`: receipt undo is derived **only** from `AI: <kind>` entries in the journal; `--review` mode does not write the timeline, so today review-type cleanup receipts have no undo slot.
- `core/crates/ccut-protocol`: `EditChannel::Timeline {ops}` is an untyped JSON op, so `cutWords` needs no new variant; `SPEC_VERSION = "1.58.0"` (`version.rs:112`); a new `Command` variant = minor bump; WS has only the `doc` / `agent` channels, and `doc.changed` carries `DocDelta` (four ops: `set / unset / put / remove`).
- Two gates in `core/crates/ccut-serve/src/contract_tests.rs`: endpoint table ↔ `router.rs` dispatch set must be equal; new handlers may only go through the envelope via `Kernel::dispatch/query`, and `(file, variant)` must be registered in `KERNEL_API_CALL_SITES`.

## 2.5 Review UI already in `ccut-editor-core` and App v2

- `core/crates/ccut-editor-core/src/review.rs`: `CutProposal {kind silence|filler|badTake, reason, detail, t0, t1, removed_sec, word_ids, early_ids, late_ids, can_flip, keep_later}`, `CutReview {items, filter, cursor}` and `visible / current / stats_text / step / toggle_current / item_for_word / span_menu_text / flip_item / accepted_indices`, `cut_review_word_sets(review, words) -> (cut, kept)`, `cut_review_from_suggestions(json)` (retake / falseStart → badTake), `resolve_command_args`.
- `apps/cuccut/src/app/editor/review_bars.rs`: a port of the Mac `CutReviewBarView`: stats + filter + previous / next + Keep / Cut + flip + Dismiss all + Apply cuts ⌘↵; `resolve_review` launches a **`ccut review accept` subprocess**.
- `apps/cuccut/src/app/editor/timeline/cutseg.rs`: the cut segments `.cutseg` on the Video track; draws only `EditorState::cut_review` (pending suggestions; the `accepted` bit decides appearance), sharing one state with the review bar.
- `apps/cuccut/src/app/editor/lists/transcript.rs`: line 1072 `cut_review_word_sets` draws suggestion underlines; line 1082 `edits::cut_word_ids(&editor.derived.cuts, &words)` draws already-cut underlines.
- `apps/cuccut/src/app/editor/mod.rs:1093`: `refresh_reviews` reads from disk directly via `engine::review::list` → `AiReview::parse_list`.
- There is only one load point: `app/editor/entry.rs:332 write_content` hands `pending_cleanup` to `cut_review` when the project opens as `Ptype::Clean` (only the `Entry::Clean` layout in `entry_mode.rs:214` opens `cut_review / cut_segments`). After "find again" from the AI tool card at any time, there is no second load path.
- `lists/transcript.rs:1452 render_body` already has word-level hit testing (`layout.index_for_position` → `word_index_at_byte_offset`) and word-anchored popovers (`word_anchor_rect`); what is missing is the press-move-release **range accumulation** and the multi-word highlight style.
- Two existing defects / limitations (this plan fixes them in passing and records them):
  - **`cutseg.rs` uses the wrong clock**: `prep.scale` is built on `editor.duration` (the timeline clock, `EditorState::content_end()`, kernel `TimelineDoc::content_end`; detached documents look only at element end, see [product-design §12.0](../../product/product-design/12.md#120-三种文档形态与统一口径2026-09-16)), yet it directly calls `scale.x(proposal.t0)` to draw source-clock suggestion ranges; after the first cut, all subsequent suggestion segments drift left. §5.4 switches to `clamp_source_event`.
  - **gpui cannot draw dashed underlines**: `UnderlineStyle` has only thickness / color / wavy; the file header records "equivalent to a 1pt solid line in the same color". See §8.4 D-C7.

The already-correct pattern in the tree: `lists/subtitle.rs::toggle_cut` wraps `edits::cut_range_op / restore_cut_op` into `Mutation::Timeline` and goes through `commit_labeled`, one history entry per gesture; `review_bars.rs::apply_cuts`, however, bypasses `EditorState::commit` to launch a subprocess. Manual cut and restore in cut mode follow the former.

In short, App v2 already has a Mac-style review of "one set of suggestions, accept all or Dismiss all, batch-written on Apply"; the prototype's cut mode (round 192) is its **superior replacement**: same state source, but with per-item persistence, coexisting with manual cuts, plus a summary bar + underline menu + floating toolbar.

## 2.6 Web

- `features/editor/panes/transcript/TranscriptPane.tsx`: the render unit is the **paragraph** (one `EditableText` per paragraph); sub-paragraph decorations are all UTF-16 character ranges (`shades / ms / cur`); there are no word `span`s and no word-level hit testing. `transcript.logic.ts:58 LeanCue` deliberately strips `words` before crossing the wasm boundary (§P.10.13); `activeWordId` (:148) is the only place in the whole Web that reads `cues[].words`: the data is on the client, but it is not projected or drawn.
- `features/editor/timeline/rows/ClipsRow.tsx` draws only a 2px seam at cuts; the overlay in `TrackArea.tsx` has only snap lines and `Playhead` (the only per-frame `Clock` subscriber, ADR-W07), with no range highlight or label layer. `ClipsRow`'s filmstrip and cue projection already correctly go through `timelineToSource / projectTimedItems`; the clock is correct.
- `state/timeline.ts` has only `splitClipOp / removeClipOp / removeElementOp / elementSpanOp`; wasm already exports `cutRangeOp / restoreCutOp / cutWordIds` (`ccut_wasm_editor.d.ts:264/268/298`) but there is no atom wrapper.
- `DocOverlay` in `state/optimistic.ts` has no cut key (only `elements` touches `timeline.tracks`), so optimistic underlines have nowhere to land.
- `panes/aitools/aitools.logic.ts:29` has a `clean` tool card (`kind: 'cleanup', view: 'flow', undo: true`) that can start a task, but `summaryOf / blockedReason / buildOptions` have no `clean` branch; the receipt has no consumer. The wasm `entryLayout` already provides a `cutReview` slot (`misc.rs:294`), and the wizard has the `entry.toast.cut_suggestions` copy, but nothing consumes them.
- None of the serve `__ccut` routes includes `review`; `GET /__ccut/jobs/<id>/artifact` is open only to export jobs. Today Web cannot get suggestions and has no accept path.
- `ccut-editor-core::review` and `subtitle_list::word_ranges` (byte ranges) / `transcript_list::word_index_at_byte_offset` have no wasm exports.
