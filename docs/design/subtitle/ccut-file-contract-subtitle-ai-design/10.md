# 10. Error Classification, Retry Accounting and Degradation Ladder

> From [CucCut File-Contract Subtitle AI Pipeline Design (File-Contract Pipeline, v0.3)](../ccut-file-contract-subtitle-ai-design.md)

## 10.1 Error Code Table

`ProblemCode` (17 codes) is the **only layer** that enters retry accounting and the **only layer** fed back to the model/worker. Each Problem carries a `scope` (`Document` / `Page{id}` / `Sentence{id}` / `Paragraph{index}`), and the repair scope is determined by the scope.

| Code | Meaning | Repair scope |
|---|---|---|
| `document-truncated` | Output not closed / only half a page | Current page (and check max_tokens) |
| `document-wrapped` | Multiple fences / extra explanation mixed in | Current page (stripping a single fence costs nothing and is not counted) |
| `document-oversize` | Output size exceeds the **hard cap** estimated from the input (the runaway-generation guard of §16: `max_output_chars` = **8×** input characters, floor 4096; raised from 4× in 2026-08. The guard only judges whether the payload is still worth parsing; a long but structurally complete answer is left to each kind's unit-level rules for deduplication/truncation) | Reject the whole document. The four carriers (align table / translate HTML / polish txt / context md) all pass through `guard_output_size` before parsing; if the limit is exceeded, nothing is parsed and this attempt is voided. **Note**: the sentence-level quality gate of polish has moved out of this code. Conflicting adjacent punctuation is now normalized by code, and dangling false sentence-ends and Chinese text glued to 20+ letters of English are now `surface-artifact` (2026-08 retry strategy redesign). A single-sentence source span exceeding the snowball, or a corrected single sentence exceeding paragraph capacity, goes through `sentence-oversize` (§6.7). |
| `source-drift` | Polish substantially rewrote the source / align changed the source | Minimal change window / Sentence |
| `missing-id` / `empty-translation` | Missing sentence / empty translation | Sentence (aggregated repair wave) |
| `duplicate-id` | Same id appears multiple times | Current page |
| `unknown-id` | Extra id | Ignore + advisory |
| `paragraph-move` | Sentence moved to another paragraph | Current page |
| `frozen-modified` | Frozen sentence modified | Current page; never overwrite |
| `glossary-missing` | Locked term translation missing | Sentence |
| `align-content-drift` | Alignment concatenation drift (including a reordered rewrite magnitude out of bounds) | Sentence (targeted round) |
| `align-over-hard` | Cut fragment still exceeds hard | Sentence (targeted round). **Under the file contract, does not block acceptance of this batch**; see §8.4 |
| `align-illegal-seam` | Seam violates the `seam.rs` criteria | Sentence (targeted round); same as above, advisory |
| `context-invalid` | `context.md` / `context.<lang>.md` structure invalid: missing frontmatter, missing `# Canonical Terms`, header mismatch, unknown `Category`, illegal `Lock`/`Origin`, illegal `tone` | **Reject the whole document and keep the previous verified context** (the enforcement point of §5.1 "never overwrite with an empty table"). Unknown categories / illegal enum values additionally carry a Sentence scope pointing to the offending line |
| `sentence-oversize` | Overlong sentence (single-sentence source span > 1200 characters / 300 seconds, or corrected text exceeds single-paragraph capacity): in the `punct-repair` answer, the sentence is echoed verbatim without any sentence-final punctuation added, or the newly added punctuation cannot split it into ≥ 2 pieces / cannot be mapped back to source words (§6.7). The main polish page does not report this code; an overlong sentence is accepted on the first round, with targeted punctuation repair after the wave | That sentence (scope `Sentence{id}`, id being the `sNN` within the payload). The detail is the targeted instruction for the next round, fed back via `retry_reason` / `problems`. Other sentences in the same payload are unaffected. Pieces still overlong after splitting do not report this code and only go to the next round. Round limit `PUNCT_REPAIR_MAX_ROUNDS = 3`; after exhaustion the engine deterministically splits the sentence along the source timeline |
| `paragraph-oversize` | In a `segment-repair` index-contract answer, a block returned only one range while the whole block exceeds the limit (§6.6). The main polish page no longer reports this code; an overlong paragraph is accepted on the first round, with targeted paragraph splitting after the wave | That block (scope `Paragraph{index}`, index being the block order within the payload). The detail is the targeted instruction for the next round (including the minimum paragraph count), fed back via `retry_reason` / `problems`. Other blocks in the same payload are unaffected. Sub-groups still over the limit after splitting do not report this code and only go to the next round. Round limit `SEGMENT_REPAIR_MAX_ROUNDS = 3`; after exhaustion the engine deterministically closes out by pause level (§6.6) |
| `surface-artifact` | Surface-level flaws: dangling false sentence-end (`当。` / `because.`), and a suspected English glue of 20+ letters inside a single Chinese-body atom (conflicting adjacent punctuation is already normalized by code and does not enter this code). **Never rejects a page**: the main polish page only records a Warning of the same name per paragraph; `punct-repair` records a Problem per sentence | That sentence (scope `Sentence{id}` / `Paragraph{index}`). After the main wave is mapped to sentences, it enters the sentence-level supplementary queue of `polish-retry` (`reason = surface-artifact`, ≤2 rounds). When exhausted, **the model text is kept** and counted in `surfaceArtifactSentences`. The `polish-false-sentence-end` / `polish-surface-artifact` warnings of `ccut check` continue as the backstop |
| `range-invalid` | The line-range in a `segment-repair` / `seam-repair` / `speaker-repair` index-contract answer is illegal: missing block, no range, not starting at 1, not contiguous end to end, not covering the last line, or out of bounds. speaker-repair additionally includes a label not among the window's speakers, or more segments than the current state (§6.6/§6.8/§6.9) | That block (scope `Paragraph{index}`). The detail locates the first defect and is the targeted instruction for the next round. Other blocks in the same payload land as usual. A rejected seam-repair block ⇒ keep the original paragraph pin. A rejected speaker-repair window ⇒ keep the original attribution |

**Five supplements relative to v0.2 (implementation decisions):** `document-oversize` and `context-invalid` (M1–M4), `paragraph-oversize`, `sentence-oversize` and `range-invalid` (2026-08). The first is the step where the last rule of §16, the "output size hard cap", was turned from a principle into an error code. The second is that v0.2 §10 only targeted the page-level editing stage and missed structural validation of the `context*.md` path. analysis and translate-brief also failed and also needed a code that could be accounted for. The third is the gap exposed by the paragraph-degradation incident (§6.1): "zero paragraphs were validated, but one paragraph run-on was not validated". It first landed as "whole-page retry + forgiveness on the last round", then changed to "accept on the first round + `segment-repair` targeted paragraph splitting" (§6.6), and this code is only reported in the splitting carrier. The splitting carrier was then changed to an index contract (§6.6): the answer only returns line-number ranges, and the contract has no place for rewritten text, so `source-drift` no longer appears in splitting. In its place the fifth code, `range-invalid`, is accounted per block (scope `Paragraph{index}`): missing, non-contiguous, or non-covering ranges reject that block, and other blocks in the same payload are accepted as usual. The fourth is the gap exposed by the overlong-sentence incident (§6.4): "rejecting the page forces the model to break sentences, which is ineffective". Single-sentence over-limit changed from whole-page rejection under `document-oversize` to "accept on the first round + `punct-repair` targeted punctuation addition + engine deterministic sentence splitting" (§6.7). This code is only reported in the punctuation-repair carrier; `source-drift` / `missing-id` are accounted per sentence in `punct-repair` (scope `Sentence{id}`).

`WarningCode` (19 codes) only goes into observability. It consumes no retry budget and does not change the acceptance verdict, so it is not given a separate table: `wrapper-stripped` (single outer fence stripped at zero cost), `control-stripped`, `blank-lines-collapsed` (≥3 consecutive newlines collapsed, §6.1), `marker-residue` (residual `⏸` stripped), `node-dropped` (non-whitelisted nodes such as style/script dropped, §16), `attribute-dropped`, `sentinel-neutralized` (a literal fence in the body neutralized, §16 injection defense), `rowspan-mismatch` (`<th>` rowspan does not match the group's row count; a purely redundant check that does not veto data, §8.3), `content-ignored`, `boundary-forced` (cut point not on a word boundary, snapped to the nearest boundary, §8.4), `align-over-hard-uncuttable` (line fragment exceeds hard but the whole-sentence translation has no legal split; accepted at commit time and the engine hard-cuts mechanically, §8.4), `anchor-repaired` / `anchor-text-mismatch` (chapters anchor repaired from the opening fragment / fragment does not match the paragraph start), and the codes added by the 2026-08 retry strategy redesign: `duplicate-id` (same id / Source appears multiple times; the first is kept or they are merged), `row-repaired` (columns padded or merged back, illegal values downgraded, junk rows discarded), `fence-recovered` (sentinel fence inferred from adjacent fences), `punctuation-normalized` (conflicting adjacent punctuation normalized by code), `surface-artifact` (surface flaw, diagnostic record only), `frozen-ignored` (frozen sentence modified or moved; the model text was ignored). They are two channels independent of `Problem` (`manifest.pages[].problems` only carries `ProblemCode`), and they are **not fed back to the model and not part of retry criteria**.

## 10.2 Retry Principles

- **Do zero-cost recovery at the format layer first**: BOM, single outer fence, HTML entities, newline normalization. None of these consume any budget.
- **Account transport and content separately**: 429/5xx retries do not consume the content retry budget. The content budget is counted by the repair scope in §10.1 (page-level / sentence-level).
- **Deterministic fallbacks must be explicitly marked** and must not be disguised as model results.
- `Http{408,429,5xx}`/`Malformed` are retryable. `Terminal` (401/403/404) aborts the run. The artifact files of every attempt (`.a2` suffix) are all kept as records.

## 10.3 Ladder Summary

| Stage | Round-by-round ladder | Terminal guarantee |
|---|---|---|
| polish | Whole page ×3 → span-local ×2 → cut-point recovery → original-text fallback | Never loses characters; manual layout is never silently reflowed |
| translate | First wave → in-page repair wave → global residual wave (sentence budget: 3 times) | Missing translations stay blank: `translation-partial` warning / `translation-missing` blocker; never a fabricated translation |
| align | Round 1 → targeted round 2 → deterministic fallback | All sentences are either within hard or a blocker is reported; the fallback is explicitly marked |
