# 7. Stage 2: Translation (HTML contract)

> From [CucCut File-Contract Subtitle AI Pipeline Design (File-Contract Pipeline, v0.3)](../ccut-file-contract-subtitle-ai-design.md)

## 7.1 Rendering

`derive_sentences` + paragraph projection → sentence-level HTML. Structure: **`section` carries the paragraph, `p` carries the sentence.** (The `<p><div>` nesting in the original proposal is invalid HTML; the `<span>` inline approach is also dropped, because whitespace between inline elements is ambiguous and, when the model reflows a whole block, adjacent spans tend to merge. Block-level elements give a clear signal that each is an independent unit.)

```html
<article lang="en" data-target="zh"
         data-ccut-format="translation-source/1"
         data-project-fp="1024:g1.0:g88.4:ab12cd">
  <section id="p-g1.0" data-sp="S1">
    <p id="s-g1.0" data-budget="整句≤26字">Ninety days, eight times the growth.</p>
    <p id="s-g1.7" data-budget="整句≤17字">We did it without ads.</p>
  </section>
</article>
```

- The root node is a bare `<article>`. **Do not** wrap it in a full `<!doctype html><html><body>` document: that adds a fixed token overhead to every page, and it invites the model to add `<head>`/`<title>`. The `data-ccut-format` version marker is the anchor that puts the renderer version into the §9.5 cache key.
- Contains no timestamps. The speaker is attached to `<section>` via `data-sp` so the model can adjust tone; it is not required to be written back.
- All transcript text is written after HTML escaping (§16).
- **`data-budget` (length channel)**: a per-sentence reading budget, on the same basis as `maxChars` in json-v0: `floor(display duration × target-language cps)`. Counting is in **reading units**, the same basis as `target_cps_chars` (whitespace and ordinary commas/periods are free; for CJK target languages, Latin letters and digits count as about half a character). It is **not** the raw count of non-whitespace characters, which can never be satisfied for "a short sentence plus a required Latin locked term". For example, a budget of 11 cannot fit the 11-letter "description" in `data-rt`. As with the `data-budget` in the §8 align table, it **carries only a relative budget phrase, never seconds**; the unit switches between `字` and `字符` (both mean "characters") depending on the target language. It is attached **only to editable sentences**. Frozen sentences (§7.6) must be copied verbatim, and attaching a budget would only tempt the model to alter translations it should leave alone. The contract text also states that the deliverable is subtitles, along with a reverse guardrail: necessary length takes priority over compression, and causality, negation, numbers or proper nouns must never be deleted for the sake of compression. The per-line display cap varies by target language (CJK ≈16 cells, Latin ≈42 characters), so **only the nature of the constraint goes into the contract constant; concrete values always go through `data-budget`**. The parser ignores this attribute entirely: it does not take part in validation and is not reverse-parsed. `src.html` files in old task directories without `data-budget` are judged exactly as before.
  - **v0.3 incremental ruling**: when M1–M4 landed, this channel was left out during porting. Measurement showed file-v1 translation display width about 13% higher than json-v0, and translation-unsplittable rose from 1 sentence to 31. With this item filled in, the length constraint for file-v1 = the subtitle semantics in the contract + `data-budget`, and it still does not introduce the fused segment removed in §7.8.

## 7.2 Glossary first

Translation order is enforced: `context.md → context.<lang>.md → body`. The body page's contract inlines a summary plus the translated-name rows for the terms that hit this page. `Lock=yes` rows are compiled into `rt` for validation (§5.2).

## 7.3 Pagination and parallelism

- **Paginate by natural paragraph as whole blocks, with no redundancy.** `<section>` is atomic and is never split across pages. The page budget is 8000 source words; Latin is counted by word and CJK by character. Sentence count and worker slot count do not factor into pagination.
- Cross-page context is statically injected as HTML comments: `<!-- context-before: … -->`. The model is not required to output them.
- Pages have no dependencies between them and are dispatched in batch. Each page is parsed and written back on success.

## 7.4 Output parsing: symptom reconciliation table

Model output has the same structure as the HTML: no id may be missing or changed, and the content of `<p>` is the translation. The parser (html5ever, extracting by id) reconciles each item:

| Symptom | Error code | Handling |
|---|---|---|
| Missing sentence id | `missing-id` | Partially commit the sentences of this page that have arrived; missing sentences enter the repair wave |
| Unknown id | `unknown-id` | Ignore that node + advisory |
| Empty translation | `empty-translation` | Treated as a missing id |
| Duplicate id | `duplicate-id` | **This page is rejected without retry** (it cannot be determined which is the answer) |
| Paragraph id lost but sentence ids intact | — | Accept the sentence translations; paragraph membership follows the source structure |
| Tag changed to `div`/`span` but id present | — | Extract by id; tag names are not part of the protocol |
| Markdown fence or chatter before/after | `document-wrapped` | Take all nodes with sentence ids across the whole tree; a single outer fence is stripped at zero cost |
| Output truncated (trailing sentences consecutively missing + HTML not closed) | `document-truncated` | Retry this page, and check `max_tokens` calibration (§9.3) |
| Locked term missing | `glossary-missing` | That sentence enters the repair wave |
| Frozen sentence changed (§7.5) | `frozen-modified` | Page error; frozen sentences are never overwritten |

## 7.5 Retry waves and terminal states (sentence-level accounting)

Re-sending a whole page is wasteful, since sentences that already passed have been written to disk one by one. Accounting is uniformly per **Sentence, with a budget of 3 attempts per sentence** (the page's first response counts as one attempt):

1. **First wave**: all pages in parallel.
2. **Repair wave**: the failed sentences of each page are aggregated into a per-page repair mini-page (carrying structured problems).
3. **Residual wave**: all remaining failed sentences across the task are merged into one final residual batch.

After three attempts, if a sentence still has no translation: **leave it untranslated, never write a fake translation, and never copy the source text as the translation and then report success.** Terminal semantics are consistent with the current check: partially missing translations → `translation-partial` (warning, does not block the gate); entire language missing → `translation-missing` (blocker). **At the render layer, a missing sentence leaves the picture blank; there is no "fall back to source".** (`derive_trans_cues` produces no cue for untranslated sentences. In bilingual mode, burning only the source line works correctly as a two-line display in its own right; it is not a fallback.) Sentences that pass: CJK first goes through idempotent AutoCorrect → write `trans` + `transSrc` → `save_doc` checkpoint.

## 7.6 Incremental (stale-only)

The set to retranslate = `stale_sentences` (determined by `transSrc`, semantics unchanged) ∪ the provenance determination (§11.3). When rendering a stale-only page, render the whole paragraph as is to preserve context, and **keep the id of every sentence**. Non-stale sentences get `data-editable="false"` and their existing translation attached as a comment (read-only reference). The model must keep frozen sentences verbatim. The parser commits only editable sentences, and **any change to a frozen sentence is a page error** (`frozen-modified`); existing translations are never overwritten. (Keeping ids is what makes it possible to detect whether the model touched a sentence; an id-less bare-text scheme fails silently.)

## 7.7 timeline (multi-source routing)

The existing route id mechanism is kept: the HTML `id` uses a globally unique route id (current `r%06d` format), and the element additionally carries `data-source-id` and `data-sid`. The parser writes back dispersedly by the `(srcId, sentenceId)` pair (the persistence key is unchanged). A duplicate HTML id must never appear within the same document. `transSrc` remains the post-trim visible-word fingerprint.

## 7.8 Fused alignment draft: removed (changes the current default)

Fusion (translate also emits sourceBreaks drafts) is the path **enabled by default today** (the `--align many-to-one` default value). This plan removes it. It front-loads align complexity into the translation contract, and it compresses the translation page budget to 1000 words. Removal itself is the largest source of benefit in §1. Align only handles overlong sentences (§8), and call volume has already dropped substantially, so a pre-acceptance channel is no longer needed. **No `data-hint` backfill slot is kept**, because keeping it would preserve the possibility of pulling the page budget back.

**M1–M4 implementation ruling (overturned by the later deprecation execution)**: during the gray-release period, fusion was only "removed within the contract". **After the 2026-08 deprecation execution it was retired globally.** `TranslateOptions` no longer has an `align` field, the `TRANSLATE_FUSED_WORDS`/`TRANSLATE_WORDS` constants were deleted, and the page budget is fixed at `TRANSLATE_FILE_WORDS = 8000`. `--align-mode` only affects the alignment strategy of the align stage.
