# 9. Stage 5: display split and subtitle alignment (display split / align)

> From [ccut transcript post-processing AI pipeline technical design (polishing / segmentation / chaptering / translation / subtitle alignment)](../ccut-ai-pipeline-design.md)

## 9.1 Problem

Translation produces, sentence by sentence, a translation in natural target-language word order. A source Cue is just an independent line break in the original text. The LLM needs to **split the translation into lines** according to target-language semantics, then anchor each translated fragment back onto a contiguous range of source words. The word ranges provide semantic time anchors. Display boundaries may use the slack within a sentence and real silences to smooth transitions without overlapping adjacent subtitles, and they must not be locked to the old Cue boundaries.

**M8.2 (2026-08-17) removed the local alignment scorer**: `--align-scorer` / config `align.scorer`, together with the `reranker` / `hybrid` modes, were retired (based on [`core/fixtures/align/golden/REPORT.md`](../../core/fixtures/align/golden/REPORT.md) M8.1). The evidence source is always `llm`, which is the path described in this section. The three-round orchestration in §9.4 was retired along with it. For the historical design, see the [semantic scorer alignment plan](../../../archive/subtitle/ccut-semantic-reranker-alignment-design.md) (**archived**), §0 status box and §4–§6 (research record).

## 9.2 Approach: block alignment edges (default) / LLM segmentation + deterministic reconciliation (table carrier)

**Default carrier `align-edges/1` (aligned-block design §4/§6, `AlignCarrier::Edges`)**: the LLM does not split the source, does not split the translation, and does not resolve crossings. It only labels "translation semantic block → set of source word ordinals". Block merging, safe boundaries, bilingual DP and time allocation are all deterministic code in `align_block.rs`.

```
Input: one HTML table, with one <tbody data-sid> per sentence: td.src = in-sentence anchor words with [N] ordinals (one ordinal per word, same convention as TransAlign.words); td.tgt = the complete natural translation of the sentence;
       the system prompt carries only fit/soft/hard and locked terms (no seconds, no source Cues, no pause hints)
Output: the same table, with only td.tgt changed: <span data-src="4-7">因为我病了，</span>
       <span data-src="1 2 3">所以没去。</span> — minimal natural semantic blocks in the order of the translation itself; data-src lists source word ordinals (may be out of order, non-contiguous, or empty), and each ordinal appears in at most one block per sentence
Validation (string-level, filepipe/align_edges.rs, shared by the engine and submit-time lint):
       ordinals must parse and be ≤ the source word count (align-edge-ordinal); no duplicates across blocks (same); the span texts concatenated and normalised must == the translation (align-edge-text); missing, truncated or duplicate-id sentences are handled as in the table carrier; a tgt without span is only warned about and treated as "no alignment edges"
Block kernel (deterministic, align_block.rs): block → soft edges (weight 0.75) + AnchorAligner hard edges (numbers / dates / URLs / verbatim Latin / bilingual terms) → safe boundary (leftMax < rightMin) → minimal monotone blocks → bilingual DP (blocks are atomic; a piece = union of contiguous blocks; target layout + source layout + shared time window + seams on both sides)
Decision: Aligned ⇒ write correspondence:block + blocks[];
      if a block > hard ⇒ align-rewrite/1 rewrite round (same table shape, <tbody data-over-hard="chunk 1
      (words 1-9): 27 units > hard 20">; the model gives, in one response, the whole sentence rewritten in source-clause order, plus span annotations. Acceptance: ±max(25%,4) reading-unit guardrail; numeric / URL / Latin / term hard anchors and locked terms must not be lost; target AutoCorrect; edges→blocks→DP is re-run on the rewritten text and must come out Aligned ⇒ write transDisplay{basis:"monotonic-rewrite"} + text_basis:display;
      otherwise whole-sentence alignment; the rewrite round has no repair);
      insufficient evidence / DP has no solution ⇒ correspondence:sentence, the whole sentence as one block (advisory)
Rounds: first-round batch call (page id b…) → failed sentences share one global repair (r…, retryReason restates the per-sentence problems) → rewrite round (w…) → when the repair budget is exhausted: first try block alignment with pure AnchorAligner edges, which is kept only if Aligned; otherwise a deterministic target-language split fallback (fallback_sentences)
Incremental: display-stale (trans has changed) first deletes the stale transDisplay and its display baseline entry; existing entries are validated against their baseline text according to text_basis (align_entry_valid_for_lang)
```

**Review/repair carrier `align-table/1` (`--align-carrier table`, `AlignCarrier::Table`)**: keeps the original two-column split table protocol, as follows. There are two semantic changes. When the model self-reports `data-crossing`, it no longer writes `crossing:true`; it writes `correspondence: sentence` instead (the whole sentence as one block, one piece). A `data-reordered` rewrite no longer writes back to `trans`; it writes `transDisplay{basis:"table-reorder"}` and the entry's `text_basis: display`.

```
Input: the source word-atom sequence for one sentence (including pause hints) + the full translation of that sentence
      + target-driven lengthPlan (the number of pieces is determined only by the reading needs of the translation; the source-side length is only a suggestion)
      + sourceBreakCandidates
      + deterministic draftSource / draftTarget / draftWidths / draftSeconds / draftReady
      + draftWorstSourceUnits / draftWorstSourceSeconds (the width and time window of the worst paired source line in the entry draft. If an answer makes the worst source line, which still exceeds its band, even worse, engine acceptance and submit-time lint both reject it, so a targeted repair round must not net regress. Older task directories that lack these two fields do not trigger this check)
      + draftBlockers (per-item reasons for ready=false: piece over hard / single-source-word piece / fragmentary source piece / risky or blocked source seam /
        suspected intra-word split / over-fit piece at a seam / unfinished Chinese quantity phrase / conditional lower bound on piece count /
        bilingual source lines too dense where the target has natural seams / blocking-level seam lint. The worker only fixes the seams that are named; it need not blindly rewrite the whole sentence)
      + data-target-frozen (appears when the fused target piece has already been accepted but source anchoring failed; target piece boundaries may not change)
      + sourceWordUnits (submit-time and provider acceptance recompute source-line density by the same rule)
      + sourceWordEndsSec (cumulative end seconds of each source word relative to the sentence start, rounded to 0.1s. Custom cut points use it to estimate each piece's speech window, to avoid long translations being crammed into sub-second source pieces. Omitted when all timestamps are zero)
Output: when the draft qualifies, {"key":"…","useDraft":true}
      or {"key":"…","sourceBreaks":["b…"],"target":"… | …"}
      (when word order crosses, prefer "reordered":true. The worker has language ability itself and reorders the translation's clauses directly, without changing its meaning, to remove the crossing; after acceptance the sentence-level trans is written back as the source of truth. Only when reordering is also unnatural, use "crossing":true to record TransAlign.crossing in the database. The two flags are mutually exclusive)
      —— the LLM only reviews semantic boundaries; source word ranges are recovered from candidate ids; the source text is not retyped
Validation (deterministic): concatenation of pieces == the full translation (after normalisation). For reordered sentences, each piece is instead run through target-language formatting and a length-band guardrail of ±max(25%, 4 units); anything outside the band is rejected as a rewrite. Reordering may only adjust word order and add necessary connectives / particles, not compress or drop content. Word ranges must be contiguous, non-overlapping and fully covering. Each target piece's projected reading units must not exceed hard (an absolute ceiling, with no exception for crossings). Seam lint (dangling connectives / clinging particles / dangling tail of attributive “的” (complete words such as 目的 and 标的 are exempt) / unfinished Chinese quantity or category phrase / numbers and unit classifiers spanning a seam / mergeable enumeration-comma (、) coordination splits / mergeable Chinese pieces of 3 characters or fewer) and dangling source articles, modifiers and relative words all block retry. Ordinary risky source cut points block only when there is no clause seam at the same boundary; a weak bound-phrase detection at a seam may pass. `blocked`, and mismatches of bilingual term anchors, are always hard failures that neither pauses, seams nor draft sources can override (the provider and the Agent submit lint follow the same rules). `pieceCount.min` is usually advisory, but it blocks when the actual piece count is below min and some piece still reaches fit (`data-target-frozen` sentences are exempt: the translation pieces are frozen and no more cuts can be added, and both validators skip this check). Soft+1..hard preferred seams, and source-piece length imbalances caused solely by natural word-order crossings, remain advisory. When a source piece exceeds the language-aware single-line budget or about 4s, it blocks only if the corresponding target piece itself already has a complete clause or parallel-action seam, and it requires splitting along that natural target seam. In that case an enumeration-comma seam is allowed between complete parallel actions; ordinary noun lists still follow the mergeable-enumeration-comma rule.
       The source side also has a **lower bound**: in a multi-piece sentence, when a piece is attached to ≤2 source words, those words' display width is below 1/4 of the single-line budget (en 10 / zh 4 units), and the translation piece itself is shorter than the degeneration threshold (8 units), that piece is a "fragment". The contract requires merging it into the adjacent piece that continues the same clause. This criterion moves in lockstep with the source-line hard cap: it only attaches a draftBlocker, and only `ccut check` emits `align-source-fragment` to drive a targeted `refine-align` re-alignment. Engine acceptance and submit-time lint do not reject it at all, because rejecting it would only burn the single global repair call and produce a semantically blind deterministic fallback. Narrow source pieces whose translation piece has already reached a width of 8 units belong to the `degenerate_paired_row` rejection channel; the two channels do not overlap.
       The time budget is advisory only. When the reading need for the whole sentence exceeds the speech window, a hint suggests fewer pieces or compression. When one piece has a large gap and an adjacent piece has slack, a hint suggests moving the boundary (the root-cause fix for the "short source, long translation" flashing-subtitle problem).
Degradation: within a batch, sentences are accepted one by one. Each batch makes one first-round call, and all failed sentences enter a single repair round (round limit 1; within the round, calls fan out in parallel per batch). The repair round's retryReason carries the full details of all validation failures from the previous round, and restates the budgets (fit/soft/hard), the per-sentence pieceCount and the key draftBlockers, not just the last one. Over-hard target pieces left by the LLM are deterministically re-split within the same response, without triggering a repair call. But the re-split result must again pass paired acceptance: if re-splitting itself breaks a criterion such as bilingual anchoring, the re-split is abandoned and the cut submitted by the worker is kept (the over-hard piece is written to disk whole and reported through the check alignment warning, rather than rewritten by the engine).
      When the repair budget is exhausted and a worker answer that has passed submit-time lint exists, it is preferred (salvage) over the deterministic equal-width fallback.
      The deterministic fallback hard-cut snaps to atomic boundaries and, within a ±3-atom window, to the strongest seam. It is forbidden to cut inside a CJK word when a legal word boundary exists. The DP splitter follows the same rule: intra-word boundaries and objective seam defects are penalised at the same level.
      When pieces can be safely assigned source words one by one, the anchor is re-scaled proportionally. If a proportional cut point falls inside a source-bound phrase, or the target has more pieces than there are source words, it switches to independent and allocates the whole sentence's time window by reading length. Other structural errors that still fail also fall back to a legal target-language seam split + seam-lint repair.
Long-sentence criterion: when the target exceeds fit/hard, or the whole-sentence speech window exceeds the dwell guardrail (~7s), it enters the batched LLM path. Source length alone no longer triggers a split: many-to-one is the default shape, with several short source phrases sharing one compact translation. But when bilingual paired lines are too dense and the target pieces already have natural seams, the above applies, so the editor does not show three source lines corresponding to one translation line. `--align-local` is a deprecated compatibility parameter and no longer bypasses the long-sentence LLM path.
Thresholds: chosen by target language (CJK fit/soft/hard = 16/14/20, overridable with `--fit`). For mixed Simplified Chinese text, two Latin half-width cells ≈ one CJK reading unit. The source side uses a unified character basis (non-whitespace Latin characters, CJK reading units); the word-count basis is deprecated.
Batching: keep sentence order contiguous. The page count is the maximum of three constraints: the source `word_count` executor tier (agent / provider are both currently 2000 words, §5.3 slack redundancy), at most 40 pending alignment items per page, and a deterministic complexity budget of 16000 per page (approximate cost of the HTML body, the suggested piece count, and terms and bilingual anchors). Pages are then balanced across contiguous complexity. `targeted` and worker slots do not participate in page shaping. The first round, full `align-only`, `--sentences` targeted repair, and the single global repair round all share this three-constraint paging.
Diagnostics are exposed via `alignDiag` / check `align-overfit`. Advisory details are passed through unchanged via `data.advisories` in both the single-document and routed paths (visible to the orchestrator only as counts).
The lint at `task submit` time rejects clinging leading words and dangling tails on the target side, as the engine does. The worker repairs them within the same turn; they are no longer deferred to the aggregate repair batch.
```

## 9.3 Write-back and consumption

- A complete, naturally translated sentence is written to `trans[lang][s-…]`; a word-anchored split is written to `transAlign[lang][s-…]`. The target segment is first frozen independently, then mapped onto a contiguous span of source words; the source Cue and `breaks` take part in none of these steps. When the duration of the whole sentence allows, the derived target stream smooths inter-segment boundaries toward the minimum reading duration, and it fills short sentences only with real subtitle gaps;
- When the timeline keeps only part of a sentence, `transAlign.words` may store the **ordered subsequence of visible words** within that Sentence, and the from/to of manyToOne are evaluated relative to this subsequence; independent may also use the same set to bound the display time window. This way, persistent anchors do not re-cover words that have already been cut; an empty `words` still keeps the "full sentence" compatibility semantics;
- **Deriving BCF `from`** (format spec §8.4) works directly: the source lane takes word atoms (real word timestamps → karaoke highlighting), and the translation lane takes `trans` per Cue. The degraded design of showing the whole sentence on screen at once fits this naturally;
- **Export side**: SRT/VTT/ASS/JSON/Markdown/MP4 and the six kinds of project export all consume the same target stream. Translated segments of the same sentence that sit inside a cut are re-merged within the same clip, while different occurrences of reused material stay separate.

## 9.4 Round orchestration: streaming local alignment + LLM fallback set (M8.2 retired; this section is kept as a historical record)

> **M8.2 removed**: the three-round orchestration described in this section (the streaming local round / local tail-sweep round / LLM fallback round) was taken offline together with `align.scorer`. The align stage now always follows the orchestration at the end of this section (“`align.scorer = llm`”): after the whole text has been translated, align runs once over all of it. The content below is kept for understanding the historical implementation.

When `align.scorer` is `reranker` / `hybrid` and at least one local backend has been injected, the align stage is split into three rounds (semantic scorer plan §20.4; engine entry points `run_align_local` / `run_align_fallback`):

1. **Streaming local round** (inside the translate engine): as soon as the output of each translation batch lands (writes `trans`), run the local two-level scoring once over only that batch's sentences, write `transAlign`, with zero LLM calls. The event order is fixed as "batch i translation lands → batch i alignment lands", so the App's translation card shows a bilingual split within 1–2 s after the translation appears. Sentences judged low-confidence in this round are first written with whole-sentence correspondence so they are displayable, and their sentence ids go into `AlignOutcome.low_confidence`.
2. **Local tail-sweep round**: after the whole text has been translated, run the local round once more over the entire text. This covers sentences this round did not re-translate (and therefore did not enter the streaming batches), as well as the forced re-split of `--align-only`. Entries that are already valid are skipped before scoring, so when the whole text is already aligned this round costs almost nothing.
3. **LLM fallback round**: issue one single dedicated `align-edges` repair round plus `align-rewrite`, over the union of the low-confidence sets from the first two rounds. That set defines the coverage: no entry outside it is rewritten (D6). If the set is empty, the number of LLM align calls in this run is 0. `reranker` still does not issue a dedicated `align-edges` in this round; sentences that the draft is not enough to settle are simply aligned as whole sentences.

`align.scorer = llm` does not use this orchestration. After the whole text has been translated, it is still one full align run (fused draft → dedicated → rewrite → fallback), with behaviour unchanged byte for byte. Routed (final timeline) translation only aligns after projecting visible words per source, and it also does not use the streaming round.

## 9.5 Re-alignment entry point

`ccut translate --align-only [--sentences s-g1.0,s-g2.0]` (`--groups` is an alias): skips whole-sentence translation and re-runs only line splitting. The key is the sentence id (`s-<first-word-id>`). If a stale key or a bare word id is passed, the CLI remaps it to today's sentence that contains that word and records it in `alignDiag`. A full re-alignment must pass `--yes` (enforced by the CLI, not left to documentation discipline). `ccut check` emits the `align-overfit` list only for sentences that **still exceed hard in the current display stream, or exceed fit while an executable natural seam exists** (including a seam preview and a ready-made `--sentences` command). This keeps sentences that are already aligned correctly, or that have no safe seam, from falling into endless re-runs. A sentence that exceeds fit but not hard, and has **no** natural seam, is filed under `infos[]` as `translation-unsplittable`. Its full detail is still reported, but it is graded as a deliverable structural fact: it produces no fix, does not enter `next`, and does not enter the refine hotspots. For this tier only a shorter translation can improve things; re-running align is ineffective.
