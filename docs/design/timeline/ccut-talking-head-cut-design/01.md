# 1. Goals and scope

> From [CucCut talking-head cut technical plan (prototype rounds 192–197 → core / serve / App v2 / Web)](../ccut-talking-head-cut-design.md)

## 1.1 Prototype requirements → existing capabilities / gaps

| # | Prototype requirement (§12.6 / §13.1 / §15.3) | Existing capability | Gap |
|---|---|---|---|
| R1 | The AI / Agent scans for filler words, pauses and repeated sentence openings and writes them as suggestions; nothing affects playback or export until accepted | `ccut cleanup --review` writes local detection + LLM suggestions into `ai/cleanup.json` and `ai/reviews/cleanup.json` without touching the timeline | Suggestions are one `pending` batch with no per-item status; the LLM categories have no “repeat” category |
| R2 | Accept / ignore one by one, or accept / ignore all at once | `ccut review accept <proj> cleanup --items i,j` (zero-based index) / `reject` | After one accept the whole file becomes `accepted`; the remaining items have no “still pending” state; ignoring is only possible for the whole file |
| R3 | Suggestions coexist with manual cuts; a new scan replaces unhandled suggestions, leaves cut ones alone, and skips ones overlapping existing cuts | `skip_already_cut(proposals, &CutSet)` skips already-cut ranges at generation time | `accept_action_review` compares `baseTimelineSha`, so one manual cut rejects the whole suggestion batch |
| R4 | Drag-select a span of text in the script and press ⌫ to cut it | `cutWords {srcId, first, last}` op + `resolve_word_span` | Neither end has word-level drag selection or a cut-editing mode UI |
| R5 | Cut words are struck through; click to restore; cut spans are visible on the timeline | App v2 `lists/transcript.rs` already draws strikethrough from `derived.cuts`; `restoreCut` op | Cut spans are invisible when the timeline is collapsed; Web has no marking |
| R6 | Every step has a toast + undo; receipt undo for a task = withdraw the whole suggestion batch | Journal group undo; `AI: cleanup` label drives `task_undo` | `--review` mode does not write to the journal, so receipt undo has nothing to attach to; ⌘Z after accepting leaves the review file state out of sync with `cuts[]` |
| R7 | The script selection is mirrored onto the timeline and labelled “1.9s · 00:07.1 – 00:09.1” | `TimelineMap::clamp_source_event` can map a source range to a timeline segment | No selection source of truth, no conversion, no label copy |
| R8 | Floating toolbar above the selection: duration + start/end timecodes / cut ⌫ / preview / cancel Esc | — | None at all |
| R9 | Preview one spot (keeping 0.6s before and 0.4s after) | App v2 hover-preview once window | Needs to bypass collapsing and play a segment on the source clock |
| R10 | Cut-experiment project: no elements, no pre-seeded suggestions | Any project with no elements is already this | Only the empty-state copy is missing; no core concept needed |

## 1.2 Shared / self-owned dividing lines

Following the three red lines in §2.1 of [`ccut-editor-interaction-port-design.md`](../ccut-editor-interaction-port-design.md): any criterion where “the same input must produce the same conclusion” goes into `ccut-editor-core`, and views keep only platform conventions. In this plan, what goes into the core is: token segmentation, mark derivation, selection geometry and timecode copy, summary-bar copy, toolbar state machine, key-binding predicates, preview window, and derivation of suggestion state after undo. What is left to the views is: drag-selection hit testing, overlay positioning, GPUI / DOM rendering, and player controls.

## 1.3 Out of scope

- Do not change the top-level fields of `timeline.json` or the shape of `Cut {id, t0, t1, ref}`; do not change `transcript.json` or `words[]` (cuts never touch words; see [`ccut-edit-domain-design.md`](../../cli/ccut-edit-domain-design.md) §1.3).
- No linked changes to the clip layer (`splitClip / removeClip`); talking-head cutting works only on the media-layer `cuts[]`, where an implicit single clip is sufficient.
- On export, the cut-seam fade only applies a linear ramp of `--seam-fade-ms` (default 10ms) on each side of every seam; no cross-fade (the finished video's duration is unchanged; decided in §11).
- `skills/cuccut/templates/studio` is retired and does not apply.
