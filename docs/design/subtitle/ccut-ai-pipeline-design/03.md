# 3. Data and State

> From [ccut post-transcription AI pipeline technical design (polishing / segmentation / chaptering / translation / subtitle alignment)](../ccut-ai-pipeline-design.md)

## 3.1 Word atoms are the single source of truth (inherits format spec §18)

The whole pipeline reads and writes the §18 transcript document: `words[]` is the only persisted source of text and timing;
Cue / Para are derived by the normative algorithm of §18.5; structural interventions by the user and the AI both land in
sparse override tables keyed by word id (`breaks` / `paraBreaks` / `hidden`). **This design adds no source-text store parallel to the words**: polishing edits words, segmentation writes override tables; the full natural translation is attached to the id of the derived Sentence, and alignment fragments are only a display overlay.

The existing `transcript.json` v0.1 (rows contract) of `ccut-speech-core` is demoted to a **raw ASR artifact**, stored at `ai/asr-rows.json` for audit and rebuilding. The canonical document for editing and the pipeline is the §18 word-atom transcript, generated by the deterministic build step of Stage 0 (§4.3).
The stdin of `ccut project seed-transcript <project>` also accepts this 0.1 rows contract. When writing into an empty project, it reuses the same `build_doc`, CJK AutoCorrect and validation path as transcription, while saving an audit copy. This lets regression experiments rebuild the raw word stream from the same model inference without re-running ASR, and polished text cannot pass itself off as raw input. The language and media path/hash/duration in the rows are synced back into the project manifest, replacing the placeholder values from `project create` before transcription.

## 3.2 Fingerprints: two kinds, strictly separated by purpose

Ported from voice-ink's FNV-1a scheme (`offset 0xcbf29ce484222325`, `prime 0x100000001b3`, separator between values `hash ^= 0x1f`):

```rust
// ccut-flow-core/src/fingerprint.rs
/// Content fingerprint: hashes each word's text. Any text edit invalidates it.
/// Format: "1234:g1.0:g87.4:k3f9…" (count:firstId:lastId:base36hash)
pub fn fingerprint(words: &[Word]) -> String;

/// Structure fingerprint: hashes only each word's id. Survives text edits (rebind keeps ids) and is invalidated by re-transcription (all ids are reissued).
pub fn id_fingerprint(words: &[Word]) -> String;

pub fn fingerprint_strings<I: IntoIterator<Item = String>>(items: I) -> String;
```

## 3.3 Stage stamps (transcript v0.2 incremental fields)

The transcript document gains an optional field `stages` (a 0.2 evolution of format spec §18, backward compatible: absent means “never run”):

```jsonc
"stages": {
  "asr":       "1234:g1.0:g87.4:k3f9…",   // content fingerprint: text at transcription completion
  "asrLayout": "…",                        // layout fingerprint: sorted string of breaks+paraBreaks+hidden
  "polish":    "…",                        // content fingerprint: at polish submission
  "segment":   "…",                        // structure fingerprint (id): at segment submission
  "chapters":  "…"                         // content fingerprint: at chapters submission
},
"transSrc": {                              // lang → { sentenceId → source-text / visible-word fingerprint }
  "en": { "s-g1.0": "…", "s-g5.2": "…" }
}
```

Dirty-detection rule table (who writes / who reads / when it expires):

| Stamp | Fingerprint type | Expiry condition | Meaning |
| --- | --- | --- | --- |
| `asr` | Text | Current text ≠ stamp | Manual text edits exist (flips the default of `--polish`) |
| `asrLayout` | Layout string | Current layout ≠ stamp | Manual sentence/paragraph intervention exists (automatic segmentation yields to manual) |
| `polish` | Text | Current text ≠ stamp | Edited after polishing; the polish is stale |
| `segment` | **id** | Current id set ≠ stamp | Pure text polishing does **not** expire segmentation; re-transcription does |
| `chapters` | Text | Current text ≠ stamp | Chapter titles may no longer match the content |
| `transSrc[lang][sentenceId]` | Single-source project: the whole source sentence's words; timeline project: the sequence of visible words after cuts | Corresponding fingerprint changed, or existing translation lacks a stamp | **Sentence-level** expiry: the basis of incremental translation (§8.5) |

`segment` using an id fingerprint is the crux of the whole table. The segmentation product (`paraBreaks`) is keyed by word id, and polishing keeps unchanged words' ids via rebind, so “polish once” does not invalidate segmentation. Re-transcription reissues all ids, so segmentation necessarily expires. **Expiry semantics match how the product is keyed**, which is why the rule table can stay simple.

## 3.4 AI artifact directory inside the project package

Following the project package layout of format spec §17, a new `ai/` subdirectory is added (valuable and not cheaply rebuildable: LLM calls cost money, so it does not go under `cache/`):

```
myfilm.ccut/
  transcript.json                          primary source canonical document (§18 + stages/trans/transSrc/transAlign)
  transcripts/<srcId>.json                 additional source canonical documents (media.id = srcId)
  timeline.json                            optional: final timeline and per-source cuts/clips
  ai/
    asr-rows.json            raw ASR rows (engine-native rows, for audit and rebuild)
    brief.json               document brief: summary + glossary + named entities (§5.2)
    polish.json              polish artifact: sentence records + per-edit suggestions (for review)
    segment.json             segmentation artifact: SegmentRecord[] (id + time anchoring)
    chapters.json            chapters artifact: fingerprint / rows / review / parts (paged run records)
    chapters/vNNN/           file-v1 per-page attempts (pages/pNNN.*, outline.*, manifest.json)
    summary/                 summary writing artifacts (§11.4): vNNN/result.json + latest.json pointer
    blog/                    blog writing artifacts (§11.4): same as above
    titles/                  title generation artifacts (§11.4): same as above
    *_status.json            resume progress (deleted on completion)
  tasks/                     contracts and payloads for the LLM agent reply loop (CLI design §8)
```

Except for ASR rows, auditable AI artifact files carry a `fingerprint` field in their header; readers **must** verify the fingerprint before use. `ai/asr-rows.json` keeps the speech-core 0.1 contract and does not invent a `fingerprint` field: its first production reader checks same-source by comparing `media.hash` with the main transcript's `media.hash`, and requires word ids to still follow the `g<row>.<column>[~atom]` structure. If the file is missing, corrupt, of an unrecognized version, or the source does not apply, the initial soft segmentation is silently disabled. The full contract is in [`ccut-asr-initial-segment-design.md`](../ccut-asr-initial-segment-design.md). The persistent truth of translations is not written to a separate `sentences-<lang>.json`; instead it lives in the three tables inside each source transcript. `ai/*_status.json` only holds resumable live state and is deleted on completion.

## 3.5 Checkpoint resume

```rust
// ccut-flow-core/src/progress.rs
pub struct PipelineStatus<T> {
    pub fingerprint: String,      // fingerprint of the input word stream; a mismatch invalidates it outright
    pub total_pages: u32,
    pub processed_pages: u32,
    pub custom: T,                // stage-specific custom state: committed paragraphs / translated sentence id mapping…
}
```

- Page boundaries are **not persisted**: they are deterministically re-derived from the fingerprinted word stream (the paging algorithm of §5.3 is a pure function);
- The persistent unit of translation is the **sentence id, not the page number** (§8.4): resumption stays valid when paging parameters change;
- A completed stage must delete its status file: a completed state leaves no resumable live state.
