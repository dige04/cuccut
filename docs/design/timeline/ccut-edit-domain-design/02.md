# 2. Overall architecture

> From [CucCut editing domain protocol design (Cut / Clip / Element / Watermark / project export)](../ccut-edit-domain-design.md)

## 2.1 Two-layer editing model and media view

```
┌─ Media layer (per source) ───────────────────────────────────┐
│  Source media + transcript (real source time, never rewritten) │
│  cuts[]: lossless soft-delete ranges (source time; filler words / silences / script-based cuts land here) │
│      │                                                        │
│      ▼  fold cuts (pure derivation, not persisted)            │
│  [Media view] ≈ database view:                                │
│    · view duration = source duration − Σcuts                  │
│    · view subtitles = Cues / word stamps with cut words removed (view time) │
│    · externally behaves like a physical trim; internally everything is real time │
└──────────────┬───────────────────────────────────────────────┘
               │  clip references view range
┌─ Timeline layer ▼─────────────────────────────────────────────┐
│  clips[]: ordered arrangement sequence (can be split / trimmed / reordered / hard-deleted; undo-reversible) │
│  tracks[]: overlay elements (B-roll / text / watermark / audio, anchored to timeline time or words) │
│  timeline time = prefix sum of each clip's view-window duration = final output time │
└──────────────────────────────────────────────────────────────┘
```

The reversibility contracts of the two layers are deliberately different:

| | Cut (media layer) | Clip (timeline layer) |
| --- | --- | --- |
| Delete semantics | **Soft delete**: a cuts entry existing means "cut"; restore removes the entry | **Hard delete**: the clip is removed from the array; the data model keeps no trace |
| Reversibility | Data-model level (lossless set; can be restored exactly at any time) | Session level (`.ccut/history` journal undo/redo) |
| Typical operations | Cut filler words, cut silences, delete sentences by script | Split clips, extract segments, reorder, discard whole sections |
| Scope | Takes effect once at **all** references to that media | Affects only this one spot on the timeline |

## 2.2 File and responsibility boundaries

```
myfilm.ccut/
  project.json        Project manifest (primary media identity, language, stage stamps) — unchanged
  transcript.json     Primary media word-level transcript (ccutTranscript 0.3) — unchanged
  transcripts/        Additional source transcripts: <srcId>.json (same 0.3 schema, media.id = srcId) — new
  timeline.json       Sole source of truth for the editing domain: sources (containing each source's cuts) / clips / overlay tracks / main picture — new
  studio/style.json   Project-level persistent truth for subtitle and picture presentation
  studio/data.json    Derived projection (adds timeline and view sections) — extended
  ai/cuts.json        Cut provenance (append-only) — new
  ai/broll-suggestions.json  B-roll suggestion artifact — new
  screentext.json     On-screen text OCR ticket queue (not document data) — new
```

Iron rules of responsibility (continuing the existing layering):

- `transcript.json` remains the **sole source of truth for text and timing**, anchored to media source time; editing never writes to it;
- `timeline.json` is the **sole source of truth for editing intent**: what each source cuts (cuts), what the timeline arranges (clips), what it overlays (tracks), and how it moves (animate);
- `studio/style.json` is the **persistent source of truth for subtitle and presentation styles**; `studio/data.json.style` is only a derived copy of it;
- **Everything persisted uses real source time**. View time and timeline time are evaluated results that appear in projections, command receipts and the UI, never in storage. “Internal real time, external view time” is this protocol's storage discipline;
- `studio/data.json` remains a pure derived projection, adding only timeline / view projection sections;
- BCF composition documents (`.ccut.json`) **do not enter the product project**. Where BCF rendering semantics are needed (overlay burn-in, animation sampling), the implementation **compiles and derives** an equivalent structure from `timeline.json`. The direction is one-way and nothing is persisted (§4.3);
- All writes go through `ccut` / `ccut serve`, briefly hold `.ccut/lock`, and enter the `.ccut/history` journal.

## 2.3 Three-layer time domains (normative)

| Time domain | Definition | Used by |
| --- | --- | --- |
| **Source time** (per srcId) | Seconds on the media file's own clock | All persisted fields: `words[].t0/t1`, `cuts[].t0/t1`, `clip.in/out`, element `srcStart` |
| **View time** (per srcId) | Continuous seconds of that source after folding cuts | Media view external contract: view subtitles / word stamps, in/out parameters of the `clip` command, the asset panel |
| **Timeline time** | Seconds from clip view windows concatenated in array order; **i.e. the final output time** | Editor timeline, element `start/end`, word-anchor evaluation results, export / burn-in |

The timeline has **no cut segments** (this is the biggest difference from the old version). Cuts are already folded at the media view layer, and a hard-deleted clip leaves no trace. Timeline time and output time are unified, so a separate OUTPUT folding domain is no longer needed.

Normative mapping functions (any implementation must match them, including tolerance and seam semantics):

```
// Media layer: source ↔ view (per srcId)
viewTime(src, t)      = t − Σ dur(cuts lying entirely before t)      if t falls inside a cut → no mapping
srcTime(src, v, bias) : inverse; bias ∈ {preceding, following}
                        UI dwell uses preceding; export advance uses following (aligned with the old version's SeamBias)

// Timeline layer: view ↔ timeline
clipViewIn/Out(c)     = viewTime(c.srcId, c.in / c.out)       if an endpoint falls inside a cut, snap to the adjacent kept boundary
viewDur(c)            = (clipViewOut − clipViewIn) / c.rate
tlStart(i)            = Σ_{j<i} viewDur(clip_j)
tlTime(src, w)        = tlStart(c) + (viewTime(src, w) − clipViewIn(c)) / c.rate
                        (w must fall within c's valid window; 0 hits = cut / not arranged, N hits = media reuse)

// Event folding (subtitle / element windows → timeline)
clampEvent(start,end) : intersect the event window with the kept∩clip window; if the whole span is cut, or the kept part is < 10ms → discard
```

Assignment of precision and tolerance across layers (fixed by the implementation in v0.5): the mapping functions themselves stay at full precision with no frame rounding. `1/fps` frame alignment happens at **consumption points** (WordSpan settlement §3.3-3, and the sampling and writing layers of burn-in / export). fps does not enter the mapping layer signature. The 1µs seam tolerance between adjacent segments belongs to the `ccut-editable` builder (uniformly tightened before entering the writer, §6.2/§6.3). The 10ms threshold of `clampEvent` is the crate-level constant `ccut_timeline::MIN_EVENT_DURATION`; all Rust call sites must consume this constant, and the JS/Swift side mirrors it with the same value. This set of functions is a layered refactor of the old `ClipPartitionIndex` + `CutTimelineMap`, landing in the `ccut-timeline` crate (§5.5). Rust has a single implementation, and the three ends (CLI / serve / Studio JS / Swift) are cross-checked against contract fixtures (the fixtures include a 10ms drop sample; the Swift-side views table is likewise driven by the fixtures).

**Key corollary (the core benefit of this model)**: clips store source time, so when a **new cut is added** to a source, every clip referencing that range **automatically shortens**; on **restore** it automatically lengthens. Content follows the words, and a filler-word cut takes effect across the whole timeline at once, with no ripple rewrite. Cut / restore operations **do not change any clip field**. (From 2026-09-28, 1.283.0: picture and sound live only on elements, so the same write transaction also makes elements placed by numeric time follow the clock. The video element under the clip name receives the remaining source range, and other elements are converted by the output moment, so the diff also includes element changes. Word-anchored elements do not move. For the rule, see [BCF §19.1](../../bcf/cuccut-format-spec/19.md) “Elements follow the clock”.)
