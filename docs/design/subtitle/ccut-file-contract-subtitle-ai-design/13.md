## 13.1 Intentional Limitations Already Implemented (M1–M4 ruling summary)

Each item below is **an intentional current state**, not a pending defect. It is recorded here so it is not later treated as a bug and "fixed" back in. Genuinely unimplemented items are in §17.

**(1) brief.json / context.md dual-write and grayscale coexistence**

`ai/context.md` / `ai/context.<lang>.md` is the new source of truth, but `ai/brief.json` / `ai/brief-<lang>.json` **continue to be atomically dual-written in the same run**. The first migration seeds context.md from brief.json; afterward context.md is authoritative and writes back both files. Dual-writing is kept because json-v0 consumers still read brief: `ccut check`, Subtitle Studio, existing user scripts, and **the Mac App's only read point**, `apps/mac/Sources/VoiceInk/Presentation/SubtitlePresentationContext.swift:41` (which builds the `brief-<lang>.json` path). Dual-writing can only be removed after the §13 mutual-recognition period ends and the Mac side has switched to reading context.md.

**(2) ~~Fixed json-v0, entry points not exposing `--contract`~~ (obsolete after the 2026-08 deprecation was executed)**

`--contract` has been removed entirely. All entry points in the original list (pre-polish embedded in workflows, finished-timeline routing, `ccut refine`, workflow / `auto`, jobs started by `ccut serve`) now, like direct commands, **always run on file-v1**. The only remnant of the original table is that the serve task allowlist still has no `contract` key, and there is now no parameter to expose.

**There are no "silently fails midway" combinations**: `--fit` is orthogonal (it feeds `TransParams`; the file carrier carries it as `data-fit`/`data-soft`/`data-hard`). `--align-local` conflicts only with `--align-mode` and is unrelated to the contract.

**(3) M2 (polish) rulings**

- Carry-over is fully retired. The json-v0 path kept during the grayscale period and `MAX_CARRY_CHARS` were deleted along with the deprecation execution (§6.5).
- `resplit_oversized` **is not wired into** the file path. It creates paragraph boundaries from sentence-final punctuation, which conflicts with "paragraph boundaries have only two sources: blank lines and `⏹`" (§6.5). When a whole page has been crammed into one sentence, the page is no longer rejected outright: the body is accepted on the first round, and overlong sentences go through `punct-repair` for targeted punctuation insertion plus deterministic engine sentence splitting (§6.7). Sentences split apart are then given paragraph breaks by `segment-repair`.
- The low-similarity wrap-up still reuses the `polish-retry` channel (a single-round json-v0 JSON envelope, belonging to an unmigrated kind). It is the same core repair semantics, so there is no need to build a separate one for the file contract.

**(4) M3 (align) rulings**

- The two align validators **have not been merged into one call site** (only the arithmetic was merged, §2).
- `align-over-hard` / `align-illegal-seam` are downgraded under the file contract to **per-sentence advisory** and do not block acceptance of the batch (§8.4).
- The commit-time lint pushed to the worker is the **full** set of Problems, including the two codes the engine itself would let through. This is **a deliberate asymmetry**, not a missed change (§8.4).
- The `pause_tier` private threshold is kept only in the draft tokens' internal pause metadata. It does not enter the file carrier and does not participate in pagination (§8.2).
- Preview `<style>` is deliberately not inlined (§8.1).

**(5) M1 (translate / execution layer) rulings**

- `default_lease_sec` has not been recalibrated (§9.2).
- The agent task directory has **not been split into data plane / control plane**. It is still five directories plus `payloads/` (§9.2).
- The lint budget is still keyed on `(callId, leaseId)`. Changing the lease resets it to zero (§9.2).

**(6) M4 (context / provenance) rulings**

- The provenance stale criterion is narrowed to **changes in the term-hash set**. Changes in summary or style only produce advisory output (§11.3).
- When no effective brief exists, everything is judged clean rather than everything being judged stale (§11.3).
