# 3. timeline.json data model

> From [CucCut edit-domain protocol design (Cut / Clip / Element / Watermark / Project export)](../ccut-edit-domain-design.md)

## 3.1 Top-level structure

```jsonc
{
  "ccutTimeline": "0.1",
  "sources": { /* §3.2 sources table: media identity + in-source cuts + transcript ownership; the main media keeps the reserved id "main" */ },
  "clips":   [ /* §3.4 timeline arrangement sequence; array order is the timeline order */ ],
  "tracks":  [ /* §3.6 overlay tracks (elements) */ ],
  "main":    { /* §3.8 main-picture transform and canvas fill */ }
}
```

- No field in this document accepts code. Values are literals only, plus the word-anchor strings of §3.5 (a `~` subset reusing BCF TimeExpr).
- **There is no top-level cuts table**: a cut is internal state of a source (decision 10), and its lifetime is bound to the source.
- The minimal legal document is `{"ccutTimeline":"0.1"}`: a source with no cuts means the view is the original footage, and no clips means an implicit single clip covering the whole view of the main media. When the first editing intent arises, the implementation seeds an explicit single clip (`[{"id":"c1","in":0,"out":<duration>}]`). **A transcript-driven editing workflow writes cuts only on sources and may never touch `clips`**: the single clip references the whole view, and cuts collapse automatically.

## 3.2 sources table: media identity + in-source cuts + transcript ownership

```jsonc
"sources": {
  "main": {                              // reserved id: media identity is still held by project.json,
    "cuts": [                            //   this entry carries only edit-domain source state (no identity fields)
      { "id": "cut-1", "t0": 12.40, "t1": 13.10, "ref": "cut-1" },   // ref → ai/cuts.json
      { "id": "cut-2", "t0": 47.02, "t1": 47.31 }
    ]
  },
  "src-a1": {
    "path": "media/broll/factory.mp4",   // project-relative or absolute path
    "hash": "sha256-…",
    "kind": "video",                     // video | image | audio
    "duration": 12.4,                    // omitted for image
    "naturalW": 1920, "naturalH": 1080,
    "hasAudio": true,
    "poster": "cache/posters/src-a1.jpg",// rebuildable, may be omitted
    "cuts": [ { "id": "cut-3", "t0": 0.0, "t1": 1.2 } ]
  }
}
```

- **A source is the aggregate root of the edit domain**: one source entry = media identity + in-source `cuts[]` + transcript ownership. When a source is deleted, its cuts disappear with the entry (this is exactly why cuts are cohesive with their source, decision 10). Any clip or element that references it immediately triggers a `clip-source-missing` error. Deleting a source is an explicit destructive operation: the command surface requires `--yes` and lists the affected objects.
- `"main"` is a reserved entry: **identity fields (path/hash/kind/…) are forbidden** (the single source of truth remains `project.json.media`). It carries only edit-domain source state such as `cuts`. The entry may be omitted when there is no edit state.
- The `hash` of an attached source has the same meaning as in `project.json` (a content anchor; a change makes related derived data stale).
- **Transcripts belong to the source and are stored in separate physical files**: `main` → the project-root `transcript.json`; attached sources → `transcripts/<srcId>.json` (ccutTranscript 0.3, `media.id = srcId`). The path is a protocol convention, not a stored field. All word timestamps and the `trans`/`transAlign`/`transSrc` translation tables inside a transcript are anchored to **the real source time and source words** and travel with the source: when footage is cut, spliced, reused or moved, the transcript and translations stay valid down to the character. Orphaned transcript files left after a source is deleted are cleaned up by `project repair` (explicit, never silent). A transcript is optional. Without one, the source has no word-driven cuts or view subtitles, and only time-range cuts are possible.

## 3.3 Media layer: in-source `cuts[]` (lossless soft delete)

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | unique within the document; `cut-<n>` increments deterministically and is never reused once assigned |
| `t0` / `t1` | number | **source-time** interval, `0 ≤ t0 < t1 ≤ source duration` |
| `ref` | string | id of the provenance entry (§3.9), may be omitted |

Normative constraints and semantics:

1. **One set per source**: sorted by `t0`, non-overlapping. Adjacent intervals within 0.02s are merged automatically on write (the merged interval keeps the earlier id; the absorbed id is retired and never reused).
2. **Soft delete**: an entry's existence means "cut"; `restore` = delete the entry. The set itself is the lossless fact. No "kept partition" companion is needed, since kept is derived as the complement.
3. **Word-driven writes**: `cut add --words wA..wB` first snaps the word range to a source-time range per [§18.6 WordSpan rules](../../bcf/cuccut-format-spec.md) (breathing padding `padPre/padPost = 0.05s`, never crossing adjacent words, aligned to the frame grid; the spec already defines this, and this protocol is its first implementation), then writes the entry, and the receipt is marked `snapped: true`. Silence cuts are written directly as source-time ranges (detection parameters carried over from the old version: `threshold 0.8 / compressTo 0.3 / maxGap 3.0`, etc., §5.1).
4. **A word's cut state is derived**: if a word's midpoint `(t0+t1)/2` falls within a cut interval of its own source (half-open `[t0, t1)`), the word is cut. The single implementation entry point for this test is `CutSet::word_is_cut`. Anchor evaluation, projection and translation-visible words must all go through it; inlining copies anywhere is forbidden. The `hidden` override table still governs only "no subtitle" (slips of the tongue, filler words), and the two semantics are independent and can be combined.
5. **The media view** is determined solely by cuts (§2.3): view duration, view subtitles (cut words removed, word timestamps converted to view time), and the `viewTime/srcTime` mapping. The view is **purely derived**: any implementation given the same set must produce a bit-for-bit identical view.

## 3.4 Timeline layer: clips (arrangement, hard delete)

```jsonc
"clips": [
  { "id": "c1", "in": 0.0,  "out": 48.00 },                    // main media (srcId defaults to "main")
  { "id": "c2", "srcId": "src-a1", "in": 2.0, "out": 8.0 },    // insert attached footage
  { "id": "c3", "in": 48.00, "out": 96.50 }                    // second half of main media (c1/c3 produced by splitting)
]
```

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `id` | string | required | unique within the document; `c<n>` increments deterministically and is never reused once assigned |
| `srcId` | string | `"main"` | media source |
| `in` / `out` | number | required | **source-time** interval, `0 ≤ in < out ≤ source duration` |
| `rate` | number > 0 | 1 | playback speed; written by `clip set --rate`, static, not animatable |

Normative constraints and semantics:

1. **A clip references the media view**: its effective content = `[in, out]` minus that source's cuts, and after collapsing it enters the timeline. The in/out parameters of the command surface and UI are in **view time**. On write they are converted to source time via `srcTime()` before being stored (§2.3 storage discipline).
2. **Timeline position is derived**: a clip's start on the timeline = prefix sum `tlStart(i)`, not stored. Reordering = moving array elements. Splitting = one becomes two (the right half gets a new id). Neither requires changing other clips' numbers.
3. **Hard delete**: `clip remove` removes the entry from the array, and the data model keeps no trace. Reversibility is provided by the `.ccut/history` journal (each timeline.json write transaction goes into the history store, so the undo/redo endpoints cover it with no changes).
4. **No-coverage invariant**: clips are a free arrangement sequence. They are not required to cover any source, the same source interval may be reused by several clips (footage reuse), and whole segments may be discarded. The old-version invariant that "the main partition must cover the full length" is dropped with the two-layer separation: losslessness is already guaranteed independently by the cuts layer.
5. **Splitting**: splitting at timeline time t (or at a word) = locate the containing clip, convert to source time, and cut there. If the cut point falls inside a cut segment, it snaps to the adjacent kept boundary.
6. **Empty-window check**: if a clip's effective window (after subtracting cuts) is empty, that is a lint error (`clip-empty-after-cuts`). Adding a cut that empties a clip triggers the same error (suggesting deleting that clip or restoring it).

## 3.5 Word anchors

Element time fields accept `~<srcId>:<wordId>[:start|:end][±offset]` (the BCF Appendix A grammar reused verbatim, with `refId` restricted to srcId). Evaluation chain: word source time → view time (if the word is cut, per the §3.3-4 midpoint rule, it is a `word-anchor-cut` error; if the word is kept but a cut trims an endpoint exactly off the word head or tail, the endpoint snaps to the kept side where the word body lies, same as the §2.3 clip endpoint semantics) → timeline time (via the clip that references that source; 0 matches → `word-anchor-unmapped` (not arranged); multiple matches → `word-anchor-ambiguous`, which must be rewritten explicitly as seconds or narrowed by clip). Evaluation happens at read/render time, and **the anchor string is kept on disk**. After cut/restore, splits or reordering, elements follow their words automatically. This is the capability gain of the new protocol over the old version.

## 3.6 Overlay tracks and elements

```jsonc
"tracks": [
  { "id": "broll", "kind": "overlay", "name": "B-roll", "hidden": false, "locked": false,
    "elements": [
      { "id": "el-1", "kind": "video", "role": "broll",
        "start": "~main:g42.0", "end": "~main:g48.3:end+0.4",
        "srcId": "src-a1", "srcStart": 2.0, "muted": true,
        "place": { "x": 71, "y": 29, "w": 34, "radius": 28 },
        "mode": "pip", "fit": "cover", "bg": "blur",
        "animate": { "enter": { "preset": "rise", "dur": 0.5 },
                     "loop":  { "preset": "float", "period": 2.4 } },
        "ai": { "suggestionId": "sug-3", "query": "factory line", "reason": "…" } }
    ] },
  { "id": "text", "kind": "overlay", "elements": [
      { "id": "el-2", "kind": "text", "text": "三个瓶颈，一个答案",
        "start": 12.0, "end": 16.0,
        "place": { "x": 50, "y": 18, "w": 62 },
        "style": { "fontSize": 41, "fontColor": "#FFFFFF", "bold": true,
                   "background": true, "backgroundColor": "#101418A6",
                   "textOutline": { "on": true, "color": "#000000", "width": 14 } } }
  ] },
  { "id": "wm", "kind": "overlay", "elements": [
      { "id": "el-3", "kind": "text", "role": "watermark", "text": "@jimliu",
        "place": { "x": 85, "y": 10, "w": 22, "opacity": 0.6 },
        "tile": { "on": true, "angle": -30, "gapX": 8, "gapY": 10, "stagger": true } }
  ] },
  { "id": "bgm", "kind": "audio", "elements": [
      { "id": "el-4", "kind": "audio", "srcId": "src-b2",
        "start": 0, "end": null, "volume": 0.4 }
  ] }
]
```

**Tracks**: `{id, kind: "overlay" | "audio", name, hidden, locked, muted, elements[]}`. Stacking order = track array order (bottom → top) × element array order within a track. **There is no implicit canonicalRank**: the migrator is responsible for materialising the old project's implicit order into an explicit array order (§7). Subtitles do not occupy a track. Subtitles are still derived from the transcript, with styles defined by `studio/style.json` (and projected to `studio/data.json.style`), and at render time they sit beneath all overlay tracks and above the main picture. This is semantically equivalent to the old composition order `video → B-roll → subtitles/text → watermark`, but it is expressed as a "fixed position for the subtitle layer" rather than through a track registry. If an element must sit beneath the subtitles, put it on a lower track.

**Elements** (closed field set, `additionalProperties: false`):

| Field | Applies to kind | Description |
| --- | --- | --- |
| `id` / `kind` / `name` | all | kind ∈ `text · image · video · audio` (closed set for the first version; shape/sticker/motion see §11) |
| `role` | all | Semantic label: `broll · watermark · screentext`; default none. **Only affects command-surface selectors and lint; it does not change rendering semantics**: a watermark is simply a text/image element with a role set (decisions 7/8) |
| `start` / `end` | all | **Timeline seconds** or a word anchor (§3.5); `end: null` = to the end of the timeline. The window is half-open `[start, end)`. Numeric anchors keep their timeline coordinates unchanged after structural changes (cut/split/reorder), as in standard NLE behaviour. To follow content, use a word anchor |
| `hidden` | all | Temporarily hides the element (not rendered, not exported, data kept). Default false, and false is not written to disk |
| `place` | visual | Normalised transform: `x/y` (centre point, canvas %, y measured from the top), `w` (width %; for text, the default is content-adaptive), `scale/scaleY/rot/opacity`, `radius` (corner radius, in canvas reference units). **Aspect-ratio independence** is a hard requirement (§1.3 correction 3) |
| `srcId` / `srcStart` / `rate` / `muted` / `volume` | image/video/audio | media references go through the sources table (`"main"` is valid, for switching the main video back in as picture-in-picture); `srcStart` is **source time**; bare paths are not accepted |
| `mode` / `fit` / `bg` | image/video | `fullscreen · pip`; `cover · contain`; contain letterbox fill `blur · black · #RRGGBB` (solid colours since `ccutTimeline` 0.12) |
| `text` / `style` | text | `style` **reuses the subtitle style schema** (the font/outline/shadow/backing-plate subset of the fields projected from `studio/style.json`). Text element rendering reuses the subtitle rendering core directly, so the Rust and JS sides have zero drift out of the box |
| `stylePresetId` | text | points to the project style library (§5.2 `element style --save`) |
| `tile` | text/image | tiled watermark: `{on, angle, gapX, gapY, stagger}`; when `on: false` the whole object is not written to disk |
| `mask` / `fx` | image/video | `{shape:"ellipse", feather}`; `{grayscale, blur, brightness}` |
| `animate` | visual | §3.7 |
| `keyframes` | visual (`volume` limited to audio/video) | 0.12: `{属性: [{t, v, ease?}]}`, properties `x/y/scale/scaleY/rot/opacity/radius/volume`, `t` is element-local seconds or `"N%"`; sampled values replace the static values as the base pose, and `animate` is layered on top; `volume` keyframes are the volume envelope. End of §3.7 |
| `duck` | audio/video | 0.12: `{under: "speech" \| 轨 id, depth?=10 dB, attack?=0.02 s, release?=0.35 s}`, lowers this element while sound is present elsewhere. End of §3.7 |
| `ai` | all | Provenance: `{suggestionId?, query?, reason?}` (B-roll) or `{op:"screentext", srcText, frameT, blockId, conf, targetLang, appliedStart, appliedEnd}` (screen text; `(frameT, blockId)` is the idempotency key for apply) |

**Screen text (screentext)**: not a separate type. It is an ordinary element with `kind:"text"` + `role:"screentext"` + `ai` provenance. The OCR work-ticket queue still lives in `screentext.json` at the project root (workflow state, not document data), and its schema is aligned with the old version (block geometry in canvas %, `span.source ∈ detected|scan-refined|manual`, state machine `pending|translated|skipped|applied`).
A scan first atomically extracts a deterministic sampling grid, then calls Tesseract in multi-page batches of at most 24 frames. If one batch fails, it reports the first and last frames and does not commit the queue, and it does not change per-frame geometry or queue order.

## 3.7 Animation

Reuses the BCF animation model (decision 9), with the slots adapted to the clip domain:

```jsonc
"animate": {
  "enter": { "preset": "rise", "presetVersion": 1, "dur": 0.5, "delay": 0,
             "intensity": 1, "ease": "easeOutCubic" },
  "exit":  { "preset": "fade", "dur": 0.3 },        // when absent, derived by mirroring enter, dur×0.75
                                                     // "none" = explicitly no exit
  "loop":  { "preset": "float", "period": 2.4, "intensity": 1, "phase": 0 }
}
```

- **Pure data, closed enumerations**: preset id + frozen version + scalar parameters, with no hand-written keyframes surface (first version; free-form keyframes are a BCF orchestration capability and stay out of the clip domain). The easing vocabulary is the closed enumeration in BCF Appendix A. The legacy `spring(response, damping)` maps approximately to `easeOutBack` / `easeOutElastic` (migration table in §7).
- **Determinism of loop**: the element window is finite, so at render time the loop is expanded by window into keyframes for a finite number of periods. This does not violate BCF's “no repeat” rule, and `sample(t)` remains a pure function.
- **Per-segment cascades for text**: `typewriter` works by Unicode grapheme cluster, `riseWords` splits by whitespace-separated words, and CJK text is split per character. `stagger` can override the interval between segments, and `staggerFrom ∈ start · end · center` controls the arrival order. Whitespace merges into the adjacent visible segment. The cascade spread is capped at 0.5 seconds, and short elements are refitted within the compressed enter window. During a cascade the container keeps identity; only the segments get `opacity/dy`, to prevent double transparency.
- **Preset vocabulary (clip-domain subset; every platform must implement it; shares the registry with BCF Appendix B, and new entries are published in the BCF preset format)**:
  - Enter/exit: `none · fade · rise · drop · slideL · slideR · slideUp · slideDown · pop · zoomIn · zoomOut · spin · blurIn · typewriter · riseWords · wipe · compress · bounce · fall · skid · roll · wave · flipboard · dragonfly · billboard` (`typewriter`/`riseWords` are text-only; they are the first implementation of BCF's future extension 5, “rich-text sub-splitting”. Expanded from 14 to 25 on 2026-09-05; the registry has 21 exit recipes, so `pop`/`blurIn`/`typewriter`/`riseWords` are valid in the exit slot but have no recipe)
  - Loop: `float · pulse · sway · jitter(seed) · blink · rotate · heartBeat · vogue · dragonfly · billboard · roll` (expanded from 5 to 11 on 2026-09-05)
  - Parameter constraints carry over from the legacy version and go into the schema: `dur ∈ [0.1, 2.0]` (snaps to 0.05), `period ∈ [0.2, 6.0]`, `intensity ∈ [0, 1]`; out-of-range values raise `invalid_arg`.
- Animatable kinds: text/image/video; audio returns `unsupported`.
- **Keyframes (`ccutTimeline` since 0.12; this revises the “no hand-written keyframes surface” note above)**: element-level `keyframes` are the clip domain's own per-property keyframes, not the BCF orchestration surface. The only properties are the seven scalars of `place` and `volume`. Sampled values replace the static values as the base pose, and the three `animate` slots still layer on top. CLI form: `ccut element set --move "<property>:<from>→<to>[:<easing>]"` (writes the `0%` and `100%` frames; they travel with the element through trims). Full multi-frame keyframes go through `patchElement` in `ccut edit apply`. A static image or video that covers the canvas is rejected if any part of the motion exposes the background (`--allow-uncovered` lets it through). The full contract is in [BCF spec §19.3 “Keyframes, solid-color canvas and ducking”](../../bcf/cuccut-format-spec/19.md).
- **Volume and ducking (0.12)**: `volume` is still a linear multiplier. The CLI `--volume` accepts `-6dB` / `80%` / `0.8`; the receipt and `element list` report both `volume` and `volumeDb`. `duck` lowers elements such as music by `depth` dB when someone is speaking (`under:"speech"`, read from the projected transcript's word ranges) or when another track is audible. Activity is read only from the document. Final gain = volume (static or keyframed) × fade in/out × ducking. Export and both-end previews use the same pure function, `ccut_timeline::element_gain_envelopes`.

## 3.8 Main picture and canvas

```jsonc
"main": {
  "place": { "x": 50, "y": 50, "scale": 1, "rot": 0 },   // main-picture transform (normalized)
  "muted": false,                                          // mute the whole main-track audio
  "background": "blur"                                     // canvas fill: blur | black | #RRGGBB (0.12)
}
```

Canvas size and aspect ratio are not stored on disk. Previews default to the main media's natural size, and at export they are set by `--ratio/--size` (matching the legacy `outputSize` semantics). Normalized coordinates keep a timeline's meaning stable across aspect ratios.

## 3.9 Cut provenance: `ai/cuts.json`

An append-only artifact at the same level as the other AI-stage outputs (not in `timeline.json`, so that frequently edited objects do not mix into the audit log):

```jsonc
{ "entries": [
    { "id": "cut-1", "kind": "silence",        // silence | filler | badTake | manual | match | offScript (since 1.291.0)
      "t0": 12.40, "t1": 13.10, "srcId": "main",
      "reason": "1.9s pause", "detail": "…",
      "origin": "detect",                       // detect | cleanup | manual | match
      "category": "pause",                      // optional: filler | pause | retake | falseStart | repeat (cleanup subtypes; kind is a closed-set projection)
      "via": "review",                          // optional: flow (applied directly by cleanup) | review (accepted item by item) | ui (manual in the editing state)
      "batch": "cleanup-1757230000000",         // optional: the cleanup scan batch this belongs to; whole-batch undo of a receipt relies on it
      "at": "2026-08-01T10:12:00Z" } ],
  "params": { "minPause": 0.8, "compressTo": 0.3, "maxGap": 3.0, "fillerLang": "auto" },
  "fingerprint": "sha256-…" }
```

Entries are merged and appended by `id` and are never replaced wholesale. `cuts` entries point back to their provenance via `ref`. `restore` does not delete provenance entries (they are kept for audit). `check` warns on “a cut with no provenance” (matching the legacy audit).

## 3.10 Validation rules (schema + lint)

Schema hard errors: closed field sets, kind/preset/easing enums, cuts sorted with no overlap, valid clip ranges, word-anchor grammar.

lint (merged into the `ccut check` report, clip-domain rule group):

| Rule | Level | Description |
| --- | --- | --- |
| `cut-mid-word` | error | cut boundary falls mid-word (deviates from the word boundary by more than the breathing pad) |
| `clip-empty-after-cuts` | error | clip's valid window is emptied by cuts (§3.4-6) |
| `clip-source-missing` / `element-source-missing` | error | `srcId` not in the sources table / file missing |
| `word-anchor-cut` | error | word anchor points to a cut word (§3.5) |
| `word-anchor-unmapped` / `-ambiguous` | error | word not laid out by any clip / reused by multiple clips without qualification (§3.5) |
| `element-window-void` | warn | visual element window does not intersect any on-screen content (e.g., past the end of the timeline) |
| `element-rect-out-of-canvas` | warn | `place` extends beyond the canvas (a video/image box overflowing on either side; a box that fills the full width is a zoomed crop and is not reported, `1.269.0`) |
| `cut-ratio-high` | warn | removed amount from one source > 40% |
| `cut-into-head-tail` | warn | cut intrudes into the first or last 3 seconds of a source |
| `cutaway-flash` | warn | fullscreen B-roll < 1.5s flash cut |
| `cut-no-provenance` | warn | has a cut, but `ai/cuts.json` is missing or has no matching entry |
| `element-window-overrun` | warn | video element source time runs past the end of the media (last frame frozen, same as BCF §6.5) |
| `picture-not-following-cuts` | warn | in a separated document, a clip's picture still sits before the cut point (an older version's cut did not carry the picture along); the next clock-changing write fixes it automatically (BCF §19.1 follow rule 1, `1.283.0`) |
| `clip-unused-source` | info | sources table entry not referenced by any clip/element |
