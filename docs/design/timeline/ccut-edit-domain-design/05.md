# 5. Command surface and serve

> From [CucCut editing domain protocol design (Cut / Clip / Element / Watermark / project export)](../ccut-edit-domain-design.md)

## 5.1 `ccut cut` (media layer: lossless cut)

All commands follow the current envelope / error kind / exit code contract. Write-command receipts carry `changed[]` and new ids. `--json` is covered throughout. Entries are included in `ccut spec` self-description.

```
cut detect <proj> [--src <srcId>] [--dry-run] [--no-pauses] [--no-fillers]
                  [--min-pause 0.8] [--compress-to 0.3] [--max-gap 3.0]
                  [--filler-lang auto|en|zh] [--fillers a,b] [--trim-chapter-starts]
cut match  <proj> [--src <srcId>] --query <text> [--regex] [--whole-word]
                  [--scope match|para] [--action cut|keep] [--dry-run] [--note "…"]
cut add    <proj> [--src <srcId>] (--start A --end B | --words wA..wB) [--note "…"]
                  # --start/--end are source times for that source; the --view switch makes them view time
cut restore <proj> <cutId,…|--all> [--src <srcId>]
cut list   <proj> [--src <srcId>] [--kind silence|filler|badTake|manual|match|offScript] [--map]
cut script <proj> --script <file> [--src <srcId>] [--take last|first] [--snap <秒>] [--dry-run] [--report <path>]   # since 1.291.0
```

- Everything operates on a **source**: default `--src main`. `restore` takes a **cutId** (the old behaviour of taking a clipId ended with the separation of the two layers). cutId/clipId accept a unique prefix (§5.2 id resolution rules, no name layer).
- Silence and fixed filler detection are local pure functions. badTake and context-dependent fillers are produced by the LLM cleanup stage (`task start cleanup` / `auto --rough-cut`, provenance written to `ai/cuts.json`). The rule that the CLI never calls an LLM is unchanged.
- The receipt includes the affected surface: `{cut: {t0,t1,removedSec,snapped}, cutId, affectedClips: [c1], viewDuration}`.
- **Post-transaction stale scan in the receipt** (where §4.2 rule 3 lands): all commands that change subtitle visibility (cut add/restore/detect/match, clip add/trim/remove, source remove) attach `staleTranslations: {lang: ["srcId:sentenceId", …]}` to a successful receipt, and write the targeted retranslation command into the envelope `next`. Both are omitted when there are no stale entries.

## 5.2 `ccut clip` (timeline layer: orchestration) and element commands

```
clip list       <proj>            # id · source/view interval · timeline position · word summary
clip split      <proj> (--at <tl秒> | --word <wordId>)
clip add        <proj> (--file <path> | --src <srcId>) [--in A --out B]   # in/out are view time
                       [--after <clipId> | --before <clipId> | --at-end]
clip move       <proj> <clipId> (--after <clipId> | --before <clipId> | --to <n>)
clip trim       <proj> <clipId> [--in A] [--out B]                        # view time
clip set        <proj> <clipId> --rate <factor>                           # 1 original speed, 2 double speed
clip remove     <proj> <clipId,…>          # real delete; reversible via undo/history
clip transcribe <proj> --src <srcId,…> [--model …] # batch attach source transcription → transcripts/<srcId>.json

source list     <proj>                     # source list: reference counts, transcription/cut status
source remove   <proj> <srcId> --yes       # delete source: cascades to delete the cuts inside the source (decision 10),
                                           # lists affected clips/elements and requires confirmation; orphaned transcript files are flagged explicitly
```

Batch `clip transcribe` reuses the Qwen/Whisper ASR, VAD and aligner instances within the command's lifetime, and the stream processor resets the VAD state at the start of each source. This is an in-command optimisation and does not introduce a resident model process. Each source is still written as an independent history transaction, and the Studio projection is refreshed once after the whole batch ends. MOSS is a controlled exception: to avoid having the ~1.7GB speaker model and the ~0.9GB word-level aligner resident at the same time, it releases, refines and reloads per source. On low-memory devices, the peak memory upper bound takes priority over this engine's batch start-up speed.

**`ccut element`** (unified element surface):

```
element list   <proj> [--role broll|watermark|screentext] [--track <id>]
element add    <proj> --kind text|image|video|audio
               (--text "…" | --file <path> | --src <srcId>)
               [--start A --end B|none | --at-word wA[..wB]]
               [--track <id>] [--role …] [--rect "x,y,w"] [--mode …] [--fit …] …
element set    <proj> <elId,…> [--x --y --w --scale --rot --opacity --start --end
               --grayscale --blur --brightness --mask --volume --muted --hidden
               --text --name …]                 # whole batch in one transaction; flags validated against the per-kind capability matrix
element remove <proj> <elId,…>                  # whole batch in one transaction; if any selector fails, nothing is written to disk
element style  <proj> (--id <elId> | --role … | --all-text)
               (--apply <styleId|name> | --patch '{json}' | --save <name> | --refresh)
               [--force-size]                   # default does not change font size (preserves screentext OCR font size)
```

**Facade commands** (skill parity regression; same underlying element/cut/clip implementation):

```
broll add|update|remove|list|suggestions|preview   # update/remove accept <elId,…>; add defaults: image 4s pip / video ≤8s fullscreen
watermark add   (--text "…" | --file <img>) [--tile on] [--style …] [position default 85,10,22 / opacity 0.6]
screentext scan|add|show|translate|set|insert|apply|list|clear
animation list|show|apply|clear|preview|save|saved|forget
frames <proj> (--at t[,t…] | --start A --end B [--count N]) [--size N] [--tile]
```

The facade only injects role, track and product defaults. B-roll and element time windows, display and common patch, watermark and element display parameters, and B-roll and animation preview parameters all come from the shared clap flatten structure. The `ccut spec` tests compare field by field, to stop the facade from evolving independently into a second protocol.

ID resolution order is uniform: exact id → unique prefix → unique name, otherwise `ambiguous`.

## 5.3 serve edit transaction: `POST /<id>/__ccut/timeline/apply`

AI-suggested per-item accept / ignore / revert (`Command::Review`, `POST /__ccut/review/apply`) has a separate review write path, see [`ccut-talking-head-cut-design.md`](../../editor/ccut-talking-head-cut-design.md) §7.2.

Interactive editing cannot spawn a child process for every operation. Add a new transaction endpoint parallel to `transcript/apply`:

```jsonc
{ "baseRev": 7, "label": "剪掉口误",
  "ops": [
    // —— media layer (soft delete, acts on cuts) ——
    { "kind": "cutRange",   "srcId": "main", "start": 12.4, "end": 13.1, "note": "…" },
    { "kind": "cutWords",   "srcId": "main", "first": "g42.0", "last": "g43.2" },
    { "kind": "restoreCut", "cutId": "cut-2" },
    { "kind": "retimeCut",  "cutId": "cut-2", "t0": 12.2, "t1": 13.1 },   // 1.303.0: change interval in place; id and origin unchanged
    // —— timeline layer (orchestration; removeClip is a real delete) ——
    { "kind": "splitClip",  "at": 30.0 },
    { "kind": "addClip",    "srcId": "src-a1", "in": 2, "out": 8, "after": "c1" },
    { "kind": "moveClip",   "clipId": "c2", "before": "c1" },
    { "kind": "trimClip",   "clipId": "c2", "base": [2, 8], "set": [2, 6.5] },
    { "kind": "removeClip", "clipId": "c2" },
    // —— elements and main picture ——
    { "kind": "addElement", "track": "text", "element": { /* §3.6 */ } },
    { "kind": "patchElement", "elId": "el-2", "base": { /* values as seen */ }, "set": { "place": { "x": 40 } } },
    { "kind": "removeElement", "elId": "el-2" },
    { "kind": "setMain",    "set": { "muted": true } }
  ] }
```

- Semantics are fully isomorphic with `transcript/apply`: `baseRev` optimistic lock (mismatch → 409 `stale`), `.ccut/lock` short hold (conflict → 423 `busy`), per-op base validation goes into `skipped[]` (`reason: "base-mismatch"`, **HTTP is still 200**, so clients must check `skipped[]` to detect lost writes). On success: an in-process `refresh()` projection, `rev+1`, and a `.ccut/history` journal entry (`timeline.json` goes into the history store, so **the undo/redo/history endpoints cover editing unchanged**, and truly deleted clips are reversible this way);
- Base validation rule: `base` is a sparse subset, and only the keys appearing in it are compared. Objects recurse; arrays must be the same length and match element by element. **Numbers are compared by value, not by JSON representation**: `50.0` in the on-disk `timeline.json` and `50` emitted by the client via `JSON.stringify(50)` are considered equal, so the client need not deliberately preserve decimal representation to hit base. Other scalars use strict equality;
- There is also a whole-document op `replaceTimeline {document}` (added in v0.5): it atomically replaces the entire timeline.json, for clients that have not yet split into fine-grained ops and need to submit the whole thing. The current Mac editor uses this op (converting to fine-grained ops is a registered gap in §11);
- Transactions containing visibility-changing ops (cutRange/cutWords/restoreCut/retimeCut/addClip/trimClip/removeClip/replaceTimeline) return `staleTranslations` in the response (same receipt semantics as §5.1), so the frontend can guide targeted retranslation on the spot;
- The Studio frontend and the Mac App editor both go through this endpoint. Agents and scripts go through the CLI batch surface of §5.1/§5.2. Both channels share the same `ccut-timeline` transformation implementation, and two separate sets of semantics are forbidden. The Studio-side clip editing UI has not yet landed (see §11). Currently the frontend only consumes the projection for segment-jump playback and translation edit routing.

### 5.3.1 Command-line batch editing and dry run (`1.281.0`)

Current state (2026-09-28): the three old endpoints, such as `/timeline/apply`, were merged into `POST <project>/__ccut/edit/apply` in `1.160.0` (`EditBatch`: `channel` takes `timeline` / `transcript` / `style`). The op shapes and semantics above are unchanged. [Agent editing gaps plan](../ccut-agent-editing-gaps-plan.md) G2 adds three things to it, none of which adds new ops or changes op semantics:

- **Command-line entry** `ccut edit apply <project> --file <ops.json|->` (parameters in [reference `ccut edit`](../ccut-cli-server-reference/06/ccut-edit.md)). It is the same execution body as serve / App / `Command::EditApply` (`ccut-kernel::kernel::edit::apply_locked`: project lock → `cancelJob` recheck → undo stack → `ccut-workspace::apply`). An agent submits a batch of ops in one file, all-or-nothing and undone in one step, without one child process and one undo per command.
- **Dry run** `dryRun`: `preview_timeline` / `preview_transcript` / `preview_style` in `ccut-workspace::apply` share op dispatch with the real run and stop before the first write to disk (no capture of side-channel changes, no journal write, no projection refresh). The timeline channel applies ops one by one and collects all rejected ops (`rejected[{index, failure}]`). The transcript channel applies sequentially on the same draft and stops at the first rejected op. A dry run with zero ops only reads the current version.
- **Op registry** `ccut-workspace::edit_ops`: fields, types, required flags, enums and defaults of the 31 ops across the three channels, emitted by `ccut spec edit`. Numeric fields' `type` / `range` / `unit` / `timeBase` use the same `NumParam` as the command-line numeric parameters (`ccut_protocol::param`), and the same quantity shares constants at the top of `edit_ops` with the command-line parameter. Tests scan the dispatched op names from the source of `apply_timeline_op` / `stage_inline_op` / attached-source routing / exclusive op branches, pin them equal to the registry, and for each op run "minimal legal input passes, missing required field is rejected".

The write choke point for timelines is `ccut-workspace::timeline::commit_timeline_opts(project, timeline, label, history, &WriteOptions{dry_run, base_rev, label})` (`mutate_timeline_with` is its read → modify → commit wrapper). It also records the post-write version into a thread-local slot, and the CLI envelope takes it out before output and writes it into `data.rev`. So every command that writes `timeline.json` through this choke point (`clip` / `cut` / `element` / `template apply` …) carries the version automatically, without each command handwriting it. `project undo` / `redo` / `restore`, and `reframe` (which swaps the video source and mixes the dub), do not go through this choke point, and each records a version on the spot. To add `--dry-run` / `--base-rev` to these commands later, one only needs to add the parameter on clap and pass it into `WriteOptions`.

## 5.4 Playback and preview

- Extend the serve media endpoints by srcId: `__ccut/media?src=<srcId>`; `filmstrip`/`thumb`/`waveform` work the same way;
- The preview player (Studio / Mac App AVPlayer) reads `views` + `clips` from `studio/data.json.timeline` to perform **playback-time jumps**: within a clip, seeking across a cut segment jumps to the next kept segment (a tolerance absorbs jitter, aligned with the legacy `cutEnd(containing:)`), and the source switches at clip boundaries. Overlays go through the overlay endpoint in §6.5; **preview and export come from the same sampling kernel** (carrying forward the zero-drift decision).

```

  ├─ cuts.rs                   cuts set invariants, merge, restore, media view
  ├─ arrange.rs                clips: split/trim/move/add/remove, prefix sums, valid windows
  ├─ map.rs                    §2.3 full-chain mapping + seamBias + clampEvent
  ├─ words.rs / anchors.rs     WordSpan settling, word anchor evaluation
  ├─ elements.rs / motion.rs   element and playback-time motion sampling
  └─ schema.rs                 serde model + validation
core/crates/ccut-editable/     builder.rs + capcut.rs + interchange.rs (pure functions that output bytes/file plans)
core/crates/ccut-kernel/src/cmd/timeline.rs + cmd/timeline/   cut/clip/source/element/animation facade and transaction split
core/crates/ccut-kernel/src/services/timeline_media.rs / timeline_translation.rs
core/crates/ccut-kernel/src/services/export_registry.rs / editable_export.rs / legacy_edit_migration.rs

skills/cuccut/templates/studio/timeline-*.js   frontend mapping twin
```

Three-end consistency is pinned by contract fixtures (following the `subtitle-render-contract.json` pattern): `timeline-map-contract.json` covers the boundary cases of the mapping function (view seam, tolerance, clip emptied out, multiple sources, asset reuse, speed change).
