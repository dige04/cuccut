# 4. Directory layout and versioning

> From [CucCut file-contract subtitle AI pipeline design (File-Contract Pipeline, v0.3)](../ccut-file-contract-subtitle-ai-design.md)

All intermediate artifacts live under the project package `ai/` (already on the project directory allowlist):

```
ai/
  context.md                  Currently valid source-language summary and glossary (stable path, read directly by consumers)
  context.zh.md               Currently valid target-language context (summary translation, bilingual glossary, style)
  state/
    translation.zh.json       Translation provenance (§11.3), without the translated body text
  brief/v001/…                Archived history of context versions (includes manifest.json)
  polish/v001/
    manifest.json             Fingerprint, model, parameters, page table, status
    input.txt                 Full-text snapshot (includes soft markers, for auditing)
    pages/p001.src.txt        Page input (core region + read-only context on both sides)
    pages/p001.out.txt        LLM output (retry round: p001.out.a2.txt)
    merged.txt                Full text after fence removal and merge (final polished segments)
    report.json               Per-page similarity, fallbacks, local re-polish records
  translate/zh/v001/
    manifest.json
    source.html               Full-text sentence-level HTML
    pages/p001.src.html / p001.out.html
    merged.html               Merged bilingual side-by-side (for auditing and preview)

  align/zh/v001/
    manifest.json
    round1.src.html / round1.out.html

    report.json               Per-sentence acceptance results
    fallback.json             Deterministic fallback list (absorbs ai/align-fallback-<lang>.json)
```

## 4.1 Versioning rules

- Each time the **user explicitly reruns** a stage (re-polish, re-translate, re-align), a new `v002/`, `v003/`, … is created in that stage's directory. Incremental resumes (after fingerprint checks mark stale parts, only the stale parts are rerun) **reuse the current version directory** and append a run record to the manifest. **M1–M4 implementation decision: the reuse branch is not implemented.** `ArtifactWriter::open` always opens a new directory at `max_version + 1`, so incremental resumes also open a new version (§17).
- Stage directories hold no "current" pointer. **The currently effective version = the highest version number whose manifest has `status: done` and whose `inputFingerprint` matches the current transcript fingerprint**, derived by code. The pointer is not persisted either, for the same reason as "page boundaries are not persisted." `context*.md` is the only exception: they are the stable paths for the "currently valid copy," and they are atomically replaced when analysis reruns. Historical archives go under `brief/vNNN/`.
- **Retention policy:** by default, the full artifacts of the most recent 3 versions are kept, plus `manifest.json`/`report.json` for all versions (small and high in audit value). For older versions, `pages/` and `input.txt`/`source.html` are cleaned up by `ccut ai clean --keep N`. Everything under `ai/` is a recomputable audit artifact, not project truth. Stale artifacts may be used for diff/traceback, but they must not be automatically written back to the transcript again.

## 4.2 Manifest semantics (two boundaries must be stated clearly)

```jsonc
{
  "stage": "translate", "lang": "zh", "version": 3,
  "protocolVersion": "file-v1",                       // Renderer/parser protocol version
  "inputFingerprint": "1024:g1.0:g88.4:ab12cd",
  "parents": { "context": "v001", "polish": "v002" },
  "model": "provider:anthropic/claude-sonnet-5", "params": { "fit": 16 },
  "pages": [ { "id": "p001", "status": "done", "attempts": 2, "src": "...", "out": "..." } ],
  "runs": [ { "at": "...", "kind": "full" }, { "at": "...", "kind": "stale-only", "sentences": 12 } ],
  "status": "done"
}
```

**M1–M4 implementation decision:** the fields landed in `manifest.rs` match the table above, with two additions. Each item in `pages[]` additionally carries `problems: Problem[]`, which keeps per-page protocol problems on record for auditing. `protocolVersion` is hard-coded to `file-v1` by `Manifest::new`, and `protocol_supported()` also accepts only `file-v1`. In other words, **the manifest currently cannot express `json-v0`**: the json-v0 path never writes a manifest, so the "two protocols sharing one manifest" in §9.6 holds only on the claim envelope side.

- **The `pages` table is an audit record, not the authority for resuming.** On resume, pages are deterministically reprojected, and units whose checkpoint is "fresh" are skipped. After the paging parameters change, the old page table becomes naturally invalid and is never misread.
- **The document-level `inputFingerprint` answers only "can people or Agents reuse this file artifact directly?"** (the audit layer). The sentence-level incremental criterion is still `transSrc`: changing one source sentence retranslates only that sentence, and a mismatch in the document-level fingerprint does not invalidate the whole version. The checkpoint unit for each stage: analysis → page notes, polish → accepted source word patches, translate → sentence id, align → sentence id.
