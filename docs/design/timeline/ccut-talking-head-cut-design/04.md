# 4. Data Model

> From [CucCut talking-head cut design (prototype rounds 192–197 → core / serve / App v2 / Web)](../ccut-talking-head-cut-design.md)

## 4.1 Cuts: prototype fields → real destinations

| Prototype `cut` field | Destination | Notes |
|---|---|---|
| `id` | `cuts[].id` (`cut-<n>`) and `ai/cuts.json.entries[].id` | `next_id("cut-")` |
| `start / end` | `cuts[].t0 / t1` | Source-clock seconds (the prototype used timeline seconds with `srcStart` conversion; the real product uses source time directly) |
| `kind` | `entries[].kind` (closed set) + new `entries[].category` | `pause → silence`, `take → badTake/retake|falseStart`, `repeat → badTake/repeat`, `filler`, `manual` |
| `text` | Derived: `wordIds` → current `words[]` text; for pauses, `detail` (`1.4s → 0.3s`) | Text is not stored; words are the source of truth |
| `why` | `entries[].reason` | Already exists |
| `state: 'cut'` | Present in `cuts[]` | `restoreCut` removes it |
| `by` | Derived from `entries[].origin`: `manual → you`, `detect|cleanup → ai`; new `entries[].via: "app"|"cli"|"agent"` distinguishes `agent` | `via` is set by the writer (App/Web write `app`, direct CLI runs write `cli`, CLI inside an agent session writes `agent`, based on whether the `CUCCUT_AGENT_SESSION` environment variable is present) |
| `batch` | New `entries[].batch: <jobId>`, inherited from the review item when a suggestion is accepted | Manual cuts have no `batch` |

The optional new fields `category / via / batch` in `ai/cuts.json` are not migrated for old files. `append_cut_provenance` merges by id with deduplication, so the write strategy does not need to change.

## 4.2 Suggestions: `ai/reviews/cleanup.json` v5

```jsonc
{
  "reviewVersion": 5,
  "kind": "cleanup",
  "status": "pending",                     // derived: any pending item → pending; otherwise settled
  "batch": "job-20260907-1432",            // scan job id for this round (serve job id or a ulid generated by the CLI)
  "baseWordsFingerprint": "812:g1.0:g88.4:1k3z9x",  // fingerprint(words); replaces baseTranscriptSha
  "createdAt": "...", "updatedAt": "...",
  "params": { "strength": "standard", "minPause": 0.8, "compressTo": 0.3, "maxGap": 3.0, "fillerLang": "auto" },
  "items": [
    {
      "id": "sug-1",                        // stable within this file; renumbered on each new scan
      "category": "filler",                // filler | pause | retake | falseStart | repeat
      "kind": "filler",                    // closed provenance kind: silence | filler | badTake
      "srcId": "main",
      "firstWordId": "g3.0", "lastWordId": "g3.2",   // for pause, both are the same = afterWord
      "t0": 12.41, "t1": 13.22,            // source clock; for pause, the range to cut after compression
      "reason": "句首口癖", "detail": "嗯，就是，",   // reason: sentence-initial filler habit; detail: filler words "um, like,"
      "alternative": null,
      "state": "pending",                  // pending | accepted | dismissed
      "cutId": null,                       // written as cut-<n> when accepted
      "decidedAt": null
    }
  ],
  "artifact": { /* CleanupArtifact 原样保留，供 lint 与审计 */ }
}
```

**Derivation rules on read** (`ccut-editor-core::cut_mode::effective_state`, a pure function, input `item + CutSet`):

1. `accepted` and `cutId` not in `cuts[]` → treated as `pending` (C4).
2. `pending` and `[t0, t1)` intersects `CutSet` (`contains_cut_range`, tolerance 0.01) → treated as `superseded` (overridden by a manual cut; not shown, not counted, goes to `skipped` on accept).
3. Otherwise follow `state`.

**Upgrade**: when reading a file with `reviewVersion: 3`, map it as a whole by `status` (`pending` → all `pending`; `accepted` → `accepted` for items in `applied[]`, the rest `dismissed`; `rejected` → all `dismissed`), and bump to 5 on the first write-back. `CLEANUP_ITEMS_REVIEW_VERSION = 5` (`review/cleanup_items.rs`) applies only to `cleanup`; `broll` still uses `ACTION_REVIEW_VERSION = 3` (the two kind branches).

## 4.3 Invariants and lint

- The cut invariants carry over from `ccut-edit-domain-design.md` §3.10 (ordered, non-overlapping, `clip-empty-after-cuts`, `cut-mid-word`, `cut-no-provenance`, etc.) and are not extended.
- New review lints (reported by both `ccut review lint` and `ccut lint`): `review-item-orphan-word` (`firstWordId/lastWordId` no longer in `words[]`, so the item is invalid), `review-fingerprint-stale` (`baseWordsFingerprint` ≠ current; the whole suggestion set is marked stale, and the UI shows “文稿已变化，建议可能过时 · 再找一遍” (Script has changed; suggestions may be outdated · Find again), but it **does not block accepting** items that have not gone invalid).
- `pending` items must not overlap one another (guaranteed by the generation-side `merge_proposals`; the read side no longer validates this).
