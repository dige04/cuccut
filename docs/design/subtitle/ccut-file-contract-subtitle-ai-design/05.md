# 5. Stage 0: analysis — summary and glossary

> From [CucCut File-Contract Subtitle AI Pipeline Design (File-Contract Pipeline, v0.3)](../ccut-file-contract-subtitle-ai-design.md)

Polishing and translation share the same reference material. It runs before any LLM editing stage.

## 5.1 Artifact format

`ai/context.md` (source language; replaces `summary/terms/namedEntities` in `ai/brief.json`):

```markdown
---
fingerprint: "1024:g1.0:g88.4:ab12cd"
referenceFingerprint: "…"
---
# Summary
（整体摘要：题材、语域、说话人角色、文风要求）
# Canonical Terms
| Source | Category | Variants | Note | Lock | Origin |
|---|---|---|---|---|---|
| CucCut | product | 宝卡特, 包卡 | Keep English casing | yes | user |
| KV cache | tech | KV 缓存 | Translatable on first use; keep consistent afterwards | no | analyzed |
```

`ai/context.<lang>.md` (target language; replaces `ai/brief-<lang>.json`. **All of its fields must be preserved**: `tone`/`styleGuide` go into `# Translation Style`, `difficulties` go into the free-form notes section, and `analysisFingerprint`/`instructionsFingerprint` go into the frontmatter):

```markdown
---
targetLang: zh
fingerprint: "…"
analysisFingerprint: "…"
instructionsFingerprint: "…"
---
# Translated Summary
# Bilingual Glossary
| Source | Target | Note | Lock | Origin |
|---|---|---|---|---|
| CucCut | CucCut | Keep the product name in English | yes | user |
# Translation Style
```

Format conventions:

- **Table headers are in English** (machine contract; multilingual models are more stable with them). `Category` is a closed set: `product / person / tech / proper / other`. An unknown category fails lint.
- **Variants must be misrecognitions that actually appear in the body text. Fabrication is forbidden** (anti-hallucination clause, included in both the prompt and the validation notes).
- **The `Lock` + `Origin` column pair replaces the separate user glossary file**: one table carries both user entries (`Origin=user`) and model entries (`Origin=analyzed`), so users see the final effective result in the same table and no third merged view is needed. Priority: `Origin=user` with `Lock=yes` > `Origin=user` > `Origin=analyzed`.
- **Rebuild rules**: rerunning analysis overwrites the `Origin=analyzed` rows of the whole table. `Origin=user` rows are kept one by one and must not be deleted or rewritten. translate-brief only translates rows with no Target yet ("尚未有 Target"), and locked rows are carried over verbatim. **If glossary parsing fails, keep the previous verified context; never overwrite it with an empty table.**
- **CJK-context punctuation normalization (deterministic cleanup on the engine side)**: `Translated Summary` and `Translation Style` are normalized in the same way at two points: acceptance-time persistence, and the `context.<lang>.md` → brief conversion. An ASCII `,` `:` `;` whose immediate neighbouring character is a CJK word character is replaced with `，` `：` `；` (`3,000`, `10:30`, URLs and pure English text are unaffected. `.` is not mapped, since file-name and abbreviation ambiguity cannot be resolved from the neighbouring character). Rationale: these two fields are echoed verbatim into the translate system prompt, and half-width punctuation in the style guide would spread through the whole translation (file-v1 baseline zh-Hans had 14 half-width commas/colons vs 0 in the json-v0 baseline). The cleanup is idempotent, and leftover residue in stored data is likewise covered on the conversion read side. Glossary `Target`/`Note` are not cleaned (the locked `rt` chain requires verbatim, byte-for-byte carry-over). The json-v0 brief acceptance uses the same rule.

## 5.2 Connection to the current locked pipeline (not a format port, but a pipeline migration)

The current user-lock channel is `GlossaryEntry.locked` in `ai/brief-<lang>.json`, and downstream it has four hard constraints: locked entries → the `rt` (required targets) in the translate payload → `validate_translated_page` marks the page Malformed when targets are missing → `lint_agent_answer` re-checks with the same logic → `check` reports `missingTargets`. Migration requirements:

1. `Lock=yes` rows continue to compile into the `rt` set, and the four downstream links stay connected as they are;
2. Existing entries with `locked=true` in `ai/brief-<lang>.json` are converted to `Origin=user, Lock=yes` rows during the first migration;
3. Currently no CLI subcommand edits terms (users hand-edit the JSON), and the Markdown table itself becomes the new user interface. The `ccut glossary lock/set` subcommands are listed as an optional M4 item, not a requirement. **M1–M4 implementation decision: not implemented** (optional; not taken in M4). Hand-editing `context*.md` is the only entry point.

## 5.3 Injection method

The contract for the polish/translate page does not inline the full glossary. The renderer filters out and inlines **only the glossary rows that match this page**. The page payload carries only relevant terms, and global consistency is guaranteed by the same table. **M1–M4 implementation decision**: the parenthetical "the agent path additionally gives the full `context*.md` in references" is **not implemented**. The `references` channel is not yet wired on either execution path (§9.2/§9.3), so the worker, like the provider, receives only the glossary rows that match this page.
