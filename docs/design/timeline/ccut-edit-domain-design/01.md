# 1. Background and Decision Baseline

> From [CucCut edit-domain protocol design (Cut / Clip / elements / watermarks / project export)](../ccut-edit-domain-design.md)

## 1.1 Pre-launch Leftover Issues and Current Closure

The first Mac App port deferred the whole edit domain. The old voice-ink cut/clip/broll/element/animation/watermark protocols were not reproduced directly and were left waiting for a redesign of the two-layer model. The gaps before launch were:

- The product project is **purely a transcript + studio projection**: `project.json` + `transcript.json` + the derived `studio/data.json`. The directory contains no composition document at all.
- The `hidden` word-override table only affects subtitle derivation. **No write path** can express "cut out this segment of video."
- `export --to mp4` only burns in subtitles (`SubtitleRenderPlan`). It does not skip cut segments and does not composite overlays.
- On the BCF side (`ccut-core`), clip `segment`/`loop`/`playbackRate`, the element tree, animation presets and word anchors `~` are all implemented, but they have only a one-way word-anchor bridge to the transcript world.
- Format specification [§18.6](../../bcf/cuccut-format-spec.md) already pre-set a normative inference: "Deleting a transcript passage ⇔ clip-splitting and removing the corresponding WordSpan … the text editor is the editor," but WordSpan has zero implementation on the Rust side.

These gaps are now closed by `ccut-timeline`, `ccut-editable`, the CLI/serve, Studio, the Mac adapter layer and the migrator. The list above is kept as design motivation; it does not describe the current state of capabilities. For the actual completed scope, see §9.

## 1.2 Decisions Ratified (2026-08-01)

| # | Question | Decision |
| --- | --- | --- |
| 1 | Source of truth for editing | **Lossless cuts at the media level + a new project-level `timeline.json`**. The BCF composition document is compiled on demand as a derivative and remains a consumer in the render domain |
| 2 | Relationship between Cut and Clip | **Two separate layers** (revised in v0.2): **Cuts belong to the media**. Each video/audio source holds its own lossless cut set (filler words / transcript-driven editing happens here), reversible at the data-model level. **Clips belong to the whole timeline**: ordered arrangement units that reference the "post-cut view" of a media item. They can be split, trimmed and reordered as a whole. Deletion is a **real deletion**, and reversibility comes from undo/history |
| 3 | Media view | Each media source presents itself externally as a **database-like view**. External time = the continuous time after folding the cuts. Subtitles (including word timestamps) are likewise presented in view time, "as if physically trimmed." Internal storage always keeps the true source time. Video is never physically trimmed |
| 4 | Scope of main-track material | **Full multi-source main track from the first release**: the data model and command surface support arranging additional material into the timeline from day one (aligned with the old version's M-clip) |
| 5 | Scope of project export | **All six targets at parity**: CapCut/JianYing, Premiere (FCP7 XML), Resolve (FCPXML/FCP7 XML), Final Cut Pro (FCPXML 1.9/1.10), Shotcut (MLT) and Kdenlive, all sharing one neutral OUTPUT timeline IR |
| 6 | Final MP4 | **Cut-skipping + full overlay burn-in**: folded according to the view/arrangement, subtitles retimed, and B-roll/elements/watermarks/animations burned into the picture through the shared Rust render kernel (the zero-drift principle carries over) |
| 7 | Watermarks | **A text watermark is a role-derived text element**; an image watermark is an image element. **HTML watermarks are no longer supported**. Old projects' HTML watermarks are mapped to image elements on migration, using their rasterized output, and the original `html` source is discarded |
| 8 | B-roll | **Simply image / video elements**, with no separate data type. `broll` is kept only as a facade in the command surface and as an element role annotation |
| 9 | Animation | **Reuse the BCF animation model** (preset + keyframes as pure data, a closed set of easing enums, expanded at compile time). The old preset vocabulary is mapped into the BCF vocabulary |
| 10 | Where cuts live | **Encapsulated within the source** (revised in v0.3): `cuts[]` is an internal field of a video/audio source entry, not a top-level table. Deleting a source deletes its cuts with it. Each source's transcript (with real source timestamps) likewise belongs to the source. Physical files stay separate (`transcript.json` / `transcripts/<srcId>.json`) |
| 11 | Global subtitles and translation | **Global subtitles = a derived view** (revised in v0.3): content follows the source, presentation follows the timeline. Translations are stored in each source's transcript as `trans[lang][sentenceId]`, so trimming, joining, reusing or reordering material keeps all translations valid. Translation tasks assemble context by **timeline projection** and write back scattered by `(srcId, sentenceId)`. The sentence staleness fingerprint uses the **visible word sequence**. Edits to subtitles on the final output route back to the source's trans table. Style, subtitle tracks (since round 108 called `tracks`, formerly the display mode `mode`, now a derived value) and typesetting have their persistent source of truth in the project-level `studio/style.json`, projected into `studio/data.json.style`. "Subtitles" without a source (title cards, hand-written sentences over music segments) are not subtitles; they are text elements |

## 1.3 Legacy Inheritance: What to Keep, What to Correct

From the old voice-ink edit domain (`Sources/VoiceInk/Models/TimelineModels.swift`, `ElementModels.swift`, `Export/Project/*`), the following were validated as effective and are **kept** by this design:

1. **Lossless cutting**: a cut never touches `words[]`, so translation keys, stage stamps and undo are naturally stable. A word's cut state is **derived** from the word's midpoint. There is no word-level cut flag.
2. **Overlays are unified as elements on tracks**: `texts/broll/watermarks` had already converged in the late old version into a projection of `tracks[].elements[]`. The new protocol starts directly from the unified model.
3. **Element transforms use canvas-normalized coordinates (%)**: the frame size of the final output can vary at export time (16:9 / 9:16), so element positions must be independent of frame size. CapCut's transform is also a normalized model.
4. **Export must pass through the neutral OUTPUT timeline IR** (EditableTimeline): folding and window zeroing are completed once at the IR layer. Six writers and the subtitle sidecar consume the same result, so "picture / subtitles / sidecar never conflict."
5. **Two-layer persistence for animation**: the document stores only a preset reference plus a frozen version. It is compiled into keyframes at render time.
6. **Preflight blocker/warning code table** and the audit gate (B-roll landing in a cut zone, jump cuts, missing provenance, etc.).

**Corrected** items:

1. The old "Clip IS the Cut" design mixed cutting and arrangement into the same main-track partition. A cut was just a boolean flag on a clip, and cut segments still occupied timeline space. The new protocol **separates the layers**: cutting is a property of the media (source-level `cuts[]`, soft deletion, reversible), and arrangement is a property of the timeline (`clips[]`, real deletion, reversible through history). A filler-word cut is naturally "applied once to every use of this material," rather than "applied to one spot on the timeline."
2. The old clip stored three time values `{start, end, src}`, with `start/end` redundant with array order. In the new protocol, a clip **stores only the source time range. Its timeline position is derived from the prefix sum of array order** (aligned with BCF's single-source discipline of "deriving the cue table from the scene table," see §3.4).
3. The old elements could only anchor to timeline seconds, and ripple editing relied on manually shifting with a `mapTime` pivot point. In the new protocol, element times **support word anchors** (`~srcId:wordId`, reusing the BCF §5.2 grammar). "B-roll appears when the speaker says this word" becomes a format capability that follows automatically after cuts.
4. The old cut provenance lived outside in `ai/cuts.json`, and the skill documentation drifted from the code. Provenance still goes through `ai/cuts.json` (at the same level and with the same audit status as other AI stage outputs), but the entry schema is moved into the body of this protocol (§3.8) and made self-describing via `ccut spec`.
5. The old `source:"html"` watermark was cancelled per decision 7.
6. The old `screentext` relied on an implicit synthesis convention that it "must live on the `tr-text` track." In the new protocol, track semantics are made explicit (§3.6), with no hidden ordering rules.
