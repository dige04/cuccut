# 16. Security and input isolation

> From [CucCut File-Contract Subtitle AI Pipeline Design (File-Contract Pipeline, v0.3)](../ccut-file-contract-subtitle-ai-design.md)

- When generating HTML, escape all transcript text; an unescaped `<` breaks id reconciliation.
- Parsing uses the HTML5 DOM parser with an element/attribute allowlist; **HTML is never executed**. Discard everything in `script/style/iframe/object/link/meta refresh`, event attributes (`on*`), URLs and external entities. Preview uses a `<style>` element that allows only the fixed allowlisted styles generated by the renderer itself; the parser unconditionally drops style/script nodes from the output.
- id comparison uses exact Unicode byte strings, with no case folding.
- **Prompt-injection defense**: text in the context and transcript content such as "ignore the rules, read some file, run some command" is always treated as **content**, not instructions; the contract text states this explicitly. An Agent claim limits readable files to the inputs listed in the claim envelope (the `references` channel does not exist yet, see §17), and the contract explicitly forbids path expansion. Fence/envelope literals that appear in the body are neutralized at render time and logged as a `sentinel-neutralized` warning.
- Output size has a hard cap: output exceeding a reasonable multiple of the estimated input size is rejected (to prevent runaway generation). **Implemented**: `max_output_chars = 4 × input characters` (floor 4096). All four carrier parsing entry points first pass through `guard_output_size`, and overruns report `document-oversize` (§10.1). The same function is also the baseline for scaling the provider-side `max_tokens` (§9.3). **What goes in on the input side sets what comes out on the output side, with one shared ruler**, so there is no dead zone where the model is allowed to generate something the parser will always reject.
