# 8. Stage 3: Alignment (HTML table contract)

> From [CucCut File-Contract Subtitle AI Pipeline Design (File-Contract Pipeline, v0.3)](../ccut-file-contract-subtitle-ai-design.md)

## 8.1 Send only question sentences, four-tier classification (consistent with both reference designs, not a point of disagreement)

Overlength detection is deterministic code; the LLM never takes part in detection. The four current conditions are: `exceeds_one_line_fit` (width exceeds one line), `target_cps_chars > hard` (reading speed exceeds the hard cap), dwell time over 7s (`LONG_DWELL_SECONDS`), and the source-side time window of a paired line exceeding its limit (`whole_sentence_source_ceiling_issue`, threshold `PAIRED_SOURCE_MAX/HARD_SECONDS = 4/6 s`. This is a **time-window** check, not a source-text length threshold). Note that "all four conditions false" means zero LLM calls, but in projected mode whole-sentence `TransAlign` entries are still written (non-zero writes).

On this basis, all sentences are split into four tiers:

| Tier | Handling |
|---|---|
| Pass | Not put in the table |
| Safely handled by the deterministic splitter | `split_independent_for_lang_protected` splits directly, zero LLM |
| Needs semantic splitting | Goes into the LLM table |
| Configuration blocker (e.g. **a locked term itself exceeds hard**) | Report a blocker; **never hard-split in the middle of a term**; this is one of the loop's termination conditions |

**Color marking is demoted to a human/agent preview aid**: the protocol signal is only one: every sentence appearing in the table needs handling. Styling is separated from semantics, and the parser does not look at class. **M1–M4 implementation decision: the inline preview `<style>` was not built, and this is intentional.** §16 requires the parser to unconditionally discard style nodes, and the commit-time lint after `data-soft` must round-trip parse the **persisted HTML**. An inline style would consistently produce a false `node-dropped` warning on every round trip. Visualization is left to external preview tools and does not go into the payload.

## 8.2 Rendering

Packing is constrained only by **source word count**: at most 8000 source words per page, Latin counted by word, CJK counted by character. Sentence count, HTML/JSON serialized size, fixed-point vs. full mode, and worker slot count do not change the page shape.

```html
<table data-lang="zh" data-fit="16" data-soft="18" data-hard="20" data-ccut-format="align-table/1">
  <tbody data-sid="s-g1.0" data-max-lines="2" data-budget="每行≤16字，建议2–3片">
    <tr><th rowspan="1" scope="rowgroup">s-g1.0</th>
        <td class="src">Ninety days, eight times the growth, and we did it without any paid marketing.</td>
        <td class="tgt">九十天翻了八倍，而且我们没有花一分钱做付费营销就做到了。</td></tr>
  </tbody>
</table>
```

Attribute inventory (`align_table.rs` implementation, rendering and parsing are symmetric):

| Location | Attribute | Meaning |
|---|---|---|
| `<table>` | `data-lang` / **`data-source-lang`** / `data-fit` / **`data-soft`** / `data-hard` / `data-ccut-format` | Target language, source language, the three `TransParams` thresholds, and format version |
| `<tbody>` (sentence group) | `data-sid` / `data-max-lines` / `data-budget` | Sentence id, maximum line count, relative budget text |
| `<tbody>` (model-writable) | `data-unsplittable` / `data-reordered` / `data-crossing` | Unsplittable exit, rewrite declaration, residual word-order crossing (§8.3) |
| `<tbody>` (engine-written, model read-only) | `data-no-rewrite` | Marker for the paired re-split round: the translation is already accepted, only the split points may be reselected. Like `data-target-frozen`, it disables `data-reordered`, but does not constrain piece text |
| `<tbody class="ctx">` | no `data-sid` | Read-only context row |
| `<th>` | `rowspan` / `scope` | Redundancy check |

- **`data-soft` is an addition beyond the v0.2 attribute list (M1–M4 implementation decision)**: the commit-time lint only has access to the persisted payload HTML, so `parse_align_table_input` must be able to fully restore `TransParams` (all three values fit/soft/hard feed the seam criteria in `lint_pieces`) in order to recompute exactly the same set of criteria as the engine. Without `soft`, the default would have to be guessed, and a wrong guess means two different validators, which is exactly what §2 is meant to eliminate.
- **`data-source-lang` is likewise an addition (2026-09-28)**: the contract allows a split on `、` when the source lines are too dense and both neighbors are complete parallel actions. The json-v0 acceptance and `ccut check` have long exempted this via `allowed_balanced_list_seams`, but the align-table commit-time lint missed this rule and reported it as `align-illegal-seam` like an ordinary list (Shorts acceptance C6). The exemption must measure the combined width of two adjacent source lines against the **source language** single-line budget. The payload carries no word timing, so only the width half is taken (`allowed_list_seam_indices_for_source_rows`), and the source language round-trips with the payload. A legacy payload that lacks this attribute is budgeted against the Latin source language.
- The source cell is the whole-sentence source text (visible word order concatenated). No pre-splitting, no exposed word ids, no exposed source Cue boundaries, and **the model is not allowed to pick `b7` candidate break ids** (the model only splits text; the program maps it back).
- `data-budget` carries only relative budgets: fit/soft/hard, plus a suggested piece count converted from dwell seconds. Absolute timestamps do not enter the payload.
- If the source column carries pause soft markers, the file carrier uniformly uses the `markers::pause_marks` threshold set (0.6/1.0/1.8 s). The align-side private `pause_tier` is still used for pause metadata on draft tokens, but does not participate in paging. Private tiers must not cross into the file carrier (§13.1).
- Context: the sentence before and the sentence after are attached as read-only `<tbody class="ctx">` rows (no data-sid). **M1–M4 implementation decision: the carrier is implemented, the engine is not wired up.** When `align.rs` builds the request, `context_before`/`context_after` are always empty vectors (§17).

## 8.3 Output: `tbody` grouping, pieces 1:1 per row, rowspan only for redundancy checks

The model splits one sentence into N rows, **each row = one target piece + the corresponding contiguous source span** (1:1):

```html
<tbody data-sid="s-g1.0">
  <tr><th rowspan="2" scope="rowgroup">s-g1.0</th>
      <td>Ninety days, eight times the growth,</td><td>九十天翻了八倍，</td></tr>
  <tr><td>and we did it without any paid marketing.</td><td>没花一分钱做付费营销。</td></tr>
</tbody>
```

- Splitting both columns in sync is mandatory: `pieces[].from/to` need each piece's contiguous source word range for time anchoring. The canonical order is unchanged: first decide the split from translation naturalness, then cut the corresponding source segments.
- **rowspan appears only in the id column `<th>`, and its value must equal the number of rows in that group.** It is a pure redundancy check (it catches model arithmetic errors) and carries no semantics. Data rows are always 1:1, isomorphic with the `pieces` data model. The design "rowspan on source/target cells to express N:1 sharing" is rejected, because the contiguous, non-overlapping, full-coverage structure of `pieces[]` cannot represent shared ranges.
- **Unsplittable exit**: when the source side truly has no split point, the model marks `data-unsplittable="true"` on the `<tbody>` (the semantic signal goes through the attribute, not inferred from grid shape). This follows the existing "deliberately no automatic fix" semantics: the whole sentence goes on screen, or independent proportional anchoring applies. **M1–M4 implementation decision**: `translation-unsplittable`, as written in v0.2, **is not an error code**. There is no such item in `ProblemCode`. Unsplittable is a normal exit: it does not consume the retry budget, is not in the §10.1 table, and is classified solely by the `data-unsplittable` attribute.
- **Translation rewriting**: rewriting the translation to eliminate word-order crossings is allowed, via `<tbody data-reordered="true">`. It passes the existing ±max(25%, 4 units) rewrite-magnitude guardrail, then is written back to the sentence-level `trans` (the apply layer guarantees that `trans` is written before `transAlign`). Residual word-order crossings are expressed with `data-crossing="true"` (corresponding to the existing `crossing` field; mutually exclusive with reordered). The existing position that rewriting is allowed is kept, and no translate-repair back-edge is introduced: it would add an extra cross-stage call, convergence is hard to prove, and under the round budget it is net negative.

## 8.4 Parsing, acceptance, and rounds

1. Group by `data-sid`. For each piece, align its source segment against the whole-sentence source text with a sequential cursor plus atom-LCS prefix alignment, and **snap to word boundaries** (a cut point not on a word boundary takes the nearest boundary and records a warning) → obtain each piece's `from/to`. The existing `sourceBreaks`/`useDraft` answer channel is retired together with this fusion.
2. Run each sentence through the existing acceptor: concatenation invariant, contiguous/non-overlapping/full coverage, each piece ≤ hard, and the `seam.rs` seam lint (dangling conjunctions, a trailing 的 particle, numbers+units spanning a seam, etc.).
3. **Non-regression check**: each row's source span, duration, and target density must not be worse than the worst input row. This blocks the pseudo-fix of "split into one ultra-short piece plus one that is still overlong."
4. **Hard round budget**: round 1, all problem sentences are paged at 8000 source words and run in parallel → round 2, failed sentences still generate targeted pages under the same 8000-word budget (1 round) → round 3, the deterministic fallback `split_independent_for_lang_protected` + `repair_lint_pieces` (never fails), recorded in `fallback.json` **and explicitly marked as a deterministic fallback**, not disguised as a model result. Total LLM rounds ≤ 2.
5. After each round, **the code re-runs overlength detection** to decide the next round's set. The model's self-reported completion is not trusted (`data-status` and the like are all ignored). Final success condition = the code scan reports zero executable hard defects + the blocker tier has been reported.

**M1–M4 implementation decision: under the file contract, `align-over-hard` / `align-illegal-seam` are downgraded to per-sentence advisories** (`problem_blocks_acceptance` returns `false` for these two codes). Rationale: they describe "this sentence was not split well enough," not "this document cannot be parsed." Letting them veto the whole batch would escalate one sentence's quality issue into a full table redo, which conflicts with the per-sentence accounting principle. These two codes still go into `report.json` and still drive the sentence set for targeted rounds. They just do not block acceptance of this batch.

**Sentences KeepWhole accepts but still over hard: save salvage first, then a targeted repair** (implementation addendum, 2026-08): when the worker submits a piece that is already over `hard`, and the engine's own deterministic re-split is abandoned because it would break paired readability (the `AcceptanceMode::KeepWhole` path), the answer is no longer committed on the spot. Following the same convention as polish's "accept on first round + targeted repair," that answer is stored in `salvaged` (it fills in as-is when the repair budget runs out, so the result is no worse than direct acceptance). At the same time, **only this one sentence** is sent into a repair round as a failure, together with the targeted explanation ("target segment k is N display units — over the absolute hard ceiling H … move a boundary … or declare `data-unsplittable="true"`"). Other sentences are accepted and landed as usual. Two exceptions are not sent back: if the worker has already self-declared `data-unsplittable="true"` (the contract is honored, accept directly), or the answer is a `data-reordered` rearrangement being written back (rescuing it would mean skipping the consistency precondition of the `trans` write-back, so the deterministic fallback is preferred). The round count remains subject to the hard budget in item 4 (one targeted `GLOBAL_REPAIR_CALLS` round). No new LLM rounds are added.

**Deliberately retained asymmetry**: the commit-time lint pushes the **full** `Problem` set (including the two advisory codes above) to the worker, so the worker may be asked to fix a defect the engine would itself accept. This is intentional. The worker has the whole-table context and fixing once is cheap, whereas the engine's leniency is an exit reserved for "still cannot be fixed in the end." The two have different goals (§13.1).

**Actionable hint for `align-over-hard`, and the only release valve** (2026-08, postmortem of 01a00494): under the bare message "piece N of X units exceeds hard," the worker would resubmit against the same piece over and over. The live case s-g109.20 had a legal split point at "，" yet still burned three lint tries before a force-through had the engine hard-split it mechanically. Now `check_rows` uses the strict legal splitter `split::legal_split_for_lang` (it cuts only at non-objective-error seams, keeps each piece ≤ hard, and makes no character-position hard cuts) to scout ahead for the worker. If a piece has a legal split backed by punctuation or whitespace, the detail directly gives “可切为“…”｜“…”” (can be split as “…” | “…”). If only CJK character boundaries remain, it gives “片内无标点/空白缝，请在词边界处切开” (no punctuation or whitespace seam inside the piece; split at a word boundary). The splitter has no dictionary, so it does not choose word boundaries for the worker. If the piece has no solution internally but the whole sentence does, it gives “片内无合法切点，需连同相邻片一起重切” (no legal split point inside the piece; re-split together with adjacent pieces), with the whole-sentence split attached. All three remain `Problem`s and are still rejected. **Sole release valve**: when no legal split exists for the entire target sentence (a giant Latin token, every seam an objective error), only `WarningCode::AlignOverHardUncuttable` is recorded and the sentence is not rejected. Beyond rewriting the translation, the worker has no legal action, so rejection only burns tries. The engine's acceptance side already treats this code as advisory and mechanically hard-splits via `enforce_target_hard_limit`, so the commit-time release does not change the persisted result. `data-unsplittable` still suppresses no checks, because a source-side unsplittable is not a target-side uncuttable.

## 8.5 Default carrier switched to block-aligned edges: `align-edges/1` and `align-rewrite/1` (aligned-block design M3)

Since M3 of the [aligned-block design](../ccut-alignment-block-subtitle-split-design.md), the two-column split table `align-table/1` in §8.1–§8.4 is demoted to a **review/repair carrier** (`ccut translate --align-carrier table`). The default carrier is instead the two same-shaped tables in `filepipe/align_edges.rs` (kinds `align-edges` / `align-rewrite`, both file-v1 HTML, `text/html`, `payloads/<callId>.html`):

```html
<table data-lang="zh" data-fit="16" data-soft="14" data-hard="20" data-ccut-format="align-edges/1">
  <tbody data-sid="s-g1.0">
    <tr><th scope="rowgroup">s-g1.0</th>
        <td class="src">[1]I [2]didn't [3]go [4]because [5]I [6]was [7]sick.</td>
        <td class="tgt">因为我病了，所以没去。</td></tr>
  </tbody>
</table>
```

- **Rendering**: `td.src` is the sentence's anchored word sequence with ordinal tokens (`[N]word`, one word per ordinal, same index as `TransAlign.words`; CJK source is counted per `words[]` atom). `td.tgt` is the complete natural translation. There are no pause hints, seconds, source Cues, cut-point suggestions, or chunk-count suggestions: the model's task contains no "cutting". `align-rewrite/1` has the same shape but additionally carries `data-over-hard="chunk 1 (words 1-9): 27 units > hard 20"` on the `<tbody>` (relative budget only, no seconds).
- **Response**: the model changes only the content of `td.tgt`, for example `<span data-src="../4-7">因为我病了，</span><span data-src="../1 2 3">所以没去。</span>`. `data-src` is a whitespace- or comma-separated list of 1-based ordinals and ranges (`4-7`, `1 2 3`, `1-3,9`). It may be out of order, non-contiguous, or empty (omitted translation or function block). Each ordinal belongs to at most one block within a sentence. Span text, concatenated under the `normalize_chars` convention, must equal the translation (the same tolerance as the §8.3 concatenation invariant). Body text outside spans is counted as a block with empty attribution. In `align-rewrite/1`, `td.tgt` may be rewritten (monotonized: clauses follow source order closely, and each block is ≤ hard), while still carrying span annotations.
- **Parsing and acceptance (one validator)**: `parse_align_edges` is the only string-level validator for these two kinds. The engine (`engines::align`) and the submit-time lint (`lint_agent_answer_edges` / `lint_agent_answer_rewrite`, routed by kind in `task submit`) both call it. New closed-set codes: `align-edge-ordinal` (ordinal unparseable, out of range, or duplicated across blocks) and `align-edge-text` (span concatenation ≠ translation). Rewrite mode uses `empty-translation` (rewritten to empty) and `align-content-drift` (magnitude exceeds `reordered_rewrite_exceeds` ±max(25%,4), or a hard anchor of number, URL, or verbatim Latin is lost) instead. Truncation versus scattered omission, bare `<tbody>` recovery, and size guards follow the same conventions as §8.4. A `td.tgt` with no span at all only records a `content-ignored` warning and is returned as "no alignment edges". The inverse `parse_align_edges_input` is the strict inverse of `render_align_edges` (byte-for-byte round-trip equality is pinned by unit tests).
- **Engine side**: block → soft edges (weight 0.75) plus `AnchorAligner` hard edges → `align_block::plan_sentence` (safe boundaries → minimal monotone blocks → bilingual DP). `NeedsRewrite` enters the `align-rewrite` round (no repair). Acceptance additionally requires preserving locked terms and bilingual anchors, passing target AutoCorrect, and re-running the block check on the rewritten text must yield `Aligned` before `transDisplay{basis:"monotonic-rewrite"}` + `text_basis: display` is written. Otherwise the sentence is aligned as a whole. The first-round `b…`, repair `r…`, and rewrite `w…` page artifacts all land in `ai/align/<lang>/vNNN/`.
- **Semantic changes in the table carrier**: `data-crossing` no longer writes `crossing:true`; it writes `correspondence: sentence` instead (one sentence, one block, one piece). `data-reordered` rewrites no longer write back to `trans`; a rewrite writes `transDisplay{basis:"table-reorder"}` and the entry gets `text_basis: display`. Where §8.4 says "reordered writes back to `trans`", this section takes precedence.
- **translate fusion**: the `data-align-*` attributes are simplified to `data-align-words` (the same ordinal word sequence) plus `data-align-needed`. The model annotates inside `<p>` with the same `<span data-src>` microformat (§7 carrier; `parse_translate_page` extracts blocks from the `<p>` child nodes). A bad draft discards only the draft, not the translation.
