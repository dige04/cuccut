# 12. Pagination and budget parameter table (8000-word starting stress-test value)

> From [CucCut file-contract subtitle AI pipeline design (File-Contract Pipeline, v0.3)](../ccut-file-contract-subtitle-ai-design.md)

**The metering unit is unified as word count**: Agent page budgets are measured with `atomize::word_count`. CJK counts one word per character, Latin counts one word per word, and attached punctuation is not counted. Pagination is determined only by the source word count; sentence count, serialized character count and execution concurrency do not take part in page shape. Worker slot count only controls consumption concurrency. The polish core-region budget is kept separately at 2200 words, as a control against the existing stable baseline.

| Stage | Page budget (words) | Context | Parallelism | Content retry limit |
|---|---|---|---|---|
| analysis | 8000 | None | map parallel, reduce serial (short draft: 1 call; "3" is the retry limit, not the number of stages) | 3 |
| segment | 8000 | None | batched | 3 |
| polish+segment | core 2200 | each side min(200 words, 3 sentences), ≥1 complete sentence | batched (needs `parallel_kind` added) | 3 + span 2 |
| translate | 8000 / whole-segment alignment | comment context | batched | sentence level 3 (three waves) |
| align | 8000 | 1 sentence before and after, read-only | batched | 2 rounds |

Execution concurrency is unchanged: agent workers (`CCUT_LLM_MAX_WORKERS`) / provider lanes (`CCUT_PROVIDER_MAX_LANES`). Concurrency no longer feeds back into pagination granularity.

**Current implementation metering**:

| Stage | Landed value | Metering | Difference from design |
|---|---|---|---|
| analysis | `budgets::ANALYSIS = 8000` | source words | Consistent |
| segment | `budgets::SEGMENT = 8000` | source words | Consistent |
| translate (file contract) | `TRANSLATE_FILE_WORDS = 8000` | source words | Consistent |
| polish core | `PolishBudget::core_words = 2200`, context 200 words / 3 sentences, overflow ratio 0.15 | words | Consistent; but the snowball guard's overflow check still computes using `chars` |
| align packing | `ALIGN_FILE_WORDS = 8000` | source words | Shared by the full, point-fix and global-fix passes; no additional sentence-count or character-count cap |
