# 4. Stage 0: Word-level timestamps and forced alignment

> From [ccut transcript post-processing AI pipeline technical plan (polishing / segmentation / chaptering / translation / subtitle alignment)](../ccut-ai-pipeline-design.md)

Goal: whichever ASR path is taken, the transcript written to disk must satisfy "every word has a credible `t0/t1`, and every word has a speaker."

## 4.1 Three timing paths (by priority)

| Path | Applies to | Word-timing quality |
| --- | --- | --- |
| **A. Forced alignment during transcription** (current main path) | Qwen3 / Whisper: VAD segmentation → per-segment ASR → `aligner.align(span_audio, text, lang)` | 80 ms grid, real |
| **B. Selective refinement after transcription** (wire up `refine.rs`) | MOSS / cloud engines and other engines that only give line-level timing | 80 ms grid, real |
| **C. Character-weight synthesis** (fallback) | Aligner unavailable / alignment result empty / refinement failed | Uniform interpolation within the line |

**B is the first implementation item** (P0): `refine_word_timings` is already written in `ccut-speech-core` and has tests; it only needs wiring into the MOSS path (the MOSS branch of `speech_cli.rs`). Gating and degradation follow exactly the conclusions of voice-ink's `WordTimingRefiner`:

- Only refine lines where "the engine gave no word timings **and** the line duration is > 5 s **and** the text is non-empty" (char-weight drift on short lines is imperceptible and not worth the inference cost);
- Line boundaries are **never changed**. Refinement only redistributes word timings inside the line window;
- Any single-line failure silently keeps the char-weight result. **Refinement must never invalidate a completed transcription (which may have been paid for)**;
- Long lines use `align_long` (240 s chunks with tail plateau splitting; already implemented, currently referenced only by an example).

**C's weight formula** (consistent with voice-ink and DocBuilder, so the behaviour of both ends can be cross-checked): `weight = max(2, alphanumeric count) + 1.4`. The line duration is split among the words in proportion to their weights, with monotonic clamping to the refinement window.

## 4.2 Normalization and repair (deterministic cleanup)

Output from every timing path passes through two deterministic steps, in order (ported from voice-ink's `WordTimingNormalization` / `WordTimingRepair`):

1. **Normalization** `normalized_word_timings(words, range_start, range_end)`: convert to centisecond ticks, guarantee each word at least 1 tick, and ensure strict monotonicity, no zero durations, and nothing past the line window. The aligner occasionally predicts one step out of bounds; if that escaped, adjacent VAD lines would appear to go backwards in time;
2. **Repair** `word_timing_repair`: detects five fault types (`nonFinite` / `negativeDuration` / `zeroDuration` / `startRegression` / `overlap`). Bad spans are re-laid out anchored to the healthy neighbours on both sides; if they do not fit, they expand into the neighbours; if that still fails, record `unrepairable` rather than forcing in a bad tick.
   **Repair is a pure timing operation and touches no stage stamps.** The text fingerprint covers only the text and endpoint ids, so timing repair can run at any time without falsely invalidating the freshness of polishing or translation.

## 4.3 Word building and persistence (rows → §18 transcript)

Deterministic build step (`ccut-flow-core/src/build.rs`), corresponding to voice-ink's `DocBuilder`:

```
RowIn[] (with optional words / speaker)
  → per row: adopt real word timings if present and clamp them to the line window; otherwise synthesize with char-weight
  → word id assignment: `g<row>.<col>` ("g3.7"); words created by later edits use `w<base36ms>-<n>`
  → speaker: MOSS's row-level speaker sinks down to each word's `sp`; engines without speaker info always use "s1"
  → normalization (§4.2) → write transcript.json (§18) + stages.asr / stages.asrLayout
```

Speaker boundary refinement uses two strategies (`build::SpeakerBoundaryPolicy`):

- **Interval projection** (no speaker info, cloud row-level labels, post-hoc pyannote word-level projection): keeps voice-ink's parameters. Short foreign islands (<4 words, ≤1.2 s, no pause, preceding word not sentence-final) are merged back into the host. Switch points snap to the nearest pause ≥0.25 s (within a ±1 s window), to avoid cutting mid-word.
- **Row-level authority** (`moss-transcribe-diarize`, including `remote:` forwarding): the row-level speaker is a **textual attribution verdict** that the joint ASR+diarization model emits together with the text. Row boundaries are only timestamps with slop (in a 7-hour two-person interview, 10% of adjacent rows overlap in time), so not a single word is moved. Measured on MOSS, both snapping passes were counterproductive. Pass 2 moved the filler “呃” (“er”) that opens an answer, and the phrase “一个经历对” (“yi ge jing li dui”, roughly “that's right, one experience”) at the end of a sentence, to the other speaker. The cut landed on a pause, so it looked "natural" afterwards, and LLM candidate screening could not catch it. Pass 1, in chunks where MOSS emitted no punctuation (in one transcription, 1115 of 3385 rows had none, varying by chunk), merged 142 real acknowledgements such as “嗯” / “哦是吗” / “当然” (“mm” / “oh, really?” / “of course”) wholesale into the other speaker's sentence. Without punctuation, "preceding word not sentence-final" always holds. For existing MOSS projects, `ccut polish`'s `speakerRepair.rowRealign` restores the words that snapping moved, using `ai/asr-rows.json` (word ids `g<row>.<col>` point back to the row number). It only restores mismatched runs of ≤6 words / ≤1.5 s. If the mismatch rate is >5%, or the speaker-id table has been re-numbered, the whole step is skipped (see §5.0).
  The MOSS branch of `ccut speakers reidentify` follows the same logic. New-round **row intervals** split overlaps at their midpoints, and each word is assigned to the row that contains its midpoint. It does not use the voting / escape hatch / island absorption of the voiceprint-interval approach. That approach would make overlapping regions flicker into fragments like “啊，/的，/吗？” (“ah,” / “de,” / “huh?”, filler particles) that swap speakers character by character. This was the screenshot incident of 2026-08; the other half of the cause was that rebind set the new token's `sp` to `span[0]` in every case (see §5.5).
