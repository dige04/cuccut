# 11. Deliberately Out of Scope and Open Questions

> From [CucCut talking-head cut technical plan (prototype rounds 192–197 → kernel / serve / App v2 / Web)](../ccut-talking-head-cut-design.md)

**Deliberately out of scope**

- Do not add a `timeline/apply` op, do not add a transcript override table, do not bump `TIMELINE_CURRENT / TRANSCRIPT_CURRENT`.
- ~~Do not build an “expand cut segments” (Descript's “Show deleted”) toggle; hovering over the seam marker already shows what was cut. If users need it, file it separately as P5.~~ **Overturned by round 197** (2026-09-07): users asked for it to be collapsed by default and expanded by a transport toggle into an empty slot band; `cut_mode::fold_view(expanded)` and the App v2 `CCUT_GPUI_CUTS_EXPANDED` have landed, Web is still to do (§15). **Round 200 closed this again** (2026-09-07): the separate “expand cut segments” toggle is retired. Expanding = the transport's global “cut” switch (`expanded = cut.active`); when it is off, the timeline draws no cut or suggestion marks at all (seam markers are withdrawn). `CCUT_GPUI_CUTS_EXPANDED=1` remains as an alias for `CCUT_GPUI_CUT_MODE=1`.
- Do not auto-follow translations with cuts: a translation whose source was cut is only marked `staleReason: cut`, and is re-translated in batch by `ccut translate --only-stale --after-cut` (which implies `--only-stale`; the project must have `timeline.json`). Because the stale projection is computed on the fly and not written to disk, **every edit write path's projection must carry `check`** (`ccut-workspace::apply::edit_projection`; commit `e318281e8` fixed a defect where stale was wiped after an App cut).
- Do not put suggestions into `DocProjection`; the review file goes through a separate Query, so that `doc.changed` does not carry non-document state.
- Do not add an LLM to the local `ccut cut detect`; the CLI's no-LLM rule stands.
- Do not do linkage between the clip layer and cuts (for example, splitting an already-cut segment); the `clip-empty-after-cuts` lint is the backstop.
- Do not add special handling for receipt-group undo in the Agent session's `ccut cleanup --review`: it writes no journal, so receipt undo follows §7.4 via `DismissAll {batch}`.

**Open questions**

1. **Seam audio** (decided, 2026-09-07): the export parameter `--seam-fade-ms` (protocol `ExportOptions.seamFadeMs`) defaults to **10**; `0` = hard concatenation. The implementation applies a linear fade-out and fade-in on each side of every seam (the head segment does not fade in, the tail segment does not fade out, a single segment has no seam). It is **not** a crossfade: a crossfade would need each segment to take extra source material of the fade length, changing the output duration and the subtitle / element clocks. A 10 ms DC-jump suppression is enough to remove the click, and no level dip is audible on speech. The fade length is clamped to half the segment length. The `ffmpeg` backend inserts `afade` in the segment audio chain; the `native` backend ramps the PCM of that slot after `write_mix` has copied the samples; both read `AssemblyPlan::seam_fades`. Not done: A/B listening tests on real footage (only unit tests exist). If the default changes, only `DEFAULT_SEAM_FADE_MS` changes.
2. **LLM `repeat` recall and false positives**: prompt changes must be checked by running the talking-head samples in `core/fixtures/launch-golden/` and comparing acceptance rates across the three tiers conservative / standard / tight. If `repeat` has a high false-positive rate, enable it only in the `tight` tier by default.
3. **Token view for very large projects**: a seven-hour transcript is about 60–80k tokens. Is GPUI's streaming `div` layout with paragraph virtualization enough? In P2, measure frame time with the 7h fixture in `core/fixtures/`; if that is not enough, fall back to cue-row layout.
4. **Multi-source projects**: `cutWords` already carries `srcId`, but the token view in cut mode only lays out `main` by default. How suggestions and selections for multi-source talking heads (multi-camera) map onto non-main sources is not solved this round; the UI only opens cut mode for `main`.
5. **`ccut review reject` semantics change** (whole-document void → per-item `dismiss`) has no effect on existing skill docs or the Mac 1.x archive surface, but `broll` still uses the v3 whole-document semantics, so the two kinds diverge. This needs to be stated explicitly in `review.rs`.
