# 6. Detection flow: incremental semantics of `cleanup` and vocabulary

> From [CucCut talking-head cut technical plan (prototype rounds 192–197 → core / serve / App v2 / Web)](../ccut-talking-head-cut-design.md)

## 6.1 Incremental and replacement (C9)

`run_cleanup_cmd --review` now writes to disk as follows:

1. Read the old review file (if any); keep the `(firstWordId, lastWordId, category)` of the `accepted / dismissed` entries as the "decided set".
2. Local detection + LLM → `merge_proposals` → `skip_already_cut(&CutSet)`.
3. Among the new proposals that hit the decided set: drop `accepted` ones (they are already cuts), and drop `dismissed` ones (the user rejected them).
4. Compile the remaining proposals into new `pending` entries; drop all old `pending` entries (this round replaces them).
5. Write a v4 file, with `batch` = this task's id; `changed = ["review.cleanup"]`.

The direct-apply path without `--review` is unchanged (`AI: cleanup` journal label; receipt undo goes through `task_undo`).

## 6.2 Categories and vocabulary (C8)

- The LLM answer `cat` adds `repeat` (said the same sentence or the same meaning twice; keep the later one). `validate_page` and `lint_agent_answer` are updated in step to allow it. `repeat`, like `retake / falseStart`, maps to the provenance `kind: badTake`, and `category` keeps the fine-grained type. The default is to keep the later take (`keep_later = true`); the `can_flip` logic follows `review.rs`.
- The prompt in the system section of `engines/cleanup.rs` adds the `repeat` definition and the "keep the later one" rule. Prompt changes are synced to both the local Agent (lint at `task.rs:1023`) and the provider path (AGENTS.md discipline).
- `ZH_SOFT` adds “嗯” (um), “啊” (ah) and “呃呃” (er-er). “嗯” is a soft word (it can also serve as an acknowledgment), so it only matches when isolated by punctuation. `ZH_HARD` is unchanged.

## 6.3 Unified flags (G5)

- `ccut cleanup` adds `--max-gap` (default 3.0, passed through to `make_detect_options`) and `--no-pauses` (an alias of `--no-silences`, noted in help); `ccut cut detect` adds a `--no-silences` alias. The `cleanup` task options table in `serve` (`job_kinds.rs:245`) adds `maxGap`.
- `docs/design/cli/ccut-cli-server-reference.md` is synced; the `ccut spec` jobKinds projection is automatic.
