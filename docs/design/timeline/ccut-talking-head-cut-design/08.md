# 8. View Implementation

> From [CucCut talking-head cut technical plan (prototype rounds 192–197 → kernel / serve / App v2 / Web)](../ccut-talking-head-cut-design.md)

## 8.1 Shared interaction spec (both ends consistent; criteria from §5)

- Transcript panel top row: Segmented “改字 / 剪辑” (Edit / Cut); `entry = clean` opens in the default Cut state. Cut-state body = `para_tokens` laid out by paragraph / chapter (called only for visible rows); editing text, dragging segments, and find/replace are only available in the Edit state.
- Marks: cut characters are struck through (red background, thin line), suggested characters have an orange background with a dashed underline, and a pause inserts a `◷ 1.4s` tag at the end of its cue (struck through in the cut state).
- Single-click a normal character = seek playback; click a suggestion → menu “接受 · 剪掉 / 忽略这一条 / 试听这一处” (Accept · Cut / Ignore this one / Audition this spot); click a cut item → “恢复这一段 / 试听这一处” (Restore this segment / Audition this spot).
- Drag selection: press on the first token → on move, update `CutSelection {live: true}` → on release, `live: false`, and the playhead jumps to the timeline time corresponding to `span.source_start`; if the selection is outside the visible area, scroll it to the middle. The timeline draws a synced highlight block across all rows below the ruler (dashed while dragging, solid on release) plus a `span.label` tag at the top left; across cut segments, draw multiple blocks.
- Floating toolbar: above the first line of the selection, “**1.9s** 00:07.1 – 00:09.1 ｜ 剪掉 (Cut) ⌫ · 试听 (Audition) · 取消 (Cancel) Esc”; hidden while `live`; collapses when scrolled out of view.
- Summary bar three states, toast per step + undo, footnote copy — all taken from the return values of `summary_text` / `CutOp`; do not assemble strings in the view.
- Timeline: seam markers (thin vertical line + `−0.8s` badge above; on hover, expands to “已剪 口癖 · 0.8s · 恢复” (Cut · filler · 0.8s · Restore); click = restore); suggested segments = orange dashed segments (click = accept). Neither is a block: they do not enter `SelectionSet`, do not snap, and cannot be dragged. No new track is added, and no merged "main video" row (prototype round 196, user decision 2026-09-07). **Cut points are global: seams run through the ruler and all tracks like the playhead.** Badges hang on the ruler, and adjacent cut segments at the same position merge into one line. The transport gets an “展开已剪段” (Expand cut segments) toggle; when it is on, seams open into empty slot bands running across all tracks (the ruler portion becomes shaded and carries no scale numbers), while scale numbers always show output time (prototype round 197, user decision 2026-09-07; App / Web pending sync, see prototype ledger #203).
- When the output is shorter than the source, the transport timecode additionally reports “成片 3:14” (Output 3:14) (`view_duration`).

**Web three-batch review ruling (2026-09-07, W-11)**: D-C8 / D-C9 follow App (hide the toolbar without a selection; complete compose groups are not dragged or trimmed); D-C10 follows App's notice color and adds category titles; D-C15 Web keeps the full color-bar hint, App keeps the no-tooltip difference; D-C16 uses `stale - cut` to stay compatible with old projections. The Agent path keeps the progress card on the Web session page and tools page; without a reliable task binding, it does not borrow the percentage of the previous job. Model activity shows real fields and does not fabricate pagination. This batch's revert is done on Web by stable batch ID through two review requests, “恢复已接受 + 忽略待定” (restore accepted + ignore pending), which preserves unrelated edits; the App's original journal restore-point mechanism is unchanged. A mid-way failure or skipped item does not report the whole batch as successful; retry is allowed. The above implementation mechanisms and layout differences are explicitly retained; protocol transactions, unknown progress, or prototype demo data are not treated as production facts.
