# apps/desktop

CucCut's Electron desktop app: the main process (`src/main`), the preload and renderer process (`src/renderer`, with the UI from `@cuccut/ui`). The main process starts the Runtime on demand (`out/main/runtime.js`, run with `ELECTRON_RUN_AS_NODE`), and the Runtime in turn starts each Rust Worker on demand. For run and development commands, see the [root README](../../README.md); for the verification entry point, see [development workflow §2](../../docs/development-workflow.md#2-verification).

| Directory | Contents |
| --- | --- |
| `src/main` | Main process: windows, Runtime supervision (`runtime-supervisor.ts`), updates, packaged resource layout (`packaged-resources.ts`) |
| `src/preload`、`src/renderer` | Preload script and renderer process entry |
| `tools/` | Checks on build output (`check-file-fonts.mjs`, `check-model-assets.mjs`), performance measurement and packaging scripts |
| `build/` | Packaging assets: `icon.ico` (Windows), `icon.icns` (macOS), `icon.png` (1024). All are generated by `tools/app-icon/`; `npm run icons` re-exports them, do not edit by hand |

## macOS packaging

### Intel Mac local build

An Intel Mac (macOS 14+) builds with the native x64 toolchain. The output directory must be new, and the source must be committed first:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer npm run package:mac -- \
  --local --target x86_64-apple-darwin --out /private/tmp/cuccut-mac-intel
```

Local mode produces a temporarily signed App, ZIP, DMG and checksums. It does not notarize and does not generate an update feed, and it does not accept a release build number, download URL or Developer ID identity. Artifact names carry the `x86_64-apple-darwin-local` suffix, and `app-release.json` records the source commit and signing status. Formal releases still use the Apple Silicon flow below.

On Intel, the Model Worker turns off MLX / Core ML and enables candle CPU and `whisper-ggml-metal`. Whisper uses an available AMD GPU through the Metal backend of whisper.cpp; without a compatible GPU, or with `CUCCUT_GPU=off`, it falls back to CPU. Other models, VAD and the aligner run on CPU. The Metal kernels are embedded by whisper-rs-sys, so `mlx.metallib` from Apple Silicon is not needed. A full Xcode, CMake and the Rust WASM target are required. The Intel Worker sets `GGML_METAL_CONCURRENCY_DISABLE=1` before it starts threads, to work around a bug in the current ggml concurrent Metal scheduling on AMD discrete GPUs; it still uses the GPU for compute. Chinese and English samples were run successfully on a Radeon Pro 5500M with Whisper large-v3 Turbo q8_0; other AMD models and other models have not been tested. The Runtime's Intel Mac handshake deadline allows for first-time Metal compilation, per [architecture design §6.5](../../docs/architecture/architecture-design.md#65-model-worker-local-inference-process). The startup check of the packaged Worker and real model inference are verified separately.

### Apple Silicon release package

On Apple Silicon, macOS 14+, Node 22.18+, Rust and the Xcode command line tools, run from a clean, committed repository root:

```sh
npm run package:mac -- --build 60 \
  --sign-sha1 <Developer-ID-证书完整-SHA1> \
  --out /仓库外/全新产物目录 \
  --download-base-url https://github.com/hieudinh/cuccut/releases/download/cuccut-v3.0.0-build.60
```

The version is read from `apps/desktop/package.json`, and the App ID is `com.cuccut.app`. Build numbers continue from the existing releases. The 60 above is the first 3.0.0 candidate; later releases must not reuse it. For signing and the encrypted backup, see the [signing notes](../../docs/macos-signing.md); the development agent uses the [release skill](../../.agents/skills/ccut-release/SKILL.md). The notary profile defaults to `cuccut-notary` and can be overridden with `--notary-profile` or `CUCCUT_NOTARY_PROFILE`; CI passes a separate keychain with `--sign-keychain`.

After building desktop and Web, the packager uses `cargo build --release --locked --target aarch64-apple-darwin` to build the Worker and the credential helper. The Model Worker keeps the default MLX / Core ML backend. The `mlx.metallib` from the same build goes into `Contents/Resources/bin` in the package, and the Runtime points to it through `PMETAL_METALLIB_PATH`. If several copies are found, `--metallib` must point to this build's output; do not borrow the cache from the development machine. `--bin-dir` is only for release binaries whose source commit has been verified.

Mac's Export Worker uses a separate `export-worker/external-fonts`: bundled fonts are kept only under `Contents/Resources/web/assets`, and `bundled-fonts.json` maps the kernel's original file names to Vite's hashed file names. Font URLs inside the desktop `app.asar` are pointed at the same directory during staging, while Web addresses stay unchanged. Before packaging, the bytes of the desktop, Web and native fonts are compared one by one, and any `--bin-dir` Export Worker that still embeds fonts is rejected. Ordinary development builds and Windows packaging keep the original font layout. Electron keeps only the app's shipped languages and their Chromium regional and gender variants, with the English fallback kept. The DMG uses LZFSE (`ULFO`) compression.

Electron-builder first installs as `CucCut.app`. The signing script selects the identity by the full certificate fingerprint and signs from the inside out, without `--deep`. Both the App and the DMG must be notarized by Apple as `Accepted`, then stapled. The final ZIP is generated from the stapled App; it is then extracted again and re-verified for signature, notarization ticket and Gatekeeper, and the extracted app runs the Runtime and Worker self-checks. The outputs are `CucCut-<version>-build.<n>-aarch64-apple-darwin.zip`, `.dmg`, the matching `.sha256`, `app-release.json` and the notarization record. The intermediate `notary-submission.zip` is not distributed. The output directory must be new or empty.

The resource layout inside the package is the same as on Windows; on Mac, `<resources>` is `Contents/Resources`. Check the real package with `node apps/desktop/tools/check-packaged-app.mjs /路径/CucCut.app`. Also start `verified-extraction/CucCut.app` from outside the repository, with a separate `CUCCUT_HOME`, to check pages and features. A successful signature does not replace acceptance of preview, export, models and Agent. ffmpeg and the Agent executable keep using managed external tool discovery; they are not pretended to be included in the installer.

Check the shared fonts on the artifact with `node apps/desktop/tools/check-file-fonts.mjs --out=/路径/CucCut.app/Contents/Resources/app.asar/out`. A hidden Electron window reads the pages and font URLs from the final ASAR, checks that every font in the manifest loads and is injected into the preview kernel. It does not start the Runtime and does not read user data.

Releases go through GitHub Releases; archive file names and contents are immutable. `--download-base-url` generates the ZIP update manifest, which the App's own resolver verifies. The version pin in `apps/desktop/releases/` is updated only after the public archive read-back passes. A new version uses a separate ID, and the old website's update feed is not switched directly to the new package. After all selected platform releases are published and verified, the latest stable desktop version is marked as GitHub Latest; see the steps in the [release skill](../../.agents/skills/ccut-release/SKILL.md#complete-public-release).

**GitHub Actions**: pushing a `cuccut-v<VERSION>-build.<BUILD>` release tag automatically triggers `desktop-release`, which builds the Mac Apple Silicon package and the Windows x64 CPU, CUDA and Vulkan packages from the same commit as the tag. After all native checks pass, it publishes to the same Release and updates each platform's appcast. The tag version must match `package.json` and the lockfile, the build number must increase, and the commit must already be on `main`. Build 60 cannot be reused. The signing material is kept in the `macos-release` Environment, which allows `main` and release tags. `desktop-macos` keeps the manual credential validation entry, with the default `mode=validate`. For secrets, commands and the full rules, see [signing notes §5](../../docs/macos-signing.md#5-github-actions-configuration). UI/export and real model inference are not verified by the pipeline, and the report states this explicitly.

## Windows packaging

On Windows x64, run from the repository root:

```sh
npm run package:win          # 标准版：Model Worker 用 candle CPU 与 whisper.cpp 的 Whisper（CPU）
npm run package:win:cuda     # CUDA 版：candle 与 Whisper 都走 CUDA（NVIDIA 专用），要 CUDA Toolkit 13.1；Whisper 的 CUDA 尚未实测
npm run package:win:vulkan   # Vulkan 版：Whisper 用 Vulkan GPU（candle 仍在 CPU 上），要 Vulkan SDK；尚未实测
```

Choose among the three editions by the user's graphics card: NVIDIA (Ampere / RTX 30 and later) uses the CUDA edition; AMD and Intel GPUs (and older NVIDIA cards that do not support CUDA 13) use the Vulkan edition; with neither, use the standard edition. Choosing CUDA or Vulkan at runtime within a single package is not yet possible ([architecture design §14](../../docs/architecture/architecture-design.md#14-items-pending-review), “single GPU installer picks its backend at runtime”).

All of them must run in an MSVC developer environment (whisper.cpp is built with CMake). The CUDA edition enables the Model Worker's `cuda` (candle) and `whisper-ggml-cuda` (ggml-cuda of whisper.cpp) features. `CUDA_PATH` must be set, and the packaging script additionally sets `CUDA_COMPUTE_CAP=80`, nvcc's `/MD` and `CMAKE_CUDA_ARCHITECTURES`. The default for the last one is `80-virtual;86-real;89-real;120-real`; an externally set value is used as-is. Build machines without a GPU must set it explicitly, otherwise ggml's architecture probing against the local GPU fails. ggml-cuda compiles many kernels, so the build is noticeably slower than before. The NVIDIA runtime libraries bundled with the CUDA edition already cover the cudart, cublas and cublasLt that ggml-cuda uses. Vulkan edition users need only the `vulkan-1.dll` that ships with the graphics driver; the package does not include it.

**CPU instruction set baseline**. When building the Model Worker for all three editions, the packaging script sets `GGML_NATIVE=OFF` and `GGML_AVX2=ON` (external values take precedence). By default, ggml probes the build machine's CPU instruction set, so Whisper built on a runner with AVX-512 crashes with an illegal instruction on user machines without AVX-512. The fixed baseline is AVX2 (on MSVC, `/arch:AVX2` plus FMA, F16C and BMI2; Intel Haswell and AMD Zen and later). Machines with AVX-512 transcribe slightly slower on CPU. CPUs without AVX2 (Sandy / Ivy Bridge and many Pentium / Celeron) remain unsupported, and choosing kernels per CPU at runtime is not possible under whisper-rs-sys static linking ([architecture design §6.5](../../docs/architecture/architecture-design.md#65-model-worker-local-inference-process), “ggml CPU instruction set baseline”). whisper-rs-sys does not rebuild when these environment variables change. If this machine previously built the Windows Worker, run `cargo clean -p whisper-rs-sys --release --target x86_64-pc-windows-msvc` before packaging. The workflow's cache key includes the baseline. This was checked against the source only; it has not been built on Windows or run on an AVX2-only machine.

It first runs `npm run build`, `npm run build:web`, `npm run build:slides-editor`, `npm run build:design-editor` and `npm run build:design-system-editor`. Then `tools/package-desktop.mjs` uses cargo to build the Worker (release, `x86_64-pc-windows-msvc`, `--locked`), and electron-builder writes the packages to `apps/desktop/dist/<cpu|cuda|vulkan>/` (git-ignored):

- `CucCut-<version>[-build.<n>]-win-x64[-cuda|-vulkan]-setup.exe`: NSIS one-click installer, installs per user to `%LOCALAPPDATA%\Programs\cuccut`, no administrator rights needed;
- `CucCut-<version>[-build.<n>]-win-x64[-cuda|-vulkan].zip`: unzip and use;
- `CucCut-<version>[-build.<n>]-win-x64[-cuda|-vulkan]-release.json`: release report with version, build, variant, and the file names, sizes and sha256 of the installer and the zip;
- `win-unpacked/`: the same contents, unpacked.

Neither is signed. The appId and product name are taken from the update rules (`BUNDLE_ID` and `PRODUCT_NAME` in `app-update-rules.ts`).

**Release and update**. A package for release needs a build number: `node apps/desktop/tools/package-desktop.mjs --variant <cpu|cuda|vulkan> --build <n>` (the `build` input of the `desktop-windows` workflow). The build number and variant are written into the app's `package.json` (`cuccutBuild`, `cuccutVariant`), and the output names carry `build.<n>`. A package without a build number does not check for updates. With `--download-base-url <https directory>` (the workflow's `download_base_url`), it also writes the update feed `appcast-x86_64-pc-windows-msvc[-cuda|-vulkan].json`: a schema-1 manifest that points to the installer in that directory, with size and sha256. After writing, it is read back once with the app's resolver. With `--rollout-hours <n>` (the workflow's `rollout_hours`), the release is pushed in stages: the feed also gets `rolloutHours` and `releasedAt` (the generation time), and automatic checks gradually open up by local region over the following n hours. Manual checks are not limited ([architecture design §2.6](../../docs/architecture/architecture-design.md#26-app-updates)). If the file is uploaded long after it was generated, change `releasedAt` to the actual release time before uploading it; it is not part of any digest. The app reads the one file that matches its own variant. The update feed is the `apps/desktop/releases/` version pin in the GitHub repository, and the installer is an immutable asset of the same GitHub Release ([architecture design §2.6](../../docs/architecture/architecture-design.md#26-app-updates)). For rehearsals, point to a manifest with `CUCCUT_UPDATE_APPCAST=<path to the manifest>`; installer addresses in that manifest may then also be local paths.

In-app update only recognizes the copy installed by NSIS (with `Uninstall CucCut.exe` next to the exe). After the download is verified, the app exits normally (stopping the Runtime first via IPC), and on exit it silently starts the installer to replace the files. “Restart and update” (重启并更新) uses `/S --updated --force-run` and reopens the app after installation. If the update was already downloaded and the user exits normally, `/S --updated` is used and the app does not reopen after installation. The zip edition reveals the package in Explorer and opens the download page.

**What is in the package**. The asar contains only `out/`, the generated `package.json`, and the third-party packages that the main process actually `require`s (currently `ws` and `zod`); the workspace's TypeScript packages are already bundled. What the Runtime and Workers read by path lives in `resources/` outside the asar. The layout is defined only in `src/main/packaged-resources.ts`, and the main process passes it to the Runtime through environment variables when it starts the Runtime ([repository conventions §2](../../docs/repo-conventions.md#2-placement-rules)):

| Under `resources/` | Source | Variable passed to Runtime |
| --- | --- | --- |
| `bin/` | `.exe` files of `engine-host`, `export-worker`, `model-worker`, `speech-worker` and `credential-helper`; the CUDA edition also includes the NVIDIA runtime libraries and notes | `CUCCUT_BIN_DIR` |
| `templates/` | `templates/` at the repository root | `CUCCUT_TEMPLATES_DIR` |
| `skills/` | `skills/` at the repository root: the `cuccut/` manual and the built-in skills under it, `cuccut/built-in-skills/` | `CUCCUT_AGENT_SKILLS_DIR` (`skills/`), `CUCCUT_SKILLS_DIR` (`skills/cuccut/built-in-skills/`) |
| `model-assets/` | `packages/models/assets` | `CUCCUT_MODEL_ASSETS_DIR` |
| `web/` | `apps/web/dist` | `CUCCUT_WEB_DIST` |
| `slides-editor/` | `apps/slides-editor/dist`: the slide editor page and the compiler used by `slides_check` | `CUCCUT_SLIDES_EDITOR_DIST` |
| `design-editor/` | `apps/design-editor/dist`: the design editor page, the canvas runtime and the quick-edit Worker | `CUCCUT_DESIGN_EDITOR_DIST` |
| `design-system-editor/` | `apps/design-system-editor/dist`: the design system editor page, the preview page `artifact-type/run.html`, and the React UMD used by the preview | `CUCCUT_DESIGN_SYSTEM_EDITOR_DIST` |

[CucCut license](../../LICENSE), the sources of third-party code, the modification notices and the original licenses are distributed with the desktop and Web builds by the manifest in `tools/third-party-notices.ts`. The installer carries `LICENSE` inside the asar and keeps verbatim copies in `resources/LICENSE`, `resources/THIRD_PARTY_NOTICES.md` and `resources/crates/model-runtime/licenses/speech-swift.txt`. The package structure check and the post-install self-check verify the contents of these files.

**Self-check**. `node apps/desktop/tools/check-packaged-app.mjs <directory containing CucCut.exe>` uses the app's own executable to run `runtime.js --self-check --probe` from the asar in Node mode. It reports where each item resolves, and it starts each native program once and runs it through the handshake, so missing DLLs and wrong architectures surface here. It can only be run on a Windows package, on Windows. `--dev` runs it once on a development build.

### GitHub Actions release

The routine all-platform release is triggered automatically by `desktop-release` after a release tag is pushed, which runs the native build and the candidate release. The rules are in [signing notes §5.4](../../docs/macos-signing.md#54-automatic-publishing-from-release-tags). `desktop-windows` and `desktop-windows-publish` still provide the following two manual trigger entry points, for single-platform backfill or retry. Ordinary branch pushes do not publish. Run results and hardware verification status are reported separately. The existence of a workflow must not be taken as verified.

```sh
gh workflow run desktop-windows.yml --ref cuccut-v3.0.0-build.60 \
  -f include_cuda=true -f include_vulkan=true -f build=60 \
  -f download_base_url=https://github.com/hieudinh/cuccut/releases/download/cuccut-v3.0.0-build.60

# After the native jobs pass and the artifacts are uploaded, use the actual run ID; only select variants that passed verification.
gh workflow run desktop-windows-publish.yml --ref main \
  -f 'candidate_run_id=<RUN_ID>' -f release_tag=cuccut-v3.0.0-build.60 \
  -f variants=cpu,cuda,vulkan
```

The build source is fixed to the same full commit as the existing Mac Release, and the version and build are the same. For build-environment fixes, the workflow may be run on main with `source_ref=<Mac source commit>`, and the report records the product SHA and the workflow SHA separately. Windows Cargo output uses the short path `D:\bt`, and CMake uses Ninja, to avoid the MSBuild long-path limit triggered by the Vulkan shader generator. `include_cpu=false` retries only the GPU variants. The publish workflow grants the publish job only `contents: write`, plus the `actions: read` needed to read candidate artifacts, and does not use the Mac certificate or private key. It checks the candidate workflow, the repository, the source SHA, the native job results for each selected variant, the file sizes and SHA-256 values, and the app's own update manifest parsing result. It then appends the installer, ZIP, checksum files, the supplementary release report and the manifest to the existing Release. Same-named files with different bytes are not overwritten. Mac assets are kept, the existing Latest is kept during publishing, and after completion the latest stable desktop version is marked per the release skill. Only after the public download read-back verification passes are the update manifests for each Windows variant committed and pushed.

The Windows installer is not yet Authenticode-signed. The current Worker links `MSVCP140.dll`, `VCRUNTIME140.dll` and `VCRUNTIME140_1.dll`, and the installer and ZIP do not yet ship these runtime libraries. Users must first install the [Microsoft Visual C++ v14 x64 Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist/). Hosted runners already have the runtime installed, so their self-checks cannot prove that a fresh system does not need this dependency. The startup, install, same-version overwrite upgrade, uninstall and ZIP self-checks in the pipeline do not replace inference on real CUDA / Vulkan hardware. A variant that has not passed the native job must not be published. To run the release gate itself, run `node --test apps/desktop/tools/windows-release.test.mjs` and `actionlint .github/workflows/desktop-windows-publish.yml`.

**Without a Windows machine**: manually trigger the `desktop-windows` workflow in GitHub Actions (`.github/workflows/desktop-windows.yml`). It produces packages for each variant and runs a self-check on the unpacked package, the zip, and the directory after a silent install. It verifies that the install directory contains `Uninstall CucCut.exe`, installs again over the installed build with the update parameters (`/S --updated`), and then uploads the installer, the zip and the release report. On macOS you can cross-compile the Worker (`cargo build --release --target x86_64-pc-windows-gnu ...`, which requires mingw-w64), then use `node apps/desktop/tools/package-desktop.mjs --target x86_64-pc-windows-gnu --bin-dir <artifact directory> --targets zip --out <directory outside the repo>` to produce a zip and check its structure. NSIS's `makensis` is an x86_64 program, so on Apple silicon it needs Rosetta. Packages made this way cannot replace the self-checks on Windows.

**Current status and limitations** (see [architecture design §14](../../docs/architecture/architecture-design.md#14-items-pending-review)):

- Not signed. SmartScreen will block the first run.
- Credentials: the Windows credential helper uses Credential Manager. At startup it can read the v2 `ccut` service entry and write it into the new secure storage. It has been cross-compiled for the Windows target but not yet tested on Windows. On failure it keeps a pending-retry state and does not fall back to a plaintext file ([architecture design §6.8](../../docs/architecture/architecture-design.md)).
- The CUDA variant uses the Model Worker's `cuda` (candle's CUDA backend) and `whisper-ggml-cuda` (Whisper's ggml CUDA backend). It has not actually been built yet, and Whisper has not been tested on either CUDA or Vulkan. The CUDA variant's Worker depends on the GPU driver's `nvcuda.dll`. On machines without an NVIDIA driver (including CI runners) it is expected not to start (untested), so those machines should use the standard or Vulkan variant.
- The update source and download page use GitHub (§2.6). Full cross-version auto-update on Windows and real GPU inference still need separate verification.
- Stopping the Runtime (asking it to wrap up over IPC), the Model Worker's parent-process watchdog, and lowering the inference thread priority have only been cross-compiled. They have not been tested on Windows. There is no memory-pressure signal.
- Electron fuses are not set: `GrantFileProtocolExtraPrivileges` and `RunAsNode` cannot be turned off ([architecture design](../../docs/architecture/architecture-design.md), the “Fonts” section).
