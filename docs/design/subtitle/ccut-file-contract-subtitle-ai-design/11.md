# 11. Incremental updates, fingerprints and provenance

> From [CucCut file-contract subtitle AI pipeline design (File-Contract Pipeline, v0.3)](../ccut-file-contract-subtitle-ai-design.md)

## 11.1 Stage stamps (unchanged)

`stages.polish` (content fingerprint), `stages.segment` (id fingerprint), `stages.chapters`, and `transSrc` (sentence-level visible-word fingerprint): the dirty-marking mechanism is carried over unchanged. **A missing `transSrc` stamp does not mean stale.** (Missing translation and staleness are two independent channels; this is the current semantics.)

## 11.2 Reuse of file artifacts

See §4.2: the manifest `inputFingerprint` governs file-level reuse (including "recovering directly from `merged.*` without making a call"). Sentence-level reuse looks only at `transSrc`.

## 11.3 Terminology/context provenance (new; closes the propagation chain for the user's glossary)

Editing the glossary will **not** make any sentence stale by `transSrc`, since it hashes only the source words. Without a separate channel, the user cannot locate the affected sentences after changing a locked translation. Mixing the term hash into `transSrc` would pollute its meaning as a source-word-only fingerprint. Therefore a new record is added:

```jsonc
// ai/state/translation.zh.json — does not contain translation text
{ "s-g1.0": { "contextHash": "…", "styleHash": "…", "termHashes": ["…"] } }
```

- When each sentence translation is committed, record the context/style/matched-term hashes used at that time. `term_hash` covers the four fields `source / target / note / lock`, so changing the lock state also counts as a change.
- Re-translation set = `stale_sentences` ∪ `provenance_stale_sentences`.
- **Old translations without this file continue to be judged by `transSrc`, reporting a `provenance-unknown` advisory, rather than being unconditionally marked stale.**

**M4 implementation decision: the stale criterion is narrowed to "change in the term hash set".** Changes to the summary or style only produce a `context_drift` advisory and do not enter the re-translation set. Three-tier semantics:

| Case | Verdict |
|---|---|
| No effective brief (`ContextDigest::has_basis() == false`, e.g. `--no-brief`) | **All clear**; return an empty scan immediately. Without a basis there is no fact of "what was used at that time", and marking stale out of nothing would mean re-translating the full text on every run |
| No record for this sentence in the ledger | `unknown` (advisory, follows `transSrc`) |
| Matched term hash set differs from the record | `stale`, enters the re-translation set |
| Term set identical, but the summary/style hash changed | `context_drift`, **advisory only**. Rewriting the summary is a normal side effect of re-running analysis; letting it trigger full re-translation would turn provenance into a trap where "re-running analysis burns a translation pass" |

Note that the implementation has **no** `ProvenanceBasis` type. The basis is the `ContextDigest::basis` field plus the `has_basis()` predicate.
