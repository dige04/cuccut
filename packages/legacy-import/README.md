# legacy-import

Core conversion from v1 and v2 projects to `cuccut.video`, shared by the Runtime startup upgrade and the manual import script used for archiving. Startup detection, and ownership of settings and credentials, live in `runtime-core`; see [architecture design §2.7](../../docs/architecture/architecture-design.md#27-startup-migration-of-historical-versions).

Windows historical versions only have v2; directory detection and project conversion never enter the v1 adapter. Windows drive letters and UNC paths are handled with local-path semantics; settings and credential migration are covered in the architecture section above.

## Entry points

- `planBcutProject`: from a v2 project to an import plan; relative asset paths are resolved against the old project.
- `v1-project.ts`: v1 adapter for `doc.json`, index metadata and PCM audio; refers to cuccut-app's `upgrade.rs` and `legacy_edit_migration.rs`, and does not upgrade in place.
- `EngineHost` / `writeVideo`: writes only through the engine protocol; a fixed transaction ID supports resuming a rerun from a checkpoint.
- `worker.ts`: single-project import process, built into `legacy-import-worker.js` with the desktop build. Runs serially at below-normal priority; the first project manifest is cached by the Runtime, and no scan is repeated once fully complete. The parent process cancels via IPC; if the parent disappears, the engine is also shut down. Newly imported videos go into the import directory the user chose in the startup prompt (default: `CucCut/` inside the Documents folder, see [architecture design §2.7](../../docs/architecture/architecture-design.md#27-startup-migration-of-historical-versions)), each video has its own directory and report; existing checkpoints keep their original layout (the early-version `Imported/`). Reports stay in the corresponding video directory; failures and missing assets make the process return a non-zero exit code.

For the full v2 mapping, known conversion limits and manual commands, see the [importer guide](../../scripts/legacy-import/README.md). Existing report vocabulary is kept for compatibility with historical reports. Old fields that cannot be mapped are kept in the original directory, and the import report records the related omissions.

## Verification

```bash
npm run typecheck
npm test -- packages/legacy-import/src/v1-project.test.ts packages/runtime-core/src/legacy-upgrade.test.ts packages/runtime-core/src/legacy-upgrade-v1-keys.test.ts
CUCCUT_ENGINE_HOST=target/debug/engine-host node --test scripts/legacy-import/legacy-import.test.ts
```

Native integration tests use temporary synthetic assets and do not read real historical data or the system keychain. When ffmpeg or the engine is missing, the corresponding native project tests are skipped; v1 subtitle sentence splitting uses the editing semantics generated by `npm run build:wasm`.
